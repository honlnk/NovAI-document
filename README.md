# NovAI 文档中心

本文档目录按用途分为六类：

- `product/`：项目冷启动阶段形成的初始产品构想、功能需求和 UI 设计，用于理解项目起点；不是持续更新的产品规格，也不代表当前实现。
- `architecture/`：当前有效、长期稳定的技术架构、Agent Loop、工具协议、RAG 与 UI 接口契约。
- `decisions/`：已经形成的阶段性决策记录，记录关键取舍、选择理由和边界。
- `plans/`：主要施工事实来源，记录具体功能的设计、执行待办、实施偏差和验收结果；阶段性功能计划与重构计划都在这里。
- `project/`：不定期整理的项目概览与演进阶段，帮助快速了解项目整体状态；可能滞后于真实开发，详细进度以具体 plan 为准。
- `archive/`：已完成阶段使命、仅保留历史参考价值的文档。

本项目目前由单人维护，功能通常按「形成设计 → 编写 plan → 立即施工 → 记录偏差与验收」线性推进，不维护长期等待开发的产品需求池。

## 维护规则

- 施工过程优先记录在对应 plan，包括设计、执行待办、实际偏差和验收结果。
- 项目概览按阶段不定期整理，不要求与每次提交实时同步；可能滞后，但发现明显错误或状态矛盾时仍应修正。
- 长期产品方向优先更新仓库根目录 `AGENTS.md`；`product/` 保留项目冷启动阶段的初始构想，不承担持续维护当前产品规格的职责。
- 技术方案稳定后放入 `architecture/`。
- 已做出的关键取舍放入 `decisions/`，不要混在进度文档里。
- 阶段性功能计划和重构计划放入 `plans/`。
- 阶段概览和开发日志放入 `project/`；具体待办只放在对应计划中。
- 已被新文档吸收、但仍有回溯价值的材料放入 `archive/`。
