# 竞品调研：开源全景扫描

**记录日期：2026年11月19日**

本文是开源竞品的横向扫描记录，与《[竞品调研：OpenWrite](竞品调研-OpenWrite-2026-11.md)》《[市场调研：AI 写小说产品全景与真实解决度](市场调研-AI写小说产品全景与真实解决度-2026-11.md)》构成三篇一套：OpenWrite 是闭源单点深挖，市场调研覆盖闭源商业盘，本文覆盖开源阵营。数据来自 GitHub 搜索与各项目 README，星数与活跃度为 2026-11-19 快照。

## 摘要

开源阵营的拥挤程度远超预期：GitHub 上活跃的 AI 小说创作项目超过 30 个，头部项目星数在 2000 至 9000 之间，且多数创建于 2026 年内。竞争者已分化为三种形态——桌面应用、寄生在编程智能体上的技能包、以及智能体宿主的插件。三个关键事实：其一，NovAI 引以为傲的差异化能力（伏笔追踪、按章人物状态、写后状态结算、语义检索、差异审阅写入）已被多个项目各自实现一部分，其中「书童 Pagekin」的按章取人物状态与防剧透设计与 NovAI 的读者/作者视角分离几乎同构；其二，智能体框架本身正在商品化，星数最高的两个项目是不做应用、只做技能包、寄生在 Claude Code 等宿主上的轻形态；其三，尽管拥挤，尚无统治级开源赢家（最大的应用类项目约 2700 星），多数项目是单人早期作品，格局未固化。

## 二、重点竞品小传

**书童 Pagekin（2704 星，GPL-3.0）——最直接的定位重叠。** 免费开源桌面软件，Windows/macOS，自带钥匙（BYOK），本地优先。能力清单与 NovAI 高度撞车：设定/架构/角色/蓝图到正文、审稿、修稿、定稿的流程化创作；**人物状态与关系按章记录，「写第 N 章用第 N 章时的人物状态，补写前面的章不会剧透后文」**——与 NovAI 的伏笔读者/作者视角分离在设计上同构；**伏笔有到期章节，写到相应章节时列为本章任务写进提示词，审稿时核对**——与 NovAI 的写前检查同构；蓝图 AI 检查（找出已死角色出场）；批注统一修改、修稿按段落对比逐段选用；拆解仿写、导入原稿续写；写作技能（Skill）导入绑定到规划/写稿/审稿阶段。差距在：它是「按流程向导驱动」而非「对话 + 工具自主决策」的智能体形态，且无权限分级、无上下文工程的深度披露。

**Goink（538 星，AGPL-3.0）——工程路线最接近。** 对话式写作 + 31 个结构化工具由模型自主调用（明确强调「不是流水线，是智能体」）；**写完一章自动触发维护自查：角色更新、伏笔回收、弧线推进、读者认知刷新**——与 NovAI 的写后同步同构；审稿子智能体独立审读正文与状态一致性；本地语义搜索（BGE 中文模型 ONNX 本地推理 + sqlite-vec，写完自动增量索引）；差异预览逐行对比、确认才写入；内置 Git 版本控制，每次对话自动提交；跨平台桌面安装包，开箱即用。

**天命 / 天衍（456 星，MIT）——口号最激进。** 「写到 3000 章依然连贯，不依赖上下文，靠状态」：15 维事实快照、12 类变更声明、六道生成门禁（协议解析、引用校验、一致性校验、未知实体检测、描写一致性、蓝图出场检查），正文必须穿过门禁才落地；修改设定后统一校验列出受影响章节。管理混乱（作者自述源码丢失、换新项目、群解散重建），但「结构化门禁 + 状态结算」的工程叙事与 NovAI 的写前检查/写后回填在同一方向上。

**Biz Novel Studio（3499 星，AGPL-3.0）——声量最大的应用类。** React + Express + LangGraph + Qdrant 检索 + Electron 桌面，长篇走「自动导演」持续推进、短篇走整本流程；拆书、通读导出、版本对比齐备。面向第一次写小说的新手。

**易创 easy-writing（892 星，AGPL-3.0）——定位重合的本地派。** 纯本地桌面、无需注册、BYOK、提示词全部是本机 Markdown 可视化编辑——与 NovAI 的「文件夹即真值」理念一致。写作体验打磨极深（打字音效、光标特效、码字统计日历、自爆挑战），AI 侧是划词工具 + 幽灵字补全（Tab 采纳，与 NovAI 的行内补全同款交互）+ 工作流一键建书 + 拆书 + 榜单爬虫。

**Oh Story（8731 星，MIT）——品类里星数最高。** 不做应用，14 个技能寄生在编程智能体上，用文件系统当记忆（「几十万字长篇不靠对话记忆硬撑」），写前守卫 + 写后去 AI 味，适配宿主含 ZCode。母公司同时运营商业在线工作台——开源技能引流、闭源服务变现的组合拳。

**novel-studio（164 星，Apache-2.0）——架构上最有野心。** 多智能体世界推演：角色拥有稳定智能体身份、私有观察与结构化记忆，仲裁者只裁结果不改意图；全书章位冻结 + 不可变章节合同；断点与幂等恢复。创建三个月，工程深度与 NovAI 相当，尚小众。

## 三、关键判断

**判断一：NovAI 的差异化清单正在被逐项复制。** 伏笔到期提醒（书童、Goink、天命、NeuroBook 剧情工坊）、按章人物状态与防剧透（书童）、写后状态结算（Goink、天命）、本地语义检索（Goink 全本地方案）、差异审阅写入（Goink、Storydex）、回收站与版本回退（普遍）——这些能力在闭源 OpenWrite 上看不到、曾被视为 NovAI 对商业竞品的护城河，如今在开源阵营里已各有实现。「我们是智能体架构的写作工具」这句话已经从差异化主张变成品类通用话术。

**判断二：智能体框架本身正在商品化。** 星数最高的两个项目都是技能包：不做应用、不造框架，直接寄生在 Claude Code / ZCode 等成熟宿主上。市场用星数投票验证了「借现有框架 + 领域技能」是更快被接受的路线。自研框架（NovAI、NeuroBook、Goink 的路线）的价值必须来自框架之上的领域深度与可靠性，而非框架本身。

**判断三：拥挤不等于固化。** 应用类最大者约 2700 星，且多数项目是单人作品、早期版本、甚至管理失控（天命源码丢失、NeuroBook v2 推倒重建、马良停滞）。尚无统治级开源赢家，也还没有任何一个项目把「结构化账本 + 权限体系 + 上下文工程」三件事同时做扎实——NovAI 若在未来几个月发布，仍处于「可以进入并站住一个工程可靠性位置」的窗口内，但窗口在收窄。

**判断四：闭源阵营的新形态是「开源外壳、闭源演进」。** 灵枢新版本付费、旧版免费开源；ApiSaverWriter 客户端 AGPL 开源、模型渠道与计费闭源；Oh Story 技能开源、在线工作台闭源变现。开源与商业的边界玩法已成为常规操作，纯开源项目需要想清楚自己的持续投入从哪里来。

## 四、对 NovAI 的启示

1. **发布叙事必须回答「为什么不用书童 / Goink / Oh Story」**——对手不再是只有 OpenWrite。对外 README 应含一张与主要开源竞品的定位对比，把「三账本 + 权限五档 + 上下文工程 + 浏览器零安装」的组合差异讲清楚，而不是单点功能。
2. **形态上存在一条借力路线可选：技能包。** Oh Story 验证了「文件系统记忆 + 宿主智能体」可以以技能包形态触达大量用户（且已适配 ZCode）。NovAI 的提示词体系与领域工作流理论上可以抽出一个轻量技能包作为引流入口，本体工作台承接深度用户。是否做、何时做需单独决策，此处仅记录选项。
3. **可靠性是尚无人占住的位置。** 各竞品 README 的能力宣称与其实际工程质量之间普遍存在差距（更新日志里高频的数据丢失与状态错乱修复）。NovAI 的测试门禁与三波数据安全收口，应在发布叙事中以「可验证的可靠性」呈现（如演示中断恢复、写前检查拦截错误），而非罗列机制名词。
4. **书童与 Goink 是压力测试与对标评测的第二、第三对象**，原 OpenWrite 压力测试清单的方法可复用于两者。
