# 真实创作复盘对照

## 记录时间

2026-06-09

## 背景

以 `/Users/honlnk/note/武当艳情` 作为真实创作案例，对照 NovAI 原始设计文档，复盘当前使用中暴露的问题。

本记录重点区分两类问题：

- **计划缺失**：原计划没有明确设计，真实使用后才浮现出来的新需求。
- **实现粒度不合适**：原计划方向正确，但当前落地方式过粗、过细或不够可持续。

## 对照表

| 观察点 | 原计划怎么写 | 真实使用中暴露的问题 | 判断 | 后续建议 |
|:--|:--|:--|:--|:--|
| 时间线组织 | 原计划定义了 `elements/timeline/`，并把“时间”作为核心要素之一。 | 真实创作时先生成了单个 `时间线.md`，后来发现不利于长期扩写，又改成 `timeline-01-缘起.md`。 | 实现粒度不合适。原计划有方向，但没有明确“按故事阶段拆分”的文件命名与结构。 | 建议默认时间线按阶段拆分，例如 `timeline-01-缘起.md`、`timeline-02-幼年.md`；避免生成一个无限增长的总文件。 |
| 剧情块组织 | 原计划定义了 `elements/plots/`，并把“情节”作为核心要素之一。 | 真实创作时先生成了 `剧情大纲.md`，后来用户指出剧情大纲不适合作为情节要素，应拆成 `plot-001-*` 这样的剧情块。 | 实现粒度不合适。计划要求“情节要素”，但实现初期把总纲和可检索剧情块混在一起。 | `plots/` 下优先存可独立检索的事件块；总纲若需要，应放在单独位置或标记为规划文档，不混入情节块。 |
| 要素文件格式 | MVP 清单只要求“定义最小可用的要素文件格式”。 | 真实使用后发现，不同要素类型需要不同模板：人物要称呼关系，时间线要具体日期，剧情块要核心事件、关键细节、暗线铺垫。 | 计划缺失。原计划只说“最小可用”，未细化各类要素模板。 | 为 `characters / plots / timeline / locations / worldbuilding` 分别定义默认模板，并让 Agent 创建文件时遵守。 |
| 新建要素时的默认策略 | 原计划强调从章节提取要素并写入 `elements/`。 | 当前更多依赖模型临场判断，容易先写大文件，再被用户要求拆分。 | 实现粒度不合适。工具能创建文件，但缺少“创建哪类要素时应该怎么拆”的策略。 | 在 Agent prompt 或工具前置策略中加入要素拆分原则：事件一块一文件、时间线一阶段一文件、人物一人一文件。 |
| 项目状态总览 | 原计划有文件树、预览、要素目录和 RAG，但没有独立项目状态索引。 | 真实创作后，用户需要反复问“我们都写了什么”“第一章讲了什么”“有哪些内容”。 | 计划缺失。该需求来自真实使用，不属于原 MVP 明确范围。 | 暂不实现；后续可评估 `NovAI.md` 作为项目状态地图，记录章节、人物、时间线、伏笔和最近进度。 |
| 称呼与关系规则 | 原计划把人物作为核心要素，但未细化人物关系规则。 | 写第二章时出现“大师兄称苏婉清为六师姐/六师妹”等称呼问题，用户需要手动指出。 | 计划缺失。人物卡不足以约束称呼和互动礼法。 | 人物卡或单独关系文件中加入“称呼规则”“年龄阶段”“关系禁忌”；生成前优先读取相关规则。 |
| 动作合理性与年龄约束 | 原计划只强调章节生成、要素提取和上下文复用。 | 用户指出“云溪一直站在玄岳门不合理”“下巴不能搁在刚满月孩子头顶”等动作问题。 | 计划缺失。当前设计没有针对叙事物理合理性的检查环节。 | 后续可引入轻量审校：年龄、身体动作、空间位置、时间连续性检查。 |
| 用户纠错后的要素同步 | 原计划有“章节 -> 要素”的提取与更新方向。 | 真实使用中，用户修改正文细节后，需要再手动要求更新时间线和剧情块。 | 实现粒度不合适。方向有，但同步触发不够主动。 | 当章节被修改且影响事件、时间、地点、人物关系时，Agent 应主动提示或执行相关要素更新。 |

## 总体判断

NovAI 的原始方向没有偏：

- 文件是正式资产
- 章节和要素分开保存
- 要素用于后续 RAG 复用
- Agent 通过工具读写项目文件

真实创作暴露的问题主要集中在：

1. 要素文件的默认拆分粒度不够明确。
2. 各类要素缺少专用模板。
3. 用户纠错后的要素同步还不够自动。
4. 项目状态总览是后续可能需要的新能力，但不是当前最急。

## 优先级建议

近期优先补：

1. `plots/` 与 `timeline/` 的默认拆分规则。
2. 各要素类型的 Markdown 模板。
3. Agent 写完或修改章节后的“是否需要同步要素”判断。

暂缓：

- 独立 `NovAI.md` 项目状态索引。
- 完整审校模块。
- 复杂的章节整理模块。
