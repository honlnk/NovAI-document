## 一、背景与目标

NovAI 已形成由对话驱动、通过工具和本地文件创作小说的完整工作台。写入确认、工具轨迹、文件变更和会话控制能力已经具备，但创作主流程仍有体验断点：

1. 空对话没有直接可理解的创作入口，用户需要自行理解指令、引用和权限控制。
2. AI 完成写回后，文件结果与稿件查看之间仍需手动寻找；较长的写入差异不容易审阅。
3. 手工编辑的草稿可能因模式切换、文件切换或外部修改而丢失，保存状态也不够准确。
4. 普通操作使用较多蓝色，部分提示层级过重；错误、警告与正常状态的视觉语言需要统一。
5. 长列表、窄屏、键盘操作、弹窗焦点和选字引用仍有可用性欠账。

本轮目标是：**在不重做界面的前提下，让创作者更容易开始任务、更安心地审核和编辑稿件、更清楚地理解系统状态。**

### 核心创作闭环

1. 选择章节、大纲或创作意图。
2. 通过自然语言向 Agent 下达任务。
3. 审阅并确认文件写入。
4. 打开产生变化的稿件，阅读、引用或继续编辑。
5. 保存结果，或在冲突和失败时恢复工作。

## 二、固定设计决策

| 编号 | 决策点 | 结论 |
| :-- | :-- | :-- |
| D1 | 页面结构 | 保留活动栏、分类侧栏、中央对话或计划区、右侧内容面板、底部状态栏；不新增稿件路由，不重排主导航 |
| D2 | 主题 | 保持黑白灰；主按钮为黑底白字，选中、悬停和普通信息反馈使用中性灰 |
| D3 | 蓝色处理 | 用户消息、首次引导、恢复项目、主动提问和普通按钮的蓝色样式改为黑白灰；保留已有品牌渐变和必要的正文链接辨识 |
| D4 | 语义色 | 红色用于错误和危险操作，琥珀色用于警告和等待确认；文件差异保留绿增红减 |
| D5 | AI 写回 | 不自动打开或切换用户正在查看的稿件；从文件变更面板提供明确的“打开稿件”入口 |
| D6 | 任务入口 | 空对话提供三个创作模板，点击仅填入输入框并聚焦，不自动发送或创建文件 |
| D7 | 稿件编辑 | 保留 Markdown 预览、纯文本编辑、原始内容三种模式；手动保存，不引入自动保存或富文本正文编辑器 |
| D8 | 草稿保护 | 同一文件跨模式保留草稿；主动离开、文件切换和页面卸载必须保护未保存内容 |
| D9 | 外部修改 | 保存普通文件前检测磁盘版本；冲突时保留草稿、展示差异，并由用户选择后续操作 |
| D10 | 选字引用 | 预览中选择文本后显示“引用到对话”按钮，点击才生成引用；沿用现有 500 字上限 |
| D11 | 窄屏策略 | 保留现有抽屉结构，修复溢出和工具换行；本轮不重做移动端活动栏 |
| D12 | 设计方法 | 借鉴 Impeccable 的局部评审和渲染验证流程、Vercel 的界面审计清单；是否安装外部技能另行确认，不作为施工前提 |

## 三、范围边界

### 与已有计划的关系

- 延续《UI 重构计划》确立的分类导航、对话控制面和右侧内容面板，不推翻其布局。
- 《输入框富文本化施工计划》已完成；本轮只复用聊天草稿写入、聚焦和命令能力，不重写 Lexical 编辑器。
- 《文件树与打开文件实时刷新计划》建立的文件监听和刷新链路继续使用；本轮补齐草稿与版本冲突保护。
- 《创作计划板交互优化计划》独立执行，计划板的新建、详情、改名和编辑布局不在本轮范围。

### 本期明确不做

1. 不引入新的 UI 框架、组件库、正文富文本编辑器、深色模式或自动保存。
2. 不修改 Agent 循环、模型协议、检索内核和项目文件格式。
3. 不实现校对、章节整理、版本管理等尚未落地的能力。
4. 不因界面优化顺手修复无关内核问题；发现新问题先记录，再单独排期。
5. 不为追求视觉新奇增加大面积插画、渐变、装饰卡片或无意义动效。

## 四、分阶段施工

### 阶段 1：视觉降噪与创作入口

#### 任务

- [ ] 统一首页、用户消息、首次引导、主动提问、队列、引用和普通操作的中性色规范。
- [ ] 普通主按钮使用黑底白字；次级按钮使用白底灰边；信息面板使用浅灰背景。
- [ ] 用户消息改为深灰气泡，引用和辅助文字保持足够对比度；AI 消息保留现有无气泡排版。
- [ ] 空对话提供“完善故事构想”“根据大纲写下一章”“润色当前章节”三个任务模板。
- [ ] 模板点击后只填充聊天草稿并聚焦；无大纲或当前章节时禁用对应入口并解释前提。
- [ ] 首次配置引导区分必须配置的模型与可选检索能力，与空对话形成单一视觉层级。
- [ ] 检查普通文字、选中态、禁用态和警告的对比度，状态不能只靠颜色区分。

#### 验收

- [ ] 三个入口生成符合当前项目上下文、可编辑的草稿，不擅自调用模型。
- [ ] 界面主要操作不再依赖蓝色，错误、警告和文件差异仍然清晰。
- [ ] 空项目、已有大纲、已打开章节三种条件下，任务入口的可用状态正确。

### 阶段 2：AI 写回与稿件查看

#### 任务

- [ ] 每轮文件变更面板为可读取的创建和修改文件增加“打开稿件”入口，沿用现有文件读取与内容面板链路。
- [ ] AI 写回后不自动切换稿件；无草稿的当前文件继续实时刷新，文件树和结果通知保持同步。
- [ ] 写入确认卡复用逐行差异组件，以紧凑增删视图替代截断的原文和新文双栏预览。
- [ ] 长差异默认折叠，按需展开，避免撑高输入区；确认期间禁止重复提交。
- [ ] 多项待确认写入显示当前进度和总量。
- [ ] 队列编辑、移除、插话、权限和思考强度切换失败时，在操作附近提供错误和重试入口。
- [ ] 运行失败不只显示底部状态，保留可恢复的用户输入和下一步操作。

#### 验收

- [ ] 从写回完成到查看对应稿件，不必再进入分类列表手动寻找。
- [ ] 查看写回结果不会打断聊天输入、正在阅读的稿件或未保存编辑。
- [ ] 长文本、连续多处修改和多项确认均能审阅，重复点击不会产生重复操作。
- [ ] 队列与配置失败能保留用户现场，并明确说明如何恢复。

### 阶段 3：草稿、保存与冲突保护

#### 任务

- [ ] 预览、编辑、原始模式之间切换保留同一文件的草稿；有草稿时预览显示草稿内容。
- [ ] 未保存状态在三种模式下持续可见；只有切换到另一文件时才按守卫规则处理草稿。
- [ ] 编辑区占满内容面板剩余高度，保存状态和按钮固定可达，长正文不将操作区推出面板。
- [ ] 保存等待真实写盘结果；失败保留草稿、编辑模式和可重试错误。
- [ ] 有未保存内容时，文件切换和返回首页统一提供“保存并继续 / 放弃草稿 / 继续编辑”。保存失败不得继续原操作。
- [ ] 单纯收起内容面板不丢弃草稿；关闭或刷新浏览器前提供系统级未保存提醒。
- [ ] 普通文件读取携带版本标识，手工保存使用开始编辑时的版本进行校验；复用计划保存的内容哈希思路。
- [ ] AI 或外部修改当前文件时保留草稿，提示“磁盘内容已更新”，支持查看差异、重新读取和保留草稿。
- [ ] 冲突后再次保存必须明确提示将覆盖新版本，并经过用户确认；不能静默覆盖，也不能无限重复同一失败。
- [ ] 当前文件被 AI 删除或重命名且存在草稿时，保留可编辑内容和磁盘状态说明，不静默清空。
- [ ] 文件读取失败时提供重试，不打开看似正常但没有内容的面板。

#### 实现约束

- 普通文件版本校验采用向后兼容的服务参数；现有项目文件和配置无需迁移。
- 继续通过现有项目服务读写文件，不在界面层直接访问文件系统。
- 复用已有差异展示、文件变更监听和计划冲突处理经验，不建立第二套版本历史系统。

#### 验收

- [ ] 模式切换、收起面板、文件切换、离开项目和保存失败均不会无声丢失草稿。
- [ ] AI 同时修改、重命名或删除正在编辑的文件时，用户能保留内容并理解磁盘状态。
- [ ] 覆盖、重新读取和继续编辑都有确定结果，事件乱序不会把旧内容写回新文件。

### 阶段 4：导航、窄屏与键盘可达性

#### 任务

- [ ] 章节与会话列表顶部增加即时筛选，保留目录分组；无结果时提供清除筛选入口。
- [ ] 长文件名合理截断并可查看完整名称；当前文件、当前会话和待回答状态在灰度下仍可辨认。
- [ ] 内容面板在窄屏下不超过可用视口；输入区工具按钮允许合理换行，避免横向溢出。
- [ ] 通用弹窗支持 Escape、初始焦点、焦点约束和关闭后的焦点恢复；首页弹窗复用该能力。
- [ ] 伪按钮替换为原生按钮或链接，补齐表单标签、图标名称、可见焦点和弹层键盘操作。
- [ ] 会话操作在键盘聚焦时同样可见；面板宽度可通过键盘调整。
- [ ] 稿件预览选择文本后，在选区附近显示“引用到对话”按钮；点击才写入现有聊天引用。
- [ ] 引用只接受当前稿件内的选区；清除选择、切换文件或进入其他模式后移除按钮，超过上限明确提示截断。

#### 验收

- [ ] 长章节列表和长会话列表可以快速定位，筛选不会破坏目录或当前选中态。
- [ ] 1440 像素桌面、1024 像素窄桌面、375 像素小屏无横向溢出或不可达操作。
- [ ] 仅使用键盘可以完成弹窗、文件模式、保存、写入确认、队列和引用操作。
- [ ] 焦点可见且关闭弹窗后回到触发位置；减少动态效果偏好得到尊重。

### 阶段 5：真实浏览器验收与收口

#### 验收路径

1. 新建或恢复项目，完成模型配置。
2. 选择章节或大纲，发起创作并观察 Agent 过程。
3. 审阅写入差异，处理确认并打开产生的稿件。
4. 选中稿件内容引用到对话，继续提出修改。
5. 手工编辑、切换模式、保存并模拟外部修改冲突。
6. 刷新页面、恢复会话，确认内容、状态和未保存提醒符合预期。

#### 验收要求

- 使用常驻测试项目 `~/note/test-novel`，通过“打开项目”或“恢复项目”进入；不把其中的密钥复制进仓库。
- 浏览器访问 `http://localhost:5173`；已有服务不重复启动，未运行时临时启动并在验收后关闭。
- 浏览器无法弹出系统目录授权时，使用《真机测试 OPFS 仿真目录方案》。
- 使用桌面、窄桌面和小屏截图审查信息层级与黑白灰效果，集中修复后复验。
- 检查空项目、无大纲、长章节名、长消息、长差异、读取失败和保存冲突。

## 五、新旧机制替代与兼容

| 项目 | 现有机制去向 | 升级后的机制 |
| :-- | :-- | :-- |
| 蓝色用户气泡和普通操作 | 替换普通蓝色样式 | 黑白灰消息与操作层级 |
| 空对话只有说明 | 保留原位置并补任务入口 | 三个可编辑模板 |
| 写回后自行寻找文件 | 保留手动浏览，补充结果入口 | 变更面板直接打开稿件 |
| 截断的双块写入预览 | 替换 | 可展开的逐行差异 |
| 模式切换重置草稿 | 替换 | 同一文件跨模式保留草稿 |
| 普通文件后写覆盖先写 | 替换手工保存的静默覆盖 | 版本校验、差异和显式覆盖 |
| 鼠标专用弹窗和悬停操作 | 替换伪按钮并补齐键盘行为 | 一致的焦点和键盘支持 |
| 鼠标松开即生成引用 | 替换 | 显式点击“引用到对话” |

## 六、验证、文档与交付

1. 每阶段补充对应纯逻辑或状态测试，重点覆盖草稿保护、版本冲突、写回打开、错误恢复和事件顺序。
2. 每阶段运行相关测试、全量 `pnpm test`、`pnpm typecheck`；涉及整体界面与共享组件的阶段完成后运行 `pnpm build`。
3. 外部模型不可用时仍完成本地状态、模拟事件和界面验证；真实模型生成、系统目录授权或屏幕阅读器未实测时必须明确报告。
4. 阶段验收后更新本文状态、施工日志和《当前进度》，记录偏差、用户影响和未验证项。
5. 未经单独批准不提交、不推送；若后续明确使用 goal 指令，再按仓库规则在完整阶段门禁处提交。
6. 涉及共享弹窗、全局样式、路由或其他全局骨架时，先列出拟修改文件并取得许可，不因本计划批准而自动豁免。
