# NovAI MVP 清单

最后更新：2026-06-07

## MVP 目标

MVP 的目标不是做出完整的小说创作平台，而是验证 NovAI 最核心的产品假设：

1. 用户是否愿意以“本地文件项目”的方式进行小说创作
2. AI 是否能够围绕章节文件和要素文件稳定工作
3. 文件系统 + RAG 的上下文管理方式，是否比传统聊天记忆更适合长篇小说创作

因此，MVP 只聚焦最小闭环：

`创建项目 -> 配置模型 -> 输入指令 -> Agent 读取/修改文件 -> 写入文件 -> 提取要素 -> 下次生成可复用要素`

## MVP 范围

## 必须完成

### 1. 项目创建与打开

- 创建小说项目
- 初始化标准目录结构
- 打开已有项目
- 读取项目配置和基础文件
- 记录项目打开、激活、关闭等项目生命周期日志
- 记住最后一次打开的项目，并在刷新后尝试恢复

这是所有后续能力的入口，没有这一步，整个产品无法成立。

### 2. 文件树与文件预览

- 展示 `chapters/`、`elements/`、`prompts/` 目录
- 点击文件后可查看内容
- 文件变更后可刷新展示结果

这是“文件为中心”的基础体验，没有文件树就无法体现 NovAI 与普通聊天工具的区别。

### 3. 模型配置

- 配置 LLM API
- 配置 Embedding API
- 支持测试连接
- 保存到 `novel.config.json`

这是 AI 能力运行的必要前提。

### 4. 内容生成主链路

- 输入自然语言创作指令
- 读取 SYSTEM 提示词
- 让模型通过文件工具读取必要上下文
- 调用 LLM 进行多轮 Agent Loop 推理
- 根据模型的 tool calls 执行文件读取、修改或创建
- 以流式方式展示生成过程
  - 将结果写入 `chapters/` 中的 `txt` 文件

这是 MVP 的核心，没有这一步就还不是 NovAI。

### 5. 要素提取

- [x] 从新章节中提取人物、地点、情节、时间线等要素（第一版规则型提取）
- [x] 将提取结果写入 `elements/` 子目录
- [x] 定义最小可用的要素文件格式
- [ ] 升级为 LLM 结构化提取与用户确认流程
- [ ] 支持已有要素去重、合并与覆盖策略
- [x] 新增 `elements/entities/`，容纳武功、武器、坐骑、丹药、信物等具体实体

这是 NovAI 能进入“长篇可持续创作”模式的起点。

### 6. 向量化与粗检索

- [x] 对要素生成 Embedding
- [x] 建立第一版项目 RAG 索引缓存
- [x] 查看索引状态并手动重建索引（已从设置页迁移至主工作区底部常驻状态栏）
- [x] 将 `RagSearch` 接入 Agent Loop，让模型可主动检索相关要素
- [x] 将检索结果作为工具结果回灌模型
- [x] 将当前过渡召回实现升级为正式 Orama 召回链路
- [ ] 完善自动增量索引、过期提醒与错误降级（contentHash 增量重建与状态栏一键重建已落地，自动后台重建与错误降级待补）
- [ ] 验证真实创作任务中的召回质量与上下文使用策略

这一步完成后，NovAI 才和普通“AI 帮你续写”工具拉开差异。

## 可以延后

以下内容很重要，但不建议阻塞 MVP：

- Rerank 精排（两阶段检索中的第二阶段）
- Git 自动提交与版本管理界面
- 校对模块
- 章节整理模块
- 提示词调教对话工作流
- 高级设置页
- 外部文件变更监听优化
- 多种复杂视图切换
- Claude Code 式完整权限系统、hooks、成本统计与 transcript

这些内容适合在 MVP 核心链路跑通之后继续补强。

## 第一步先做什么

当前基础工作台和第一版 Agent Loop 已经跑通，下一阶段重点不再是普通“生成按钮”，而是继续完善“对话驱动文件操作”的主链路。

原因：

- 没有项目创建与打开能力，AI 无处写文件
- 没有文件树和预览，用户无法感知“AI 正在操作小说工程”
- 没有基础页面骨架，后面的配置、生成、预览都无从承载

已完成的第一批任务包括：

1. 搭建路由与页面骨架
2. 完成项目创建 / 打开 / 修复流程
3. 完成本地文件读取与文件树展示
4. 完成文件预览面板
5. 接入模型配置和基础流式生成
6. 接入 `ReadFile / EditFile / CreateFile / RenameFile / DeleteFile / ListDirectory / FindFiles` 文件工具
7. 接入第一版 `query()` Agent Loop
8. 接入项目级日志与最近项目恢复
9. 接入第一版章节要素提取与 `elements/` 写入链路
10. 接入正式设置页 RAG 索引状态与手动重建入口
11. 接入 Agent 可主动调用的 `RagSearch`

## 建议的 MVP 执行顺序

### Step 1：工作台基础结构

- 首页
- 主工作区布局
- 设置页骨架
- 路由与状态管理

交付标准：

可以在界面中完成页面切换，并为后续功能预留稳定位置。

### Step 2：项目文件系统接入

- 新建项目
- 打开项目目录
- 初始化目录结构
- 扫描项目文件

交付标准：

用户能真实创建并打开一个本地小说项目。

### Step 3：文件树与预览

- 左侧文件树
- 点击文件打开
- 右侧 Markdown 预览

交付标准：

用户能浏览小说项目中的现有文件。

### Step 4：模型配置

- LLM 配置页
- Embedding 配置页
- 测试连接
- 配置持久化

交付标准：

用户能完成最基础的模型接入准备。

### Step 5：章节生成

- 输入指令
- 组装项目与默认目标上下文
- 由模型通过工具读取相关文件
- 调用 LLM 流式生成或继续工具调用
- 写入章节文件
- 预览生成内容

交付标准：

用户能通过一句自然语言指令生成一章内容并保存到本地。

### Step 6：要素提取与粗检索

- 提取要素（已完成第一版规则型实现）
- 写入要素文件（已接入 Test Lab 与正式右侧内容面板）
- 建立 Embedding 索引（已完成第一版索引缓存与手动重建）
- 下次生成时检索相关要素（已接入 Agent 主动 `RagSearch`）

交付标准：

系统能开始复用历史内容，而不再只是一次性生成器。当前已完成要素提取与写入、索引重建入口、Agent 主动 RAG 检索；召回链路已从过渡的手写 cosine 全量遍历升级为正式 Orama 内存向量检索（每个项目一个常驻 Orama 实例，IndexedDB 仍为跨会话持久层）；仍需继续验证召回质量，并补齐自动增量索引。

### Step 7：Agent 控制能力补强

- [x] 写工具执行前的权限确认（含 diff 预览）
- [x] 停止按钮 / AbortController
- [ ] Query Guard / 工具队列策略
- [x] 用户即时约束识别（「不要阅读文件」「不要写入」「只读不改」「只改当前文件」等指令解析 + 执行层强制）
- [x] `prompts/system.md` 修改后的会话刷新（hash 自动替换）
- [ ] 工具调用分组与更清晰的运行状态

交付标准：

用户能看见 Agent 正在做什么，并能在写文件前进行确认或中断任务；当用户明确限制工具范围时，Agent 不应越权调用读取或写入工具。

> 进度：权限确认 + diff 预览（`0707809`/`b0651e7`）、停止运行（`8feb3a4`）、结构化文件变更（`949d540`）、用户即时工具约束（`e774d2c`，第二轮补齐「只读不写」「只操作当前文件」）、system prompt 同会话刷新（`71c2d42`）均已完成，详见 [Agent 控制能力补强计划](../plans/Agent控制能力补强计划.md)。剩余 Query Guard / 队列策略和工具调用分组展示待推进。

## MVP 完成定义

满足以下条件时，可以认为 MVP 基本成立：

- 用户可以创建或打开一个本地小说项目
- 用户可以完成模型配置
- 用户可以输入一句自然语言意图，让 Agent 读取、创建或修改项目文件
- 章节内容或修改结果会写入本地章节文件（默认 `txt`）
- 系统会从章节中提取要素并保存（第一版已完成，质量方案待升级）
- 下一次生成时可以通过 `RagSearch` 利用已有要素辅助生成
- 项目运行过程可通过 `.novel/logs/agent.log.jsonl` 追踪

## 备注

如果后续开发中发现某些“必须完成”项实际上会显著拖慢验证速度，可以调整顺序，但原则不变：

优先验证 NovAI 的核心闭环，而不是优先补齐所有外围能力。
