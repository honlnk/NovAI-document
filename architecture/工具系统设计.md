# NovAI 工具系统设计

## 一、设计目标

工具系统是 NovAI 的项目执行层。聊天负责表达意图、确认动作和查看结果，真正的章节、要素与提示词通过工具写入项目文件。

工具设计遵循四条原则：

1. **限定在小说项目内。** 文件工具不能逃逸当前工作区，不提供通用 Shell 或整机文件访问。
2. **专用工具分工。** 目录浏览、路径查找、正文读取、精确修改和语义检索各自承担明确职责。
3. **安全由运行时保证。** 路径、权限、读后写入、冲突检查和用户确认在代码中强制执行，不只依赖提示词。
4. **结果可继续协作。** 工具返回结构化结果，写操作进入会话变更账本，界面能够展示确认和差异。

## 二、工具总览

| 工具 | 作用 | 主要边界 |
| :-- | :-- | :-- |
| `ListDirectory` | 查看目录的直接子项 | 不递归读取正文，默认隐藏内部项 |
| `FindFiles` | 按路径模式递归查找文件 | 只返回路径，设置数量上限 |
| `ReadFile` | 分页读取项目文本 | 只读受支持的格式，保护内部文件 |
| `EditFile` | 精确替换已有文本 | 强制读后写、过期保护、默认单处匹配 |
| `CreateFile` | 新建文本文件 | 不覆盖已有文件，可自动创建父目录 |
| `RenameFile` | 重命名或移动单个文件 | 不覆盖目标，不处理目录 |
| `DeleteFile` | 删除单个文件 | 先移入项目回收站，不直接永久删除 |
| `LoadElements` | 按名称批量加载稳定要素 | 覆盖人物、地点、实体、世界观 |
| `RagSearch` | 语义检索剧情线索 | 只覆盖情节与时间线索引 |
| `GetFileChangeHistory` | 查询当前会话的文件变更 | 只读，可按路径或轮次筛选 |
| `WebSearch` | 多角度联网搜索 | 返回外部来源与摘要 |
| `WebFetch` | 阅读指定网页正文 | 只处理网页，不访问本地文件 |
| `KnowledgeLookup` | 直达知识平台的条目全文 | 面向人物、历史、词语、古籍和术语等资料 |
| `DelegateToElementManager` | 委派独立要素管理会话 | 仅主智能体可用，任务必须自包含 |

## 三、项目文件工具

### 导航与读取

模型先通过目录和路径工具定位文件，再读取真正需要的正文。系统不向模型注入完整文件清单，也不自动读取近期章节。

文件读取支持分页，并对单次行数、长行和总字节数设置上限。过大内容会附带截断信息和后续读取位置，避免一次工具结果占满上下文。需要核对完整细节时，模型可以继续分段读取，而不是依赖被截断的片段。

### 修改与新建

修改已有文件必须先读取。读取状态记录路径和内容摘要；写入前再次读取并比较，若文件已变化则拒绝修改并要求重读。

精确替换要求原文能够唯一定位。需要替换多处时必须显式启用全部替换，避免因重复文本造成误改。成功写入后，本次读取状态失效，再次修改同一文件需要重新读取。

新建文件与修改已有文件严格分工：新建不能覆盖已有目标，已有文件通过精确替换修改。章节新建和重命名还会校验统一命名格式及章节编号冲突。

### 重命名与删除

重命名和移动只处理单个文件，目标必须不存在。删除先将原文件复制到带时间标识的项目回收站，再移除原路径，并返回回收站位置和删除统计。

项目配置与内部目录受到硬性保护，不能通过文件工具修改、重命名或删除。普通内部文件也不对模型开放读取；只有为取回溢出工具结果而保存的特定文本可以分页读取。路径校验同时防范绝对路径、上级跳转和大小写变体绕过。

## 四、故事记忆的读取分工

稳定设定与剧情检索不是同一问题，工具因此分为两类：

| 维度 | `LoadElements` | `RagSearch` |
| :-- | :-- | :-- |
| 数据范围 | 人物、地点、实体、世界观 | 情节、时间线 |
| 发现方式 | 主智能体先看到稳定要素目录 | 模型提交自然语言查询 |
| 查找方式 | 按目录名称精确匹配，可批量加载 | 向量粗召回与可选重排 |
| 返回内容 | 要素的完整结构化信息与正文 | 带来源、摘要、标签和相关章节的候选 |
| 后续动作 | 直接用于理解与创作 | 必要时按来源路径读取完整文件 |

要素目录只提供类型、名称和稳定摘要，帮助模型确定需要谁；完整正文由加载工具按需取回。语义检索用于模糊的剧情查询，不承担稳定设定的确定性披露。

章节正文不参与向量召回。模型需要原文、语气或具体场景时，通过文件导航与读取工具查阅。

## 五、外部知识工具

联网搜索、网页阅读和知识查询为创作提供外部资料，与项目文件工具分离。

- 搜索支持一次提出少量不同角度的查询，合并并去重来源。
- 网页阅读将页面正文转换为 Markdown，结果受长度限制。
- 知识查询按平台和条目名直接获取全文，未命中时可退回普通搜索。

这些工具只向模型提供外部资料，不自动把网页内容写入小说项目。是否采用、如何改写以及是否保存，都由后续创作与文件工具动作决定。

## 六、权限与确认

写权限分为五档：

| 档位 | 内容编辑的免确认范围 | 结构操作 |
| :-- | :-- | :-- |
| 仅审阅 | 所有编辑都需要确认 | 新建、重命名、删除均需要确认 |
| 章节内容 | 章节目录 | 均需确认 |
| 素材内容 | 要素目录 | 均需确认 |
| 章节与素材 | 章节目录和要素目录 | 均需确认 |
| 完全访问 | 所有合法可写路径 | 可免确认，但硬路径保护仍生效 |

精确替换属于内容编辑；新建、重命名和删除属于结构操作。提示词等其他合法文档在非完全访问档下编辑也需要确认。授权只针对当前动作，不自动扩展为永久许可。

确认在执行前发生，展示文件路径和相应的内容、差异或路径变化。用户拒绝或停止时，实际写入不会执行，失败结果返回模型。确认按会话归属，主智能体和要素管理员的请求不会混答。

## 七、变更记录与差异

成功的写工具会生成结构化变更并追加到当前会话账本：

| 操作 | 记录内容 |
| :-- | :-- |
| 新建 | 新文件路径与完整新增内容 |
| 编辑 | 实际替换的前后片段与差异 |
| 重命名 | 原路径与目标路径 |
| 删除 | 原路径、回收站路径和删除统计 |

确认预览来自模型提交的写入参数，账本差异来自工具真正执行的结果，两者分别服务于「执行前决策」和「执行后审计」。账本随会话保存，不因模型上下文压缩而消失。

主智能体可以通过变更历史工具查询当前会话的文件改动；界面按轮次和文件聚合这些记录，形成写回面板与差异视图。

## 八、角色工具面

| 能力 | 主智能体 | 要素管理员 |
| :-- | :-- | :-- |
| 文件导航与读取 | 全部 | 全部，可读取章节作为整理依据 |
| 新建与编辑 | 全部合法项目路径，受权限控制 | 仅要素目录，运行时强制路径闸 |
| 重命名 | 可用 | 仅要素目录内的源与目标 |
| 删除 | 可用，需用户明确意图并受权限控制 | 不可用，只能在汇报中提出建议 |
| 稳定要素加载 | 可用 | 不使用，直接导航和读取要素文件 |
| 情节与时间线检索 | 可用 | 可用 |
| 会话变更历史 | 可用 | 不提供查询工具，但自身变更仍入账 |
| 外部知识工具 | 全部 | 不提供 |
| 委派 | 可委派要素管理员 | 不可再次委派 |

要素管理员不注入主智能体的项目记忆、大纲和要素目录，而以项目要素规范作为角色约束。它可以继承主模型与权限设置，也可以使用项目级覆盖配置。

## 九、委派会话

委派不是把主对话原样交给一个临时函数，而是创建并驱动一个真实、持久化的要素管理员会话：

1. 主智能体提交自包含任务和可选整理范围。
2. 服务创建要素管理员会话，任务进入该会话的收件箱。
3. 子会话使用独立工具白名单、路径闸、确认链和变更账本。
4. 主智能体接收最终汇报和会话标识，完整工具过程保留在子会话中。
5. 用户可以打开该会话查看过程或继续交流；停止主会话也会停止正在执行的委派。

委派工具本身不直接写文件，所有写入都发生在要素管理员的内层工具中。因此，工具边界、确认与审计不会因委派而被绕过。

## 十、上下文保护

工具系统与 Agent 运行时共同控制上下文体积：文件读取有分页和截断，路径查找有数量上限，检索结果可限制候选数量。

单次语义检索结果过大时，完整内容会保存到项目内部的溢出文件，模型视图只保留开头、结尾和取回位置。模型之后能通过受控读取例外分页取回，避免重要结果被永久截断。

这与会话历史压缩是两套机制：前者处理单次工具输出，后者处理长期对话增长；二者都不替代项目文件和会话账本中的持久事实。
