# 关系图谱要素计划

> 状态：占位，待讨论
>
> 背景：人物关系目前散落在人物卡片的自然语言描述里，无法支撑"查询 A 和 B 的关系路径""找出所有与 C 有敌对关系的角色"这类结构化查询。
>
> 核心想法：新增"关系"要素类型，用 JSON 格式记录人物间关系；提供 Canvas JSON 式的无边白板可视化展示；提供关系查询工具。可能扩展到实体、事件、时间的关系。
>
> 参考：同级目录 `duet` 项目中已有类似关系实现，可作为设计参考。

## 待讨论

- 关系对象 Schema：起点、终点、关系类型、强度、建立时间、状态变化历史？
- 关系类型的分类体系：血缘、师徒、敌对、恋爱、利益、未知……是否需要预定义枚举，还是自由文本？
- 双向关系与单向关系如何处理？（A 恨 B 不等于 B 恨 A）
- 与人物卡片的关系：关系是独立要素文件，还是嵌入人物卡片？
- 可视化方案：Canvas JSON 式无边白板的技术选型？（canvas 渲染、SVG、还是第三方库？）
- 查询工具设计：模型如何发起关系查询？（"A 和 B 的关系路径""所有与 C 敌对的角色"）
- 扩展性：实体关系（物品归属）、事件关系（因果链）、时间关系（先后重叠）是否复用同一套机制？
