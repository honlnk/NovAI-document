## 一、背景与问题

计划页当前沿用了工作区的外层骨架，但在中央区域又建立了一套深色看板和内嵌详情区域。右侧原有文件内容面板同时保持展开，形成多个区域争用宽度的情况。

真实页面检查确认：

1. 桌面端的右侧文件内容面板不是覆盖式抽屉，而是实际占用宽度的可收起面板；只有窄屏才变成右侧抽屉。
2. 计划看板只替换了中央对话区域，计划详情仍嵌在看板内部，与文件内容面板属于不同层级。
3. 在其他分类打开文件后切到计划页，文件面板会继续显示原文件；它既不是当前计划的内容，也会挤压看板。
4. 计划看板与详情使用深色背景，其他分类的主内容区域和右侧内容面板使用白色，页面像两套界面拼接。
5. 左侧计划列表与看板右上都有新建入口；看板右上还承担刷新，入口层级不统一。
6. 在 1280 像素桌面宽度、计划详情与文件面板同时打开时，看板实际只剩约 320 像素，四列内容无法正常并列阅读；看板标题和操作也会被压缩。

## 二、目标与固定设计决策

本轮目标是：**让计划页回到整个工作区统一的布局范式，而不是继续为计划增加独立面板。**

统一规则为：左侧负责导航与选择，中间负责当前分类的主要任务，右侧负责查看和编辑当前选中的内容。

| 编号 | 决策点 | 确定方案 |
| :-- | :-- | :-- |
| D1 | 中央主区域 | 始终显示计划看板，不因打开详情或新建而替换、覆盖或内嵌挤压 |
| D2 | 计划详情归属 | 复用工作区最右侧内容面板的位置与展示规则，不再在看板内部保留另一块详情区域 |
| D3 | 新建归属 | 新建计划与计划详情共用右侧面板，同一时刻只显示其中一种 |
| D4 | 桌面布局 | 右侧面板展开时实际占用宽度，可收起；不改成覆盖式浮层 |
| D5 | 移动布局 | 右侧面板沿用窄屏右侧抽屉规则，不挤压看板视口 |
| D6 | 配色 | 看板、计划详情和新建表单使用与其他主页面一致的白色及中性灰，不保留计划专用深色主题 |
| D7 | 刷新入口 | 移到左侧「计划」标题行原新建按钮的位置，使用与其他工具一致的图标按钮和明确提示 |
| D8 | 新建入口 | 看板右上角原刷新、新建所在的区域只保留「新建计划」；左侧不再设置第二个新建按钮 |
| D9 | 看板顶栏 | 保留标题、卡片数量和已搁置筛选；已搁置是内容筛选，不随刷新与新建一起移走 |
| D10 | 默认状态 | 进入计划分类时，未选择计划或新建任务则右侧面板收起；点击卡片或新建后才展开 |
| D11 | 跨分类恢复 | 计划页不显示其他分类的文件；返回对话、章节、要素或提示词时恢复此前打开的文件面板 |
| D12 | 草稿 | 延续静默保留：收起面板、切换分类、切换卡片和关闭详情不弹离开确认；重新打开可继续未保存内容 |

## 三、布局与交互设计

### 1. 页面分区

| 区域 | 计划页内容 | 规则 |
| :-- | :-- | :-- |
| 最左分类导航 | 对话、章节、要素、提示词、计划及工具入口 | 保持现状 |
| 左侧分类列表 | 计划标题、刷新、看板入口、最近计划 | 当前打开的计划需要与列表选中态一致 |
| 中央主区域 | 计划标题、数量、已搁置筛选、新建、看板列 | 始终保留看板；白色背景，列区域按需横向滚动 |
| 最右内容区域 | 计划详情或新建表单 | 与其他分类的文件内容面板共用外层位置、宽度、收起和移动抽屉机制 |
| 底部状态栏 | 索引、当前大纲、执行状态 | 保持现状，不被右侧面板遮挡 |

### 2. 面板归属与跨分类规则

1. 工作区右侧面板增加明确的内容类型：普通文件、计划详情、新建计划。外层宽度、边框、收起、遮罩、移动端关闭和底部状态栏避让由同一处承载。
2. 计划详情和新建表单作为右侧面板的内容实现，不在看板内另做一套位置、宽度和响应式规则；具体组件拆分由施工方按职责决定，避免把文件特有逻辑扩散到计划内容。
3. 进入计划分类时：
   - 默认收起右侧面板，不展示此前打开的普通文件；
   - 若当前项目已有选中的计划，且从计划分类内部再次进入看板，保持该计划详情打开；
   - 从其他分类返回计划分类时，恢复此前选中的计划详情或新建表单，而不是默认展开无关文件。
4. 离开计划分类时，不关闭普通文件，也不清除计划选择、新建输入或计划编辑草稿。
5. 返回对话、章节、要素或提示词时，恢复离开前普通文件面板的展开或收起状态；此前未打开文件时不得凭空显示空面板。
6. 切换项目时清除项目相关的计划选择、计划草稿和新建输入；不得把上一项目的计划显示到另一项目。普通文件继续按现有项目切换规则处理。
7. 看板卡片、左侧最近计划、已搁置卡片等所有打开详情的入口，都显示同一个计划详情；正在新建时点击其他计划，则切换为该计划详情，新建草稿保留。
8. 右侧面板关闭只影响可见性，不清除当前计划或新建任务。再次点击同一卡片或新建入口，可以继续之前的工作。

### 3. 看板与入口

1. 看板顶栏只保留标题、卡片总数、已搁置筛选和「新建计划」；删除看板内刷新按钮。
2. 左侧计划标题行原「新建」按钮替换为刷新图标按钮，提供「刷新计划」提示与可读名称；刷新期间显示忙碌状态并防止重复触发。
3. 看板右上「新建计划」保持醒目但遵循统一的中性色主按钮规则，不保留蓝色计划专用按钮。
4. 看板空状态保留新建入口，以便没有计划时仍能直接开始；它与右上新建打开同一个新建面板，不增加额外表单。
5. 看板主区域使用白色背景，列使用克制的浅灰背景或细分隔；卡片使用白色表面与中性边框。文字、选中态、悬停和禁用态对比度符合现有界面规范。
6. 看板列保持当前四列与排序交互。宽度不足时仅看板列区域横向滚动，标题、数量、筛选和新建按钮不得被逐字挤压，也不得导致整个页面横向溢出。
7. 右侧面板展开后中央看板自然变窄，这是预期的桌面占位行为；不能再额外嵌入详情，也不通过覆盖看板回避宽度分配。

### 4. 计划详情与新建

1. 详情头部沿用普通文件内容面板的头部高度、留白、边框和控件层级，显示计划名、预览/编辑切换与关闭入口。
2. 计划名保持可编辑；名称和正文仍通过同一个保存操作提交，真实文件名同步规则不变。
3. 五个分组状态位于头部下方固定区域，选中态与看板位置使用同一份最新状态；切换分组不清空草稿。
4. 已有计划默认预览 Markdown；双击正文或点击编辑进入多行输入。只保留预览、编辑两态，不提供文件面板的「原始」模式。
5. 正文撑满右侧可用高度并内部滚动；长正文不能把保存和删除推出可见操作区。
6. 保存、未保存状态、更新时间与删除继续位于底部同一操作行；宽度不足时合理换行，保存与删除始终可达。
7. 保存成功回到预览；保存失败或冲突时保留编辑现场、错误和处理入口。
8. 删除继续两步确认并进入项目回收站；成功后收起计划详情并刷新看板。
9. 新建面板显示「新建计划」标题、计划名、正文、创建和取消。创建等待真实结果；成功转为新计划详情预览，失败保留全部输入。
10. 计划使用标准浅色 Markdown 渲染，不继续保留只为计划新增的深色变体；移除该变体前须确认没有其他调用方，不能改变聊天和普通文件预览的配色。

### 5. 草稿与状态一致性

1. 计划详情的草稿真值继续由现有计划状态层管理，不移动到右侧外壳，也不复制到文件草稿。
2. 切换计划或关闭详情只改变当前显示对象，不清理被切走卡片的名称与正文草稿；再次打开同一张卡片应恢复未保存内容和编辑模式。
3. 为实现上述恢复，需要按项目与计划标识保留卡片级编辑会话；读取外部新内容时不得覆盖有草稿的卡片。缓存只保存界面草稿，不成为计划内容的第二存储。
4. 新建草稿继续独立保留；新建、详情互斥展示不等于相互清空。
5. 保存成功后清除该卡片的草稿并刷新看板；删除卡片后清除该卡片对应的编辑会话。
6. 如果实现过程中确认现有状态管理无法无损恢复切卡前的编辑现场，必须先补相应状态能力和测试，不得以「面板迁移」为由恢复成切卡丢草稿。
7. 普通文件保持现有草稿保护与离开行为；本计划只确保面板切换不会额外清除普通文件草稿，不扩展其保存、冲突或离开规则。

## 四、新旧机制替代与兼容

| 项目 | 旧机制去向 | 新机制 |
| :-- | :-- | :-- |
| 看板内嵌深色详情与新建区域 | 删除布局与重复入口 | 工作区统一的右侧内容面板 |
| 计划详情挤占看板内部宽度 | 替换 | 桌面右侧实际占位，窄屏右侧抽屉 |
| 从其他分类残留的文件面板 | 替换显示规则 | 计划分类只显示计划详情或新建 |
| 深色看板与深色详情 | 替换 | 与其他主页面一致的白色和中性灰 |
| 左侧新建与看板新建并存 | 左侧入口改为刷新 | 看板右上新建，空状态保留同一新建能力 |
| 看板右上刷新与新建 | 拆分职责 | 刷新移到左侧标题行，新建留在看板右上 |
| 计划专用深色 Markdown 变体 | 无其他调用方则移除 | 复用标准浅色 Markdown 外观 |

- 不迁移计划正文、文件名、标识、状态、排序、时间或项目配置。
- 不修改右侧面板宽度的已有本地偏好；计划与文件沿用相同的桌面宽度规则。
- 不改变旧计划文件的读写和兼容策略；本轮只调整显示位置与交互入口。
