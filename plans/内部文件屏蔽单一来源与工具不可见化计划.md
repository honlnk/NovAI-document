## 文档状态

- 记录日期：2026-11-07。
- 当前状态：**已完成（W1-W3 全部通过门禁与真机验收，2026-11-07 结项）**。
- 本文档是内部文件（`novel.config.json`、`.novel/`、`.novai/`）屏蔽体系的统一设计与施工依据：建立屏蔽名单单一来源，列表/搜索/读写工具全部接入，模型侧不可见化。2026-11-07 用户以 goal 指令批准开工。
- 关联：本次与 [传统工具升级与内容搜索补齐计划](传统工具升级与内容搜索补齐计划.md) 的 SearchFiles 路径边界同属内部防护族；报错文案教学化对齐 `6d24dcf`（EditFile 提示词按 ZCode 标准收敛）的动态反馈思路。

## 一、背景与动机

真机使用中主智能体反复读不该读的文件，撞 `ReadFile.path 不能指向项目内部文件（novel.config.json、.novel、.novai；.novel/spill/ 除外）` 报错。诊断（2026-11-07，会话代码调研）确认根因不是模型顽皮，而是防护结构有洞：

### 1.1 现状防线全景（代码事实）

| 防线 | novel.config.json | .novel/ | .novai/ | 代码位置 |
| :-- | :-- | :-- | :-- | :-- |
| 提示词告知 | ❌ 结构段没提 | ✅ 有一句「应用内部数据，不要直接读写」 | ❌ 没提 | `agent/prompt.ts` PROJECT_STRUCTURE_LINES |
| ListDirectory 默认 | ❌ 列出 | ✅ 隐藏 | ✅ 隐藏 | `directory-tools.ts:45-50` |
| ListDirectory `showHidden: true` | ❌ 列出 | ❌ 列出 | ❌ 列出 | 同上，模型可传参数 |
| FindFiles 默认 | ❌ 匹配 | ✅ 隐藏 | ✅ 隐藏 | `walkFiles` `includeHidden=false` |
| FindFiles `includeHidden: true` | ❌ 匹配 | ❌ 匹配 | ❌ 匹配 | `walkFiles`，模型可传参数 |
| SearchFiles 内容 | ❌ **匹配行+上下文（含 API key）** | ✅ 隐藏 | ✅ 隐藏 | `search-text.ts collectMatches` walkFiles(false) 只跳点开头 |
| ReadFile | ✅ 拦截（spill 例外） | ✅ 拦截（spill 例外） | ✅ 拦截 | `file-tools/common.ts assertReadableDocumentPath` |
| 写/改/删/移动 | ✅ 拦截 | ✅ 拦截（含 spill） | ✅ 拦截 | `assertMutableDocumentPath` / `assertWritableDocumentPath` |

`novel.config.json` 是三处同时漏的主犯：提示词没提、列表看得见、搜索能漏内容。`.novel/`、`.novai/` 是次犯：模型传 `showHidden/includeHidden: true` 或从 `.novel/trash` 回收站提示顺藤摸瓜后也会撞墙。

### 1.2 内容侧漏（安全问题）

SearchFiles 路径断言只管搜索根目录，根目录漫游时 `novel.config.json` 被正常遍历和匹配——**ReadFile 挡住的配置内容（含模型 API key），SearchFiles 能把匹配行连同上下文带进模型上下文**。这是独立于可见性的漏洞，藏列表堵不住，必须在内容遍历层跳过。

### 1.3 判定逻辑分散

「哪些东西不该给模型看」目前由两处私有逻辑各管一段：`file-tools/common.ts isInternalPath`（内部路径）与 `directory-tools.ts` 遍历里的 `name.startsWith('.')`（隐藏项）。按本计划打补丁若各写各的，将来新增内部目录要改多处，漏一处就是新漏洞。用户拍板：建立屏蔽名单单一来源模块，所有工具走同一逻辑。

## 二、固定设计决策（D1-D8，全部拍死，无开放选择题）

| 编号 | 决策点 | 结论 |
| :-- | :-- | :-- |
| D1 | 屏蔽名单单一来源 | 在 `tools/path.ts` 新增「内部路径与可见性」一节：名单常量 + 判定函数 + 教学式报错文案。所有工具（common.ts 断言族、ListDirectory、walkFiles、SearchFiles）从这里导入，不各自保留副本 |
| D2 | 模型不可见化 | ListDirectory 与 FindFiles 对点开头条目**和** `novel.config.json` 永远隐藏——删除模型可传的 `showHidden` / `includeHidden` 参数（输入类型、validateInput、schema 同步删除），无开关 |
| D3 | 内容侧漏 | walkFiles 遍历层接入内部路径跳过：非 spill 的内部路径直接跳过（文件和目录都跳），SearchFiles 自动获得防护；`.novel/spill/` 豁免照旧（显式搜索 spill 目录是合法取回行为） |
| D4 | 提示词 | 不新增静态禁令条目。`PROJECT_STRUCTURE_LINES` 中已有的 `.novel/` 一句保留（spill 指引和回收站提示会把 `.novel` 字样带进上下文，这个事实陈述仍有用）；`novel.config.json`、`.novai/` 不写进提示词 |
| D5 | 报错教学化 | common.ts 四处断言的报错统一升级为教学式（文案见 §四），与判定同住 path.ts。报错是运行时动态反馈（对齐 `6d24dcf`），不是提示词静态规则 |
| D6 | 兼容条款 | 旧会话里带 `showHidden/includeHidden` 的历史工具调用是**历史消息**（model view 的 assistant tool_calls + tool 结果成对原文保留），不会被重新执行，无需迁移；**旧用户若存了依赖这两个参数的写作提示词**，行为静默变化（参数被 schema 拒绝后模型会改普通调用，结果只是看不到隐藏项）——属预期行为收窄，在施工日志记录 |
| D7 | 不做配置化 | 名单是应用固定内部文件，不做用户可配置项（防误关防护）；不做通用权限引擎，只是常量 + 纯函数 |
| D8 | 不放开 trash 可读 | `.novel/trash` 回收站仍整体禁读（防诱导翻回收站）；spill 例外保持现状不动 |

## 三、屏蔽名单模块设计（D1）

位置：`packages/core/src/core/tools/path.ts`（已是公共路径层，依赖方向干净——file-tools/common.ts、directory-tools.ts、search-text.ts 都已从它导入）。

模块内容（对外只暴露判定与报错，名单本身保持私有——外部消费「是不是」而非名单，名单变更零外溢）：

| 导出物 | 职责 |
| :-- | :-- |
| 内部路径名单（私有常量） | 内部文件名（`novel.config.json`）、内部目录名（`.novel`、`.novai`）、spill 例外前缀（`.novel/spill/`）；比较前统一大小写折叠（macOS APFS 大小写不敏感，`Novel.Config.JSON` 变体同命中） |
| 内部路径判定 | 项目根相对路径是否内部路径（文件或目录，含 spill） |
| spill 放行判定 | 是否 `.novel/spill/` 自身或其子路径（取回通道例外） |
| 条目隐藏判定 | 条目名点开头 **或** 内部路径 → 对模型不可见（ListDirectory 用） |
| 遍历跳过判定 | 路径点开头 **或** 非 spill 的内部路径 → 跳过（walkFiles 用，目录命中即整棵子树跳过） |
| 教学式报错工厂 | 入参为工具参数标签（如 ReadFile.path），产出 §四定稿文案的 Error 实例 |

### 各工具接入点

| 接入点 | 文件 | 改用 |
| :-- | :-- | :-- |
| 读写断言族（4 处） | `file-tools/common.ts` | 私有 `isInternalPath`/`SPILL_DIR_PREFIX` 删除，改从 path.ts 导入；报错统一 `internalPathError(label)` |
| ListDirectory 条目过滤 | `directory-tools.ts` | `hidden && !showHidden` → `isAgentHiddenEntry(entry.name)` 直接跳过；`showHidden` 参数删除；`ListDirectoryEntry.hidden` 字段保留恒 false（下游格式化只读 kind/path，app 无消费，字段保留避免类型级联改动） |
| walkFiles 遍历 | `directory-tools.ts` | `includeHidden` 参数删除，改 `shouldSkipInWalk(entryPath)`（条目路径级判定，目录命中即整棵子树跳过）；`novel.config.json` 随内部名单自然跳过 |
| SearchFiles | `search-text.ts` | 无需改动——collectMatches 走 walkFiles 自动获得防护；`assertReadableDirectoryPath` 的报错文案经 common.ts 统一 |
| schema | `agent/tools.ts` | ListDirectory 的 `showHidden`、FindFiles 的 `includeHidden` 属性删除；`additionalProperties: false` 下旧参数调用会被 schema 拒绝，模型重试普通调用（D6 预期行为） |

## 四、报错文案定稿（D5）

四处断言（读写两族 × 文件/目录两版）统一为同一段教学文案（label 前缀不同）：

```
{label} 不能指向应用内部文件。novel.config.json（项目配置，含模型密钥）、.novel/、.novai/
由应用自行管理，不通过工具读写，也不会出现在目录列表和搜索结果中。唯一例外是
.novel/spill/（超长工具结果的取回通道，可按指引用 ReadFile 分段读取）。
如果你需要项目配置信息（模型、默认目标、权限档位），模型名与默认目标已在每条用户指令的
上下文中给出，其余请直接询问用户，不要尝试读取配置文件。
```

要点：陈述边界 + 陈述原因（密钥）+ 陈述出路（上下文已给/问用户）。模型撞一次即学会，不再换路径变体重试。

## 六、验收标准

1. `ListDirectory`（根目录）结果不含 `novel.config.json`、`.novel`、`.novai`；任何参数组合均不出现。
2. `FindFiles`（`*.json`、`**/*`）结果不含 `novel.config.json` 及内部目录内容。
3. `SearchFiles` 在项目根目录搜索任意词，结果不含 `novel.config.json` 的任何行（含密钥行）；显式 `path` 指向内部目录时报教学文案（spill 目录除外）。
4. `ReadFile`/`EditFile` 等指向内部文件时报 §四教学文案；`.novel/spill/` 读取与分段取回不受影响。
5. 真机（或降级走查）观察：Agent 盘点项目后不再尝试读取 `novel.config.json`。
6. 全量 `pnpm test`、`pnpm typecheck` 绿。

## 七、明确不做

- 用户可配置的屏蔽名单 / 通用权限引擎（D7）。
- 只读配置查询工具（模型名/默认目标已在上下文，先观察真机是否真被「用户问配置」卡住，有实据再立）。
- 放开 `.novel/trash` 可读（D8）。
- 提示词新增静态禁令条目（D4）；`.novel/` 既有句保留不删。
- `ListDirectoryEntry.hidden` 字段的删除（保留恒 false，避免类型级联；标注为遗留字段）。
- UI 文件树、RAG 索引构建的可见性改动（走 fs/rag 服务层，不经 agent 工具，不在本期范围）。

## 八、风险与约束

- **schema 收窄的兼容性**：`additionalProperties: false` 下带旧参数的新调用会被拒，模型自行重试普通调用——预期行为，D6 已记录；若观察到某协议下模型不自动重试，在施工日志记录并评估。
- **walkFiles 过滤对 FindFiles 超限采样的影响**：内部目录不再计入顶层目录分组与总数，采样口径更干净，无功能损失。
- **spill 取回链路是本期防护的唯一例外区**：W2 测试必须覆盖「spill 文件可读、spill 目录可显式搜索、spill 之外内部目录全禁」三角，防误伤取回通道。
- **报错文案为中文长句**：与现有工具报错风格一致（现有 MissingDirectory 等已是教学式长文案），不引入新风格。
