# 看板卡片详情自动保存与状态操作优化计划

## 文档状态

- 记录日期：2026-11-19；2026-11-20 根据正文实际效果完成复核。
- 当前状态：**方案复核稿，待用户确认，未开始施工**。
- 前置条件：《正文自动保存与并发冲突交互重设计计划》已全部落地，并复核了其普通自动保存、冲突反馈和差异比较。本计划复用其保存原则与事件序防线，不与其并行修改同一保存基础设施。
- 本计划不自动批准共享文件修改、代码提交或推送。没有 goal 指令时，施工完成后停止并等待用户审查。

## 一、为什么优化

创作计划、伏笔和节奏卡的详情页目前同时存在两种操作逻辑：名称、正文和计划字段需要手动保存，顶部状态按钮却会立即修改卡片；伏笔「放弃」又要求登记原因，但按钮没有原因输入入口，用户只能看到失败提示。

本计划将三个详情页收敛为同一种日常体验：

> 用户修改内容或选择状态后，停止操作两秒由应用保存；只有主动放弃伏笔时，才需要填写原因并明确确认。

这次优化只处理卡片详情的编辑、状态选择和冲突操作，不重做页面布局、视觉主题或看板信息架构。

## 二、目标、范围与固定取舍

### 1. 用户最终得到的体验

1. 修改名称、正文、节奏计划字段等可编辑内容后，最后一次操作约两秒自动保存，不再点击底部「保存」。
2. 在计划或伏笔详情中点击普通状态按钮后，不立即切换选中状态，也不立即移动卡片；两秒后保存，成功才更新按钮与看板分组。
3. 连续修改不同字段，或同时选择新状态时，最终按同一张卡片的最新整体快照保存，不拆成相互覆盖的独立请求。
4. 正常状态只显示「等待保存 / 正在保存 / 已保存」；保存成功后保留当前编辑模式，不因一次保存自动切回预览。
5. AI 或外部编辑器同时修改卡片时，不静默覆盖用户输入，也不因冲突突然关闭详情；用户可以从持续提示中打开版本比较与处理。
6. 用户可以主动放弃伏笔，无需借助 AI 或手工修改 Markdown；原因和原卡片内容都得到保留。

### 2. 适用范围

| 卡片 | 自动保存内容 | 状态操作 |
| :-- | :-- | :-- |
| 创作计划 | 计划名、计划正文 | 五个现有状态按钮；普通状态均走两秒延迟保存 |
| 伏笔 | 伏笔名、读者视角、作者真相 | 普通状态走两秒延迟保存；放弃先登记原因，再明确确认 |
| 节奏卡 | 卡名、计划值、出场角色、自然语言补充、节奏意图 | 状态默认由写后回写和偏差判定驱动；作者校正遵循《伏笔与节奏卡作者字段控制权升级计划》，不新增普通状态按钮 |

只读结构字段、节奏卡实际值和新建卡片表单的字段开放由《伏笔与节奏卡作者字段控制权升级计划》负责；本计划只负责将这些领域届时已经开放的编辑字段接入统一保存与冲突机制。看板拖拽排序和删除流程不在自动保存范围内。伏笔拖拽进入「已放弃」列只增加原因登记入口，其他拖拽行为保持现有立即落盘语义；节奏跨列人工校正按关联计划处理。

### 3. 固定取舍

| 项目 | 本期固定方案 |
| :-- | :-- |
| 自动保存时机 | 最后一次字段编辑或普通状态选择后 2000ms；不逐击键写盘 |
| 手动保存 | 删除详情底部保存按钮，不增加手动/自动保存开关 |
| 编辑模式 | 保存成功不自动返回预览；预览/编辑仍由用户主动切换 |
| 卡片快照 | 同一轮所有已修改字段和最终普通状态一次提交 |
| 状态视觉 | 保存成功前保留已生效状态；待选择状态用轻量等待标记，不伪装成已生效 |
| 放弃伏笔 | 原位原因填写 + 「确认放弃 / 取消」；不自动计时放弃 |
| 冲突呈现 | 非阻塞持续提示 + 用户主动展开比较；不自动清空或跳走编辑现场 |
| 恢复机制 | 未落盘内容保存在浏览器恢复区；不在小说项目中建立卡片草稿目录 |
| 数据格式 | 沿用现有卡片 Markdown 与放弃原因字段，不迁移旧卡片、不改变旧状态语义 |

### 4. 与正文能力的复用边界

| 正文已确立的能力 | 卡片采用方式 |
| :-- | :-- |
| 两秒去抖、按归属隔离、写盘期间保留新输入 | 完整采用同一事件序规则 |
| 就地等待、在途与已保存反馈，普通成功不弹提示 | 直接采用，保存后不离开编辑现场 |
| 离开收口、浏览器恢复镜像、普通失败自动补试一次 | 采用同一原则，保留当前卡片身份与放弃待确认内容 |
| 非阻塞冲突条、四个出口、最新磁盘复检 | 采用交互原则，比较区按卡片字段组织 |
| 正文整段对齐、字级高亮、未改动段落折叠 | 只用于长正文或长说明字段；整个卡片不做全文原文双栏对照 |
| 卡片与正文变更的不同目录 | 接通三类卡片目录；通用反馈链对计划目录的早退不再被误当作已保护卡片 |

不把正文面板、全文差异组件或变更反馈逻辑整体复制到卡片。施工时应抽出已验证的通用编排，保持正文行为与既有测试不回归；卡片只提供领域快照、读写适配和字段比较。

## 三、统一编辑会话与保存编排

### 1. 一张卡片一个编辑会话

三个领域继续共用看板卡片基础设施，但将自动保存、状态选择、冲突和恢复纳入同一卡片编辑会话。每个会话按「项目 + 卡片稳定标识」隔离，至少记录：

- 最新人工输入、当前生效卡片、开始编辑时的内容版本；
- 最后一次选择的普通状态及其是否已生效；
- 待保存快照、写盘在途快照、编辑修订代次与最近成功写入版本；
- 已感知的外部版本、冲突状态、失败原因和恢复信息。

现有按项目与卡片暂存编辑现场的能力保留并扩展为可跨刷新恢复。卡片文件仍是权威内容，浏览器恢复区只承载尚未成功落盘的输入与待处理状态，不参与 AI 上下文，也不作为看板的第二事实来源。

### 2. 普通编辑与状态选择合并

- 名称、正文和计划字段输入实时进入当前卡片会话，并重置该卡片的 2000ms 计时。
- 点击普通状态按钮只登记待保存状态，不调用立即移动接口。连续点击时替换待选择状态，以最后一次为准。
- 到保存时机时，将当时的全部字段修改与最终状态作为一个完整更新提交。服务层以一次文件写入完成，避免正文已保存但状态失败造成半成功。
- 计划状态支持正文与状态合并更新；伏笔普通状态也进入同一更新，只有「放弃」改走原因确认流程。
- 点击已经生效且没有其他修改的状态不产生写入；点击等待中的同一状态保持等待，不重复排队。
- 待选择状态使用现有中性色体系中的点状等待标记和辅助说明，当前已生效按钮保持原选中样式；不新增第三套看板配色。
- 待保存期间看板卡片停留在原分组。保存成功并刷新真实数据后，才更新状态按钮、当前详情版本和看板位置。
- 保存期间继续输入或再次选择状态，新修订留待下一轮。前一次成功只能承认其携带的快照，不能清除或标存后续输入。
- 同一卡片的写盘串行，不同卡片互不阻塞；切卡后旧请求只可更新原会话和原看板数据，不得改变新详情现场。

### 3. 离开收口、失败与恢复

1. 切换卡片、分类或项目，关闭详情，切回预览，以及页面进入隐藏或离开流程时，立即请求该卡片收口；不等剩余两秒。
2. 浏览器无法保证关闭前异步写盘完成。存在未落盘内容、在途写入、失败、未处理冲突或未校验恢复记录时，保留离开提醒与恢复镜像；不得宣称已保存。
3. 普通写盘首次失败后，在当前等待窗口基础上追加 1000ms 自动重试一次；仍失败则持续显示原因和「重试」，不无限后台循环。新输入或手动重试才重新触发。
4. 无有效输入时不写盘。例如名称为空、伏笔读者视角为空，应保持等待/校验提示，不能先写入非法卡片再报错。
5. 打开卡片时按「恢复内容、保存基线、当前磁盘版本」核对：内容与磁盘一致则清除冗余镜像；磁盘与基线一致则续存并启动两秒去抖；磁盘已变化则回填人工内容并直接建立版本冲突。无法读取时保留内容并明确提示，不能静默当成已保存。
6. 已保存且无后续修改的会话可以清理恢复记录；切走再回来仍恢复编辑模式与真实内容，不要求用户重新寻找未保存草稿。
7. 普通成功不弹全局 Toast；状态区更新即可。真实错误保持到处理，切换卡片不能清掉原卡片的失败现场。

## 四、伏笔主动放弃

### 1. 从详情按钮进入

点击「放弃」不立即修改状态，而是进入卡片内的「放弃这条伏笔」操作态：

- 原来的读者视角、作者真相编辑区原位收起，显示原因输入区；顶部名称和结构信息保留，面板不跳页、不弹全局对话框。
- 原因区标题为「为什么不再回收这条伏笔？」，说明「记录创作决策，避免以后误以为漏写」。
- 输入框默认聚焦，填写本次原因；已有历史原因只在已放弃详情的信息区展示，不带入新的放弃操作；若作者控制权计划已落地，历史原因可以在高级信息中另行修订，但不能代替本次明确确认。
- 操作区固定提供「确认放弃」和「取消」。原因去除首尾空白后非空才允许确认，空内容不触发请求，也不显示后端错误。
- 进入放弃操作态不会把原状态改成已放弃，也不会产生两秒后自动执行的计时器。

### 2. 进入前后的保存规则

1. 如果当前卡片已有字段修改、普通状态等待或写盘在途，先请求原卡片收口，原因操作区可以立即显示，但「确认放弃」暂时禁用。
2. 已有在途写盘按原快照完成，不取消、不覆盖；期间新输入继续保留并进入后续保存。
3. 普通修改成功落盘后，以最新卡片版本进入放弃确认；若出现外部修改或冲突，先保留原因输入，待用户解决版本关系后再允许确认。
4. 普通保存失败时不允许绕过失败直接放弃，保留原因和全部编辑内容，提供重试或返回编辑。
5. 点击「确认放弃」后，以最新版本一次性提交「放弃状态 + 本次原因」。这次确认不再等待两秒；按钮显示进行中，禁止重复提交。
6. 只有写盘成功后，详情状态才切换为已放弃、看板才进入放弃分组，原因进入信息区；保留名称、读者视角、作者真相和关联信息。
7. 写盘失败或冲突时保持原状态，原因输入不得清空；成功响应属于旧项目或旧卡片时不得关闭当前现场。

### 3. 取消、离开与恢复

- 点击「取消」只退出原因填写态，回到先前编辑现场，不写放弃状态，不删除原有内容；已经输入但尚未确认的原因可以保留在当前卡片会话中，便于再次进入。
- 放弃等待期间切卡、切分类、切项目、关闭面板或刷新，都只能暂存原因和编辑现场，不能自动执行放弃。
- 恢复后仍显示待确认的原因操作态，由用户再次明确点击「确认放弃」。
- 已放弃卡片再选择其他普通状态时，沿用两秒延迟保存；历史放弃原因保留在卡片中，只有当前处于已放弃状态时才在状态字段区醒目展示。再次放弃时可登记新的原因。

### 4. 从看板拖入「已放弃」列

- 拖动过程中只显示现有落点，不提前改变真实状态。
- 松手时不直接写放弃状态，也不报「缺少原因」错误；保持原看板数据，打开该卡片详情的原因操作态，并暂存本次目标落点。
- 用户填写原因并确认后，一次性保存放弃状态、原因与目标列内位置；保存成功后按真实看板数据定位。
- 用户取消、关闭详情或切换现场，均不执行放弃；原因可以随会话保留，落点不单独写盘。
- 已处于已放弃状态的卡片在列内拖动仍走现有排序逻辑，不要求重复填写原因。
- 其他状态列的拖拽与排序维持现状，不强行改成两秒延迟。

### 5. 删除不是放弃

「删除（移入回收站）」继续使用现有两步确认和回收站语义，不纳入自动保存，不与放弃原因合并。放弃是保留创作决策记录，删除是移出当前工作区，两者不能互相替代。

## 五、AI 修改与版本冲突

### 1. 冲突发生时的行为

- 当前卡片没有未落盘修改且写盘已完成：可以更新展示基线与看板，不抢当前编辑模式。
- 当前卡片有待保存输入、在途写入或已存在冲突：冻结该卡片后续自动写入，保留最新输入、普通状态选择和编辑模式，读取外部版本并建立冲突。
- 旧写盘与外部修改交错时，每次结果只承认自身快照；以最新磁盘版本重定后续输入基线，不因旧成功晚到而解除冲突或继续覆盖。
- 顶部状态按钮仍保留已生效状态；尚未保存的普通状态选择随人工内容一起进入冲突处理，不能在冲突中直接落盘。
- 详情显示持续的琥珀色状态条：「这张卡片已被 AI 或外部编辑器更新，你的当前修改尚未落盘」，提供「比较并处理」。不自动展开完整比较，不自动切预览。
- 冲突按项目与卡片保存，切走、关闭详情或切换项目后保留入口。刷新后由恢复记录重新核对磁盘；若外部版本仍存在，应重建版本入口，而不是依赖刷新前内存状态自然复活。旧读取、旧写盘不得污染另一张卡片或另一项目的同标识卡片。
- 当前正在查看的卡片只有一个持续冲突条：首次进入冲突、AI 后续继续修改和磁盘快照刷新都不得重复叠加全局提示或普通变更通知。非当前卡片首次冲突可以有一次指路提示，后续修改保持静默；不得清除原始变更账本。
- 冲突期间可继续输入，自动写入保持冻结。冲突后的新修改进入最新人工快照，不因展开、收起或外部版本刷新而丢失。

### 2. 用户主动比较时

在现有详情内容区展开版本处理区，沿用正文自动保存计划的非阻塞比较与反馈层级，不新增全局冲突中心：

- 标题为「这张卡片有两个版本」；分别展示「你的当前内容（含尚未生效的状态选择）」和「磁盘上的最新版本」。
- 计划比较名称、正文与状态；伏笔比较名称、读者视角、作者真相与状态；节奏卡比较当前已开放的编辑字段及相应状态结果。若《伏笔与节奏卡作者字段控制权升级计划》已落地，比较范围必须包含其新增的高级信息、实际值、正文、人工判定来源和说明。
- 比较以打开处理区时的最新人工内容和刚重新读取的磁盘版本为准，不使用第一次冲突时的陈旧快照。
- 无人工改动的字段折叠，默认突出真正不同的字段与状态。短字段并排显示两个值；长正文字段使用正文已验证的单栏差异与局部高亮；不复制正文整块比较面板，也不做逐段自动合并或让 AI 代选版本。
- 尚未落盘的普通状态选择必须显示为「待生效选择」，不能画成已经生效；采用磁盘版本会同时放弃它，二次确认须明确这一后果。
- 采用任一版本后，名称、正文、状态按钮和结构字段都必须立即展示被采用的最新内容，不能在当前编辑框中残留已放弃的旧值。

### 3. 四个处理出口

| 操作 | 固定行为 |
| :-- | :-- |
| 返回继续编辑 | 收起比较，保留人工内容、待选择状态与冲突再入口，不写盘 |
| 将当前内容另存为副本 | 使用对应领域的新建能力保存完整人工快照；不自动删除原卡或解决原冲突 |
| 采用磁盘版本 | 二次确认；读取成功后才放弃对应人工内容与普通状态选择，读取失败不得清除 |
| 采用我的当前内容 | 二次确认；用最新人工快照整份更新原卡片，等待期间的新修改按新基线保留 |

放弃原因填写态遇到冲突时，先处理卡片版本关系，再返回原因确认；任何「采用磁盘版本」都不能在读取失败时顺带清除原因。采用操作不得绕开「放弃必须有原因」的领域规则。

### 4. AI 工具与人工编辑的职责

人工自动保存继续通过现有卡片服务和内容版本校验写入；AI 新建、修改、排序和放弃仍走现有 Agent 工具及权限确认。本计划不降低 AI 工具校验，也不让自动保存绕过确认。

人工先落盘、AI 随后基于旧读取修改时，由卡片工具自身的读后写或更新版本校验负责拦截；需要补对应事件序验收，但不能把未实现的「AI 自动重读」写成本计划附带能力。
