# 章节命名规范与整理工具计划

## 记录时间

2026-06-25

## 文档目的

本文档承接 [章节格式调整计划](章节格式调整计划.md) 里「章节命名规范」「旧项目批量整理工具」两条待补齐项，给出统一的命名格式定义、工具层强制策略、文案对齐方案，以及配套的旧项目整理工具设计。

目标是把章节命名从「靠 prompt 软约束、代码层零强制」收敛为「代码层强制 + Agent 自主编号 + 旧项目可一键整理」。

## 背景

[章节格式调整计划](章节格式调整计划.md) 已把章节正文格式从 `.md` 切到 `.txt`，但章节**文件名**一直没有统一规范。现状是纯靠 system prompt 文字约束，代码层零强制，并且代码内同时存在四套互相打架的命名示例：

| 出现位置 | 格式 |
|:---|:---|
| Agent system prompt `prompt.ts:56` | `chapters/第001章-标题.txt` |
| Agent 工具描述 `tools.ts:59` | `chapters/第001章.txt`（无标题） |
| 默认 system 模板 `defaults.ts:7` | `第001章 章节标题`（空格分隔） |
| 空名兜底 `project-fs.ts:477` | `chapter-YYYYMMDDHHMMSS.txt`（时间戳） |

带来的问题：

1. Agent 写章节时编号完全靠模型自己用 `FindFiles` 数，没有代码兜底，容易数错、跳号、重号。
2. 所有章节列表（文件树、`FindFiles`、前端章节面板）都按**文件名 `localeCompare` 排序**，命名不规范会导致顺序错乱（如 `第1章` / `第001章` / `chapter-1` 混用）。
3. 旧项目残留的 `.md` 章节和不规范命名的 `.txt` 章节没有批量整理入口，只能靠 Agent 逐个 `RenameFile`。

## 核心结论

### 命名格式

章节文件统一使用：

```txt
chapters/第NNN章-标题.txt
```

- 中文「第」+ 编号 + 「章」
- 编号**至少 3 位补零**（`第001章` ~ `第999章`），超过 999 章自然变 4 位（`第1000章`）
- 连字符 `-` 分隔标题
- 标题**必填**，不能为空
- 扩展名必须 `.txt`

规范正则：

```ts
/^第(\d{3,})章-(.+)\.txt$/
```

### 落地机制

采用「通用工具 + 格式校验 + 重号检测」，**不新增专用 `CreateChapter` 工具**：

- Agent 继续用通用 `CreateFile` / `EditFile` / `RenameFile`，自己确定章节编号。
- 工具层在**格式校验**（纯函数，无 fs）和**重号检测**（run 层，扫 `chapters/`）两层兜底。
- 命名不合规或重号时，工具直接拒绝，错误信息回灌模型让其调整。

理由：NovAI 的方向是 Claude Code 风格的「模型驱动 + 通用文件工具」。章节编号本质是创作决策（番外是否计入、是否插序章），交给 Agent 比交给工具自增更灵活；编号连续性靠重号检测兜住，足够可靠。

### EditFile 对称强制

`EditFile` 编辑 `chapters/` 下的文件时，**同样强制命名规范**（不只校验扩展名）。

这是有意为之的硬约束：它使「不规范章节完全不可编辑」，从而把「旧项目批量整理工具」从可选项提升为**强依赖**——必须先整理成规范名，才能正常编辑。这样保证：新写的章节必然规范，旧项目必须经过整理收敛，命名规范不会被「编辑路径放水」绕开。

## 与现有体系的关系

- `chapters/`：章节正文，统一 `第NNN章-标题.txt`，**受命名规范强制**。
- `elements/`：人物、地点、实体、剧情、时间线、世界观，继续使用 `.md`，**不受本章命名规范约束**。
- `prompts/`：提示词配置，继续使用 `.md`，不受约束。

命名规范只作用于 `chapters/` 目录。

## 对开发的影响

### 需要调整的部分

1. 工具层新增章节命名格式校验（纯函数层，无 fs）。
2. 写章节的工具（`CreateFile` / `RenameFile`）在 run 层加重号检测。
3. `EditFile` 对 `chapters/` 路径追加格式校验（对称强制）。
4. 代码内四处打架的命名文案统一为 `第NNN章-标题.txt`。
5. 新增旧项目章节整理 service 和预览确认 UI。

### 不需要调整的部分

- `elements/` 目录结构
- `prompts/` 提示词文件格式
- 项目配置文件格式
- RAG 索引与要素文件主结构
- 章节列表的排序逻辑（继续按文件名排序，命名规范落地后顺序自然正确）

## 实施计划

### Step 1：章节命名纯函数模块

新增 `packages/core/src/core/tools/chapter-name.ts`，作为章节命名的单一事实来源。

```ts
// 规范正则：第NNN章-标题.txt，NNN 至少 3 位
export const CHAPTER_NAME_PATTERN = /^第(\d{3,})章-(.+)\.txt$/
// 宽松编号提取（用于解析旧文件、重号检测，不要求整体规范）
export const CHAPTER_NUMBER_PATTERN = /第(\d+)章/

export function isChapterPath(path: string): boolean
export function parseChapterNumber(filename: string): number | null
export function isChapterNameCompliant(filename: string): boolean
export function assertChapterNameFormat(path: string): void  // 不合规抛清晰错误
export function formatChapterName(number: number, title: string): string  // padStart(3,'0')
export function suggestChapterTitle(content: string): string  // 正文首行/前 N 字兜底
```

独立成模块的原因：Step 5 的整理工具要复用 `parseChapterNumber` / `formatChapterName` / `suggestChapterTitle`，集中放这里避免循环依赖。

### Step 2：格式校验接入工具层

修改 `packages/core/src/core/tools/path.ts` 的 `assertWritableTextFilePath`：

```ts
export function assertWritableTextFilePath(path: string): void {
  assertTextFilePath(path)
  if (path.startsWith('chapters/') && !path.toLowerCase().endsWith('.txt')) {
    throw new Error('章节正文必须写入 chapters/*.txt；要素和提示词才使用 .md')
  }
  // 新增：chapters/ 下必须符合 第NNN章-标题.txt 规范
  if (path.startsWith('chapters/')) {
    assertChapterNameFormat(path)
  }
}
```

影响范围：所有走 `assertWritableTextFilePath` 的路径自动获得格式校验——`CreateFile`（`validateInput` 经 `normalizeTextFilePath`）、`RenameFile.toPath`（`validateInput` 经 `assertWritableDocumentPath` + run 层二次校验）。

`EditFile` 当前用宽松的 `assertTextFilePath`（允许 `.md`），需单独追加 chapters 格式校验，保留对非 chapters `.md` 文件的编辑能力。

### Step 3：重号检测接入写工具

重号检测需要读文件系统，放在工具的 `run` 层（`validateInput` 是纯函数无 fs 访问，架构上吻合）。

新增重号检测辅助函数（需 fs，放 `chapter-name.ts` 或同级新文件，实现时定）：

```ts
export async function collectChapterNumbers(
  handle: FileSystemDirectoryHandle,
  exceptPath?: string
): Promise<Set<number>>

export async function assertChapterNumberAvailable(
  handle: FileSystemDirectoryHandle,
  targetPath: string,
  exceptPath?: string
): Promise<void>
```

实现要点：列 `chapters/` 目录 → 逐文件 `parseChapterNumber` → 存 `Set`。**解析失败的旧文件跳过，不报错**，不污染编号集合。复用 `directory-tools.ts` 的 `resolveDirectoryHandle` 遍历模式。

接入点：

- `create-file.ts` 的 `run`：写入前调 `assertChapterNumberAvailable(handle, input.path)`。
- `rename-file.ts` 的 `run`：移动前调 `assertChapterNumberAvailable(handle, input.toPath, input.fromPath)`，`exceptPath` 传 `fromPath` 避免改名时把自身算成重号。
- `edit-file.ts`：**不做重号检测**（编辑不改编号），只校验格式。

### Step 4：统一代码内命名文案

把四处打架的格式统一为 `第NNN章-标题.txt`：

| 文件 | 现状 | 改成 |
|:---|:---|:---|
| `prompt.ts:56` | `第001章-标题.txt` | 已对齐，确认无改动 |
| `tools.ts:59` | `第001章.txt`（无标题） | `第001章-标题.txt` |
| `tools.ts:137,143` | CreateFile 描述 | 补充命名规范说明 |
| `tools.ts:168,178` | RenameFile 描述 | 补充 chapters 命名规范 |
| `defaults.ts:7` | `第001章 章节标题`（空格） | `第001章-章节标题`（连字符） |
| `project-fs.ts:477` 兜底 | `chapter-YYYYMMDDHHMMSS.txt` | 不再兜底非法名，抛错让调用方处理 |

system prompt 配套强化：明确教 Agent——写新章节前先 `FindFiles chapters/*.txt` 数现有章节，下一章编号 = 最大编号 + 1，补零 3 位，重号或格式不合规会被工具拒绝。

### Step 5：旧项目批量整理工具

#### core 层：整理 service

新增 `packages/core/src/services/chapter-organize-service.ts`（或挂到现有 file-service）：

```ts
export type ChapterOrganizeItem = {
  currentPath: string
  suggestedPath: string
  reason: 'format' | 'number' | 'extension'
  needsReview: boolean  // 缺标题、靠正文兜底的，标记需用户确认
}

export type ChapterOrganizePlan = {
  total: number
  items: ChapterOrganizeItem[]
}

export async function scanChaptersForOrganize(handle): Promise<ChapterOrganizePlan>
export async function applyChapterOrganize(handle, plan): Promise<RenameResult[]>
```

`scanChaptersForOrganize` 逻辑：逐文件判断——已规范跳过；能机械转换的给建议名（补零、换前缀、换扩展名）；缺标题的用 `suggestChapterTitle`（正文首行兜底）+ `needsReview: true`。

缺标题兜底策略：用正文首行（或前 N 字）作为建议标题。多数章节文件首行本就是标题行；即便不是，前若干字当临时标题也比占位强，且预览步骤让用户可改。

## 依赖关系

⚠️ **Step 1–4（规范强制）与 Step 5（整理工具）必须一起上线。**

Step 2 的 `EditFile` 对称强制一旦生效，旧项目里所有不规范章节立即变得「不能编辑」（只能先改名）。如果没有 Step 5 的整理工具，旧项目会被锁死。两块绑定发布，避免中间状态不可用。

## Agent 行为要求

规范落地后，Agent 在写章节时应遵守：

1. 写新章节前先用 `FindFiles chapters/*.txt` 盘点已写章节，确认下一个编号。
2. 新章节编号 = 现有最大编号 + 1，补零 3 位。
3. 文件名必须形如 `chapters/第NNN章-标题.txt`，标题非空。
4. 若工具返回「格式不合规」「编号已存在」错误，按错误提示调整编号或文件名后重试，不要反复尝试相同错误参数。
5. 章节正文保持纯文本，不使用 Markdown 结构符号。

## 验收标准

完成后应满足：

1. Agent 新建章节必须 `第NNN章-标题.txt`，格式不符被工具拒绝并回灌错误。
2. 同编号章节重号被拒绝；Agent 数错编号会被重号检测兜住。
3. `EditFile` 编辑 `chapters/` 下不规范文件被拒（对称强制）。
4. 代码内四处文案统一为 `第NNN章-标题.txt`，无打架。
5. ActivityBar「章节整理」可点开预览，列出所有需整理章节及建议名，缺标题项可编辑，确认后批量改名。
6. 旧 `.md` 章节可通过整理工具迁移为规范的 `第NNN章-标题.txt`。
7. 所有新增/改动有 Vitest 覆盖，`pnpm test` 全绿。
