# 写回面板文件聚合与计数口径修正计划

## 背景与问题

任务结束时的「本轮写回 N 个文件」面板（TurnChangesPanel）目前按**操作记录**逐条平铺，且行数统计算法错误，2026-09-22 用户在真实会话中抓到三类异常（代码级定位已完成）：

1. **行数统计是「净行数差」而非真实增删**：`edit-file.ts` 用 `countLines(newText) - countLines(oldText)` 算 linesAdded。一行换一行（真实一删一增）显示 `+0 −0`；替换+追加时删行被吞（真实有删行却显示 `+10 −0`）；linesAdded 无负数兜底，删多于增时渲染出 `+−2` 怪写法。展开的 diff 视图（DiffLines.vue）用的是 `diff` 包的真实 diffLines——两套算法各算各的，行数和展开内容必然对不上。标题行总数是净差累加，同样失真。
2. **同一文件出现多行**：面板逐条列操作记录（注释写明是故意设计），一轮内对同一文件的多次 EditFile 各占一行；标题文件数却按路径去重，出现「9 个文件列了 11 行」的观感冲突。
3. 新建文件的行数用 `countLines`，尾部换行会计出一个不存在的空行，与 DiffLines 渲染行数差一（`countLines("a\nb\n")=3`，渲染 2 行绿）。

## 目标形态（用户已拍板）

面板回答的问题是：**此次任务总共改了哪些文件，这些文件总共做了哪些修改**——一行一个文件，而不是平铺历史操作流水。

- 每行：净状态徽章（新建/修改/改名/删除）+ 路径 + 该文件本轮聚合 `+X −Y`。
- 展开：该文件本轮的**修改片段列表**（口径 A），按账本时间顺序逐段红绿 diff；多段修改标序号。
- 展开 diff 区**限高 30 行**，超出内部滚动。
- 标题行行为不变：最新轮展开文件列表、历史轮折叠成标题行。

## 方案

### Step 1（core）：计数口径统一为真实 diffLines

- `packages/core` 新增 `diff` 依赖（与 app 同主版本 `^9.0.0`），新增小工具 `diff-line-stats.ts`：`diffLines(oldText, newText)` 后按 part 统计增删行数（逐 part `.replace(/\n$/, '').split('\n')` 计数——与 DiffLines.vue 渲染同一算法同一边界处理，保证数字与展开视图永远一致）。
- `edit-file.ts`：output 的 linesAdded/linesRemoved 改用该工具（删掉净行数差公式与 Math.max 兜底——真实 diff 计数天然非负）；`create-file.ts`：linesAdded 同步改用（修掉尾部换行差一）。
- EditFileOutput/CreateFileOutput 类型字段不变（语义从「净差」修正为「真实增删」），`summarizeOutput` 不用这两个字段，无连锁改动。
- 删除/改名工具本就不产生 diff（无 extractChangeDiff），不在本期动。
- 测试（`file-tools.test.ts` 增补）：一行换一行 = +1 −1；替换+追加净增场景删行可见；删多于增不出现负 added；新建尾部换行不差一。

### Step 2（core/service）：change-summary 视图按文件聚合

- `services/types.ts`：change-summary 消息的 `changes: FileChangeRecordView[]` 替换为 `files: TurnFileChangeView[]`。`TurnFileChangeView` = `{ key, path, fromPath?, status: 'created'|'updated'|'renamed'|'deleted', linesAdded, linesRemoved, records: FileChangeRecordView[] }`——records 保留该文件本轮全部原始记录（面板展开渲染片段 diff 用），linesAdded/linesRemoved 为各片段按 oldText/newText 实时重算之和（不按记录里存的值求和，历史账本旧口径数字自愈；无 diff 的记录贡献 0）。
- `agent-service.ts`：聚合函数 `collectTurnFileChanges(records)`（纯函数，可单测），change-summary 分支改调它。聚合规则：
  - 按账本顺序扫记录，维护「当前路径 → 组」映射；遇 renamed 且 fromPath 有组，整组迁到 toPath（改名前后的内容修改归同一文件）。
  - 净状态：末次内容操作为 deleted → `deleted`；首次为 created（无论中间是否改名）→ `created`；含 renamed → `renamed`；其余 → `updated`。
  - created 后又被 deleted：呈现为一个 `deleted` 行（**施工中修订**，原方案为整组丢弃——丢弃会让该轮面板降级成「本轮改动记录缺失」，把净零轮误导为数据异常；完整经过留在 records 可溯源）。
- view 层形状是内存结构（持久化消息只存 runId，每次从账本重新解析），改形状无迁移问题。app 侧消费方仅 TurnChangesPanel 与一处测试 fixture。
- `RunAgentTurnResult.turnChanges` 保持原始流水不动（app 无消费方，属 service API 返回；聚合是展示关注）。
- 测试（`agent-service.change-ledger.test.ts` 增补）：同文件多笔聚一行；改名前后归并；created→deleted 丢弃；删除行无 diff 不计行数；聚合行数 = 片段行之和。

### Step 3（app）：面板聚合渲染 + 限高

- `TurnChangesPanel.vue` 改为渲染 `message.files`：删去 fileCount computed（行数即文件数）；每行渲染净状态徽章（复用现有 changeLabels）+ 路径（renamed 显示 fromPath → toPath，deleted 带「（已删除）」）+ 聚合 `+X −Y`；无 records 可展开的行（纯删除/纯改名）不响应点击。
- 展开区：该文件 records 中所有带 diff 的记录按序渲染，多段时标「第 N 处修改」；diff 容器加 `max-height: 30em`（30 行 × 行高 20px≈30em 口径实现时以行高换算为准，目标 30 行可视）+ `overflow-y: auto`。
- 标题行总数改为对 `files` 求和（数据同源，不再与逐行口径分裂）。
- `chat-render.test.ts` 的 change-summary fixture 同步改 `files: []`。

## 已拍死的取舍（用户已确认）

1. **口径 A（文件聚合 + 片段列表）**，不做整文件轮级 diff（口径 B：首改前全文 vs 末改后全文）。理由：片段是实际写入内容、信息真实；整文件快照会显著增大随会话落盘的账本体积。
2. **diff 展开区限高 30 行**，超出内部滚动；后续体验不适再调。
3. **聚合放 service 层**（toChatMessageView 的 change-summary 分支），前端只渲染；账本结构与消息持久化格式不动。
4. **计数算法与 DiffLines 渲染同源**（同一个 diffLines + 同一行数边界处理），行数与展开视图一致性强约束。

## 迁移条款

无迁移。账本（changeLedger）结构与 change-summary 持久化消息（只存 runId/aborted）均不变；旧会话重载后按新聚合逻辑重新解析账本，历史轮面板自动变为聚合形态。

## 明确不做清单

- 不做整文件轮级 diff（口径 B）及任何文件内容快照落盘。
- 不动 `GetFileChangeHistory`（AI 视角保持操作流水）。
- 不动 `file-changed` 实时广播（按记录流式走，供文件树/打开文件刷新，与面板无关）。
- 不动删除/改名工具的行数统计（删除行数不进面板总计，维持现状）。
- 不做撤销按钮（账本 diff 已为此预留，另立计划时再议）。

## 新旧机制替代表

| 旧机制 | 去向 |
| :--- | :--- |
| 面板逐条平铺操作记录 | **替换**为按文件聚合渲染（Step 3） |
| `change-summary` view 的 `changes: FileChangeRecordView[]` | **替换**为 `files: TurnFileChangeView[]`（Step 2） |
| edit-file 净行数差公式 / create-file countLines | **替换**为 diffLines 真实增删（Step 1） |
| TurnChangesPanel 的 fileCount computed | **删除**（聚合后行数即文件数） |
