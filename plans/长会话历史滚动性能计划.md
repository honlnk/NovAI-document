# 长会话历史滚动性能计划

## 背景与问题

对话历史变长后，聊天区滚动（尤其是流式输出期间向上翻阅）会卡顿。调查结论（2026-09-22，代码级确认）：

1. **无分页无虚拟滚动**：`ChatPanel.vue` 用扁平 `v-for` 把 `renderItems` 全量铺进 DOM；折叠的过程组用 `v-show`（`display:none`）只隐藏不卸载，DOM 节点随历史无界增长。
2. **流式期间每 token 整篇重渲**：`MarkdownRenderer.vue` 的 `v-html` 绑定整篇渲染结果，流式消息每来一个 delta 就把累积全文重新 `md.render` 并重建整棵 DOM 子树（O(L²) 体感）；同时 store 每个 delta 对 messages 全数组 `find`+`map` 重建（O(n)），`buildRenderItems` 随之全量重跑。
3. **每条 assistant 消息各建一个 MarkdownIt 实例**：`new MarkdownIt` 写在 `<script setup>` 顶层，N 条消息 = N 个解析器实例，纯内存浪费。
4. **会话全量装载**：`selectSession` → `getAgentSession` 一次性返回全量 messages view；change-summary 的 diff 片段全文随账本常驻。

dsh（参考项目）的主聊天界面不用虚拟滚动，靠「历史分页窗口」把 DOM 规模钉死在常量级（尾页 50 条 + 滚动 prepend 旧页），辅以增量 markdown（冻结前缀只重渲尾部）、视口激活高亮、`hidden="until-found"` 可搜索折叠。本计划按同一防线选择借鉴：**分页窗口治本，渲染优化降单价，不引入虚拟滚动**。

## 方案

### Step 1（core）：会话历史分页读取 API

- `services/types.ts`：`ChatSessionView` 增加可选 `historyStart?: number`——窗口首条消息在全量数组的下标；缺省/0 表示已是全部。hasMore 由 `historyStart > 0` 推导，不加冗余字段。
- `agent-service.ts`：
  - `getSession(projectId, sessionId?, options?: { tailMessages?: number })`：不传参行为不变（全量，向后兼容）；传参时 `toChatSessionView` 取尾部切片并带 `historyStart`。
  - 新增 `loadOlderMessages(projectId, sessionId, { before, count })`：`before` 为当前窗口起点（数组下标游标，messages append-only 故稳定），返回 `[max(0,before-count), before)` 切片视图与新起点 `start`；`before` 钳制到 `[0, len]`；窗口内 change-summary 照常从完整账本解析 changes；会话不存在返回 null。
- 测试 `agent-service.history-window.test.ts`：复用 session-store.test.ts 的内存 FileSystemDirectoryHandle 基建。

### Step 2（app store）：聊天历史窗口状态

- `chat.ts` 新增 `HISTORY_PAGE_SIZE = 100`（导出）、`historyStart` ref、`loadingOlder` ref、`hasMoreHistory` computed（`historyStart > 0`）。
- `selectSession` 改调 `getAgentSession(projectId, sessionId, { tailMessages: HISTORY_PAGE_SIZE })` 并记录 `historyStart`。
- 新增 `loadOlderHistory()`：守卫（无更多/加载中/无会话直接返回）→ service 取旧页 → messages 头部 prepend（不可变数组）→ 更新 `historyStart`；失败 setRunStatus 报错。
- `run-finish` 分支兼容：`messages = full.messages.slice(historyStart)`，窗口起点不动、尾部以权威全量为准；`message`/`message-delta` 尾部追加天然兼容。
- `chat.test.ts` 的 agent-service mock 工厂补 `loadOlderMessages`；新增窗口装载 / prepend 顺序与防重入 / run-finish 窗口保持 / delta 追加不受影响四组断言。

### Step 3（app UI）：滚动到顶自动加载 + 位置锚定

- 消息容器 `@scroll`：`scrollTop < 200 && hasMoreHistory && !loadingOlder` 时触发 `loadOlderHistory()`；朴素 handler + loadingOlder 防重入，不引入节流采样。
- 锚定用 scrollHeight 差值法：触发前记录 `scrollHeight/scrollTop`，prepend 落地后 `nextTick` 里 `scrollTop += 新scrollHeight - 旧scrollHeight`。
- 现有 `watch(messages.length → scrollToBottom)` 无法区分 append 与 prepend：加 UI 本地 `isPrepending` 标志，prepend 期间跳过吸底。
- 顶部仅 `loadingOlder` 时显示「正在加载更早消息…」行；无更多历史时不显示任何入口。

### Step 4（app 渲染层）：Markdown 共享单例 + 块级渲染

- 新增 `utils/markdown.ts`：模块级共享 MarkdownIt 单例（配置与现状一致：`html:false, linkify, typographer`），导出 `renderMarkdown(text)`。
- 新增 `utils/markdown-blocks.ts`（纯函数，node 可测）：`parseMarkdownBlocks(src): { key: number; html: string }[]`——`md.parse` 整篇（env 保留，reference link 定义不丢）后按 level-0 块边界分组 token 流，逐块 `renderer.render`；key 取块起始行号（`map[0]`，流式追加时稳定，Vue 按 key reconcile 而非重建）。
- `MarkdownRenderer.vue` 改造：改用共享实例 + 统一块级渲染（`v-for` 块 + `v-html`）。streaming/settled 同一路径——流式时 prefix 块 DOM 复用，仅尾部块 innerHTML 更新，消除每 token 整棵子树重建；settled 一次渲染无回归。新增 `streaming?: boolean` prop 透传。
- `MessageItem.vue` 把已有 `streaming` prop 传给 `MarkdownRenderer`。
- 已知偏差：流式中跨块 reference-style link 可能短暂按字面渲染，settled 自愈（与 dsh 相同）；每帧仍全量 parse（纯 JS，数千字亚毫秒），本期不做 HTML 缓存。
- CSS 兼容：`.markdown-body` 全是后代选择器，块包裹 div 不影响命中（施工时目验代码块/表格/引用样式）。
- 测试（node 可跑）：切块边界（标题/段落/列表/fence 混合）、未闭合 fence 归尾块、块拼接与整篇 render 等价抽样、空文本边界。

### Step 5（app UI）：折叠组 until-found

- `TurnProcessGroup.vue` 折叠容器 `v-show` 改为 `:hidden="group.collapsed ? 'until-found' : undefined"` + `@beforematch` 监听（命中时 emit toggle 自动展开）；组件注释同步更新（删去「Ctrl+F 搜不到」旧口径）。

### 已拍死的取舍（用户已确认）

1. **范围：全套**——core 分页窗口 + 前端渲染优化一起做，不止做渲染层。
2. **窗口 100 条/页**：首屏尾部 100 条、每次向前 100 条（dsh 是 50；NovAI 一轮任务产生多条工具行，50 可能不足两轮，取 100）。
3. **折叠组采纳 until-found**：反转既有注释写明的「Ctrl+F 搜不到折叠内容」行为——折叠过程消息变为可搜索、命中自动展开；Safari <17.4 退化为普通 hidden（与现状一致，无回归）。
4. **滚动到顶自动加载**（距顶 200px 内触发），不做常驻手动按钮。

## 迁移条款

无持久化数据 / 配置 / 文件格式变化：分页游标复用 append-only 的 messages 数组下标，不加 seq 字段，旧会话 JSON 完全兼容；view 类型仅加可选字段，不传参的旧调用行为不变。

## 新旧机制替代表

| 旧机制 | 去向 |
| :--- | :--- |
| `getSession` 全量返回 | 保留（默认行为不变），新增 `tailMessages` 窗口参数；`selectSession` 改用窗口 |
| 前端 messages 全量驻留渲染 | 替换为尾部 100 条窗口 + 滚动 prepend |
| MarkdownRenderer 每实例 `new MarkdownIt` | 替换为 `utils/markdown.ts` 模块级共享单例 |
| MarkdownRenderer 整篇 `v-html` | 替换为共享实例 + 块级 `v-for` 渲染（streaming/settled 统一路径） |
| TurnProcessGroup `v-show`（Ctrl+F 不可搜） | 替换为 `hidden="until-found"` + beforematch 自动展开 |
| ChatPanel `watch(messages.length)` 无脑吸底 | 修改：prepend 期间经 `isPrepending` 标志跳过 |

## 明确不做清单

- 虚拟滚动（@tanstack/vue-virtual 等）：窗口化后 DOM 有界，dsh 主聊天也不用；不引入新依赖。
- `content-visibility: auto`：窗口化后收益小，有滚动条抖动副作用。
- store 每 delta O(n) 数组重建优化：窗口化后 n≤300，成本可忽略。
- 改动账本 diff 全文内存驻留 / 会话 JSON 整读整写：存储层分片是大工程，暂缓。
- dsh 式增量 parse（冻结前缀连解析都省）：本期只做块级 DOM 复用，parse 仍每帧全量（纯 JS 便宜）。
- 代码语法高亮与视口激活：NovAI 未配高亮，无此成本，不预埋。
- 轮次跳转导航（dsh loadThrough / TurnNavigator）：无对应产品入口。

## 验收点

1. 【自动化】core：`getSession(tailMessages:100)` 返回尾部切片且 `historyStart` 正确；`loadOlderMessages` 边界（before=0 空切片、before 超长钳制、窗口内 change-summary 的 changes 完整解析）。
2. 【自动化】store：selectSession 后 `messages.length ≤ 100` 且 `hasMoreHistory` 正确；`loadOlderHistory` prepend 后顺序正确、防重入；`run-finish` 全量覆盖后窗口保持不冲掉。
3. 【自动化】markdown-blocks：切块边界 / 未闭合 fence / 拼接等价性 / 空输入。
4. 【自动化】全量门禁：`pnpm test` + `pnpm typecheck`（+ app 的 vue-tsc，若根命令未覆盖）全绿。
5. 【手动降级】造 ≥300 条消息的测试会话（往 `.novel/sessions/*.json` 灌假消息）：打开只渲染尾部 100 条，滚动到顶自动加载，位置不跳，直至无更多入口消失。
6. 【手动降级】长回答流式期间向上滚动历史，无明显卡顿（对照改造前体感）。
7. 【手动降级】Ctrl+F 搜索折叠组内的工具名/过程文本，命中并自动展开（Chrome）；ContentPanel 文件预览 markdown 样式无回归。
8. 【手动降级】`pnpm dev` 全流程冒烟：发送 → 工具行 → 折叠组 → change-summary 面板 → diff 展开，无渲染异常。
