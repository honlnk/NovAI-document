# 要素模块缺陷补全计划

## 记录时间

2026-09-23

## 背景与定位

本计划是《Element 要素体系优化计划》剩余工作的拆分。原计划未完成的六大块里，凡涉及「Agent 主动编写要素文件」的——双轨收敛（专用写入工具 / CreateFile 拦截）、写入合并策略、Agent 行为约束、「整理要素结构」指令——由用户拍板**整体暂缓**：这套「让 Agent 主动编写要素」的方案本身有待重新评估，不在本轮范围。

本轮只做不依赖该方案、且能立刻提升要素数据质量的缺陷补全：**五类要素模板落地 + 提取管道（/提取要素 流程）prompt 升级**。

## 已拍板决策（2026-09-23 与用户确认）

1. **双轨收敛：不做。** Agent 写要素的通道问题（专用工具 vs prompt 约束）随「Agent 编写要素」方案整体暂缓，CreateFile/EditFile 维持现状不拦截。
2. **同名要素写入合并策略：不做。** `/提取要素` 流的覆盖写维持现状（含 frontmatter relatedChapters 被新值覆盖的已知行为），合并能力随上述方案一并再议。
3. **剧情块 / 时间线编号方案：不做。** 文件名维持 name slug，不引入 `plot-NNN-` / `timeline-NN-` 编号；时间线按阶段归并为单文件依赖合并能力，同步暂缓。
4. **近名 / 模糊去重：不做。** 维持 type+name 精确匹配，近名重复文件本期接受。

## 本期范围

### 做

#### 1. 五类要素默认模板落地（core 资产）

新增 `packages/core/src/core/elements/templates.ts`，以常量承载五类要素的 body 模板骨架。worldbuilding 不出模板（抽象规则不适合固定骨架，与原计划一致）。模板只约束 body 结构；frontmatter 仍由 writer 生成，schema 不变。

五个模板骨架定稿如下（施工时以本节文本为准）：

**character**

```md
## 基本信息
- **首次登场**：第XXX章
- **年龄阶段**：待补充
- **当前状态**：待补充

## 简介
- 一到三句话说明人物是谁、在故事中的定位。

## 称呼规则
- 不同人物对其的称呼、自称、尊称或蔑称。

## 外貌与性格
- 外貌特征、性格特点、口癖等生成约束相关信息。

## 人物关系
- 与关键人物的关系及其变化。

## 行为边界
- 该人物不会做或一定会做的事，动机与底线。

## 相关剧情
- 参与的关键剧情块与章节。

## 状态变化
- 按章节记录成长、受伤、立场转变等变化。
```

**location**

```md
## 基本信息
- **首次出现**：第XXX章
- **当前状态**：待补充

## 简介
- 一到三句话说明地点是什么、在故事中的作用。

## 空间位置
- 所属区域、方位、地形。

## 可见性与可达性
- 从哪些地点可以看到或到达，通行条件与限制。

## 地点关系
- 与其他地点的距离、隶属、连通关系。

## 相关剧情
- 在此发生的关键剧情块与章节。

## 状态变化
- 按章节记录损毁、改建、易主等变化。
```

**entity**（沿用《Element 要素体系优化计划》已给出的八节草稿）

```md
## 基本信息
- **类型**：武器 / 武功 / 坐骑 / 丹药 / 信物 / 法器 / 书籍 / 其他
- **首次出现**：第XXX章
- **当前状态**：待补充

## 简介
- 用一到三句话说明该实体是什么，以及它在故事中的基本作用。

## 外观或表现
- 武器、物品、坐骑记录外观、材质、颜色、特征；武功、秘术记录施展效果、气势、招式表现。

## 来历
- 记录来源、制造者、传承、获得方式或背后故事。

## 当前归属
- **持有者 / 使用者**：待补充
- **相关人物**：待补充
- **相关地点**：待补充

## 能力或用途
- 记录功能、效果、限制、代价、使用条件。

## 剧情关联
- 记录相关剧情块、章节和伏笔。

## 状态变化
- 按章节记录获得、转移、损坏、失去、升级、封印等变化。
```

**plot**

```md
## 基本信息
- **所属章节**：第XXX章
- **剧情类型**：主线 / 支线 / 暗线 / 日常 / 战斗 / 其他

## 核心事件
- 一句话概括本事件。

## 关键细节
- 事件经过中不可省略的事实与转折。

## 登场人物
- 参与人物及其在本事件中的行动。

## 情感落点
- 本事件的情绪收束与人物感受。

## 暗线铺垫
- 埋下的伏笔、暗示、未解之谜。

## 关联要素
- 涉及的人物、地点、实体、时间线阶段。
```

**timeline**（按事件节点一文件；阶段以字段承载，为将来阶段归并留数据）

```md
## 基本信息
- **故事内时间**：待补充（可用架空朝代或年号）
- **所属阶段**：待补充（如：缘起 / 幼年 / 收徒）
- **相关章节**：第XXX章

## 事件经过
- 按故事内时间顺序记录事件本身。

## 涉及要素
- 相关人物、地点、实体。

## 后续影响
- 对后续剧情与时间线的影响。
```

#### 2. 提取 prompt 升级（extractor-llm.ts）

`buildExtractionSystemPrompt` 升级四点：

- **模板注入**：按类型把对应模板节结构写进 system prompt，要求每个 item 的 body 严格按模板分节输出，无内容的节填「待补充」。
- **plots 事件粒度**：明确要求一个独立事件一个 item，禁止「本章剧情」「总纲」式笼统条目。
- **timeline 阶段字段**：每项必须给出「所属阶段」（如 缘起 / 幼年 / 收徒）与故事内时间，落在 body 模板字段里。
- **tags 字段**：输出 JSON schema 增加可选 `tags` 数组，模型每项可给 2~5 个概括性标签（不含类型名本身）。

#### 3. 解析层适配（extractor-llm.ts）

`toExtractionItem` 读取模型产出的 `tags`：仅接受 string 数组，逐项 trim、去空、去重，与兜底标记 `['AI 提取', 类型中文名]` 合并；字段缺失或非法时回退现状（仅兜底两枚）。其余字段解析逻辑不变。

### 不做（本期明确排除）

- Agent 主动编写要素文件的一切：专用写入工具、CreateFile 对 `elements/` 的拦截、Agent prompt 的要素行为约束（先查重再写、改章后同步提示、拆分规则进 prompt）
- 「整理要素结构」Agent 指令（原 F 组）
- 同名要素写入合并策略（覆盖写维持现状）与 frontmatter 历史并集
- plot / timeline 文件名编号；时间线按阶段归并为单文件
- 近名 / 模糊去重
- 要素级确认预览（斜杠命令流已有预览确认；Agent 侧随方案暂缓）
- worldbuilding 模板
- 要素关系图谱、要素整理 UI、旧项目自动迁移

## 迁移条款

- 无持久化格式变更：frontmatter schema 不变，仅 tags 内容变长；旧要素文件不迁移、不改动。
- 旧文件再次被提取覆盖时自然升级为模板化 body（覆盖写维持现状，这是本期接受的口径）。
- 模板常量为纯新增，无旧代码删除。

## 新旧机制替代表

| 机制 | 去向 |
| :-- | :-- |
| 提取 system prompt 文案 | **替换**：模板注入 + 事件粒度 + 阶段字段 + tags 要求 |
| `toExtractionItem` 的 tags 硬编码两枚 | **替换**：模型产出 + 兜底合并 |
| writer.ts / parser.ts | 不动 |
| 五类模板 | 纯新增，无旧机制被替代 |

## 验收点

1. `templates.ts` 单测：五类模板齐备；worldbuilding 无模板；每个模板含必备节（基本信息 + 状态变化或对应收尾节）。
2. 提取 prompt 构建单测：prompt 含五类模板节名、「按事件拆分」要求、tags 字段说明。
3. 解析单测：带合法 tags / tags 缺失 / tags 非法（非数组、非字符串成员、重复、空白）的容错与合并去重。
4. 现有 elements / extractor 测试不回归；`pnpm test` 全绿 + `pnpm typecheck` 干净。
5. 真实 LLM 提取效果：本期降级为 mock 结构验证（项目惯例）；真实提取质量由用户在日常使用中复核。
