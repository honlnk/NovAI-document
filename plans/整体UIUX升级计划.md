# 整体 UI/UX 升级计划

## 文档状态

- 记录日期：2026-11-07。
- 当前状态：**调研与设计完成，待用户确认后开工**。
- 本计划取代[《UI/UX 体验升级计划》](../archive/UIUX体验升级计划.md)。旧方案已在分支 `honlnk/uiux-upgrade` 实施一轮，但效果未被采纳、未合并；其未采纳的界面不进入本分支。
- 本文只批准设计与验收标准，不批准共享文件修改、代码提交或推送。实际施工按阶段推进，每阶段必须测试、类型检查、文档同步和真实浏览器验收全绿后才算完成。

## 一、这次要解决什么

NovAI 已有完整的智能体内核和本地文件工作流，但界面仍像“把各项能力依次装上去”：内部能力名称占据主要位置，视觉语言不统一，稿件只是普通文件预览，内容确认与正文现场分离。用户需要的是一个**安静、精致、以小说稿件为中心的智能创作工作台**，而不是更密集的工具面板。

本轮同时解决两个层面，不能只改颜色，也不能只修用户点出的几个位置：

1. **全产品体验**：首页、导航、对话、章节、要素、提示词、计划、设置、索引管理和窄屏具有一致的排版、控件、状态与文案层级。
2. **稿件现场协作**：内容创建和编辑在稿件中审阅；自动修改后定位、显示红绿差异并淡出；字数、草稿、保存和冲突都可理解。其他提问与结构操作采用 DeepSeek Harness 的紧凑底部交互。

成功标准不是“组件换过样式”，而是：首次进入时知道如何开始；写作时稿件比系统术语更显眼；AI 改稿时看得懂、能审阅、不会丢自己的内容；离开再回来时仍能恢复现场。

## 二、调研依据与边界

### 已完成的验证

- 在 2026-11-07 通过隔离项目副本检查了 1280 像素桌面工作区、真实章节、设置实际状态和 900 像素窄桌面稿件抽屉；同时检查了空首页、计划板空状态与现有聊天、确认、列表、计划组件。
- 复盘了 `honlnk/uiux-upgrade` 的五个提交：它包含视觉降噪、差异、草稿和键盘等大量改动，但主方向仍是局部修补，未解决整体设计与稿件现场协作，不能回滚后当作本轮成果。
- 确认现有变更账本保存实际修改片段，却没有每处修改的可靠坐标和文件版本；新建、编辑、重命名、删除的确认视图也不相同。精准定位必须由服务层补充，不能靠界面搜索一段文字猜测。
- 对照了 DeepSeek Harness 的非编辑审批和提问实现：可复用的是紧凑输入区、明确一次性操作、局部错误、草稿隔离和防重复提交，不是它的技术架构或所有功能。
- 真实单行键盘发送后，本次环境未复现额外空行。它仍是确定要修的问题，但根因尚未确诊，禁止直接声称是编辑器默认回车竞争。

### 尚未获得的证据

- 旧分支的最终验收提交在文档子模块中不可用，未把其验收内容当作事实。
- 本轮没有观察到运行中的真实写入确认、主动提问、流式回复和有卡片的计划板；这些状态采用源码证据设计，施工时必须用真实或受控可重复场景补齐视觉验收。
- 中文输入法、屏幕阅读器和多行发送后的残行没有完成真人验证。

## 三、确定的设计方向

### 1. 视觉语言：安静的工具，清晰的稿件

采用**暖中性工作台 + 纸白稿件 + 单一墨色主操作 + 低饱和蓝灰辅助强调**。不沿用大面积纯黑导航、灰底正文卡片和到处出现蓝色的组合，也不增加渐变背景、装饰插画或彩色标签墙。

| 设计层 | 固定规范 |
| :-- | :-- |
| 工作台 | 中性略暖的页面底色，导航与内容区以留白和细分隔线分区；深色只用于文字和主操作，不再占据整块侧栏 |
| 稿件 | 纸白背景，正文不使用灰底仓库卡片；没有额外的多层边框和阴影 |
| 强调 | 蓝灰用于链接、当前焦点和少量智能体状态，不与绿增红减、红色危险操作竞争 |
| 字体 | 界面使用系统无衬线中文栈；小说正文使用舒适的系统中文阅读栈，16px 起步、行高 1.85；源代码与路径才用等宽字体 |
| 尺度 | 统一 4px 间距基线；正文每行约 28–38 个汉字；图标采用统一线性风格，主要点击目标不小于 32px，触屏目标不小于 40px |
| 边框与阴影 | 边框用于结构，阴影仅用于浮层；去掉正文容器和每个小工具的卡片化包装 |
| 状态 | 绿增红减只服务差异；红色还用于错误与危险操作；警告用细提示条，不再整卡染黄；状态都有文字或图标，不依赖颜色单独表达 |
| 动效 | 常规反馈 120–200ms，稿件高亮按本计划时序执行；尊重减少动态效果偏好，不能反复闪烁或自动滚动打断阅读 |

### 2. 工作区结构：保留熟悉的工作流，重新分配主次

保留分类导航、中央对话或计划区、右侧稿件及底部状态概念，但重新设计它们：

- 导航改为浅色、克制的项目工作台导航。主分类为对话、章节、要素、提示词、计划；“管理要素”归入要素区，“向量索引”固定归入设置的“智能辅助”组，原导航入口移除，状态栏保留索引状态和进入管理的入口。校对、章节整理、版本管理的不可用占位入口移出主导航，不实现这些功能，也不反复提醒“即将推出”。设置和返回首页保持可达。
- 中央区保留对话、工具和队列，不让长正文淹没对话。标题栏只保留与当前工作有关的信息，不重复展示通用产品口号和无关入口。
- 稿件区成为真正的“稿件工作面”，支持阅读、编辑和待审阅状态；不再仅显示文件路径和时间。计划详情仍使用同一位置，但不进入小说章节的差异模式。
- 桌面默认稿件宽度提升到约 480px，可在约 360–720px 调整；提供更宽的专注阅读状态。实际可用宽度不足时以抽屉承载，不挤压聊天和正文到不可读。保存用户主动调整的宽度，不因一次 AI 修改永久改变偏好。
- 窄屏一次只呈现一个主要工作面，稿件抽屉底部操作固定可达，返回后恢复对话、滚动位置和未提交草稿。

### 3. 创作对话：控制面，不是内核参数面板

- 空对话提供少量、可编辑的任务起点，并说明当前章节或大纲条件；点击只填草稿，不自动发送。
- 普通输入保留完整 Lexical 能力：引用、命令、大纲、补全、排队、插话、历史与失败恢复。Enter 发送，Shift+Enter 换行，Ctrl/Cmd+Enter 插话，输入法组字时不抢键。
- 权限和思考强度保留在输入区附近，不能埋入设置深处；以简短中文说明“可自动修改哪些内容”和“思考强度”，当前值可见。窄屏收进相邻的工具菜单，发送与停止始终可见。
- 用户消息与 AI 回复有清晰层级；思考、工具过程和变更摘要是可展开的辅助信息。完成摘要、确认请求和写回高亮不重复争抢注意力。
- 选中正文后明确点击“引用到对话”，不再鼠标松开即生成引用。引用保留来源，切换稿件后不会出现错误归属。

### 4. 非编辑请求：采用 DeepSeek Harness 的紧凑底部交互

用户提问、重命名、删除等结构操作**接管原聊天输入卡片的位置**，与 DeepSeek Harness 的 composer takeover 保持一致，不再另叠一张消息流大卡。普通编辑器保持挂载但暂时隐藏，草稿不丢；队列与运行状态在接管面板上方保留，停止和会话切换始终可用。采用中性面板、细分隔线、内部滚动和固定底部操作，不使用大面积黄色或蓝色卡片。

| 请求 | 界面与操作 |
| :-- | :-- |
| 主动提问 | 展示问题、轻量选项和独立补充说明；单选、多选与文本可并存。Enter 提交，Shift+Enter 换行。保留“跳过”与其后果说明 |
| 重命名 | 显示原名、目标名和影响的文件；允许一次、拒绝。长路径可换行，不用横向代码条挤压 |
| 删除 | 明确文件将移入项目回收站还是永久删除；主操作文案对应实际后果。危险操作用红色，不伪装成普通允许 |
| 多项请求 | 每个会话保持顺序，展示第几项与总数，逐项处理；不提供“一键全部允许”绕过审阅 |
| 提交中/失败 | 按请求标识锁定操作，防重复；失败在当前面板解释并保留选择，成功后才能清除草稿 |

普通聊天输入不再隐式把 Ctrl/Cmd+Enter 变成提问答案。提问草稿按会话和问题隔离，普通草稿按会话保存；切会话不串答案，新请求不清空旧输入。已结束的问题在消息流中保留只读记录，当前请求可从记录回到协作座位。

## 四、稿件现场协作：本轮核心

### 1. 稿件阅读与字数

稿件头部展示可读章节名，次级信息为“已保存 / 未保存 / 正在保存 / 保存失败”和字数。文件路径、格式、更新时间收进详情或提示，不与正文抢注意力。

- 字数显示为“正文 1,234 字”。统计当前阅读版本，包括未保存草稿，并随内容更新。
- 对 `.txt` 章节：只有首行匹配“第 + 编号 + 章 + 空白 + 标题”的既有章节标题约定时才排除该行；其他旧章节首行视为正文，空文件为 0。正文统计非空白字符数量，包含标点；说明采用“字符数”口径，不宣称等同出版行业字数。
- 对 Markdown 正文：使用解析后的纯文本统计非空白字符，标记、链接地址、元信息头与代码语言标记不计入；正文普通文字和实际代码内容计入。文件格式不适配正文阅读时显示“字符数”，不伪称章节字数。
- 保留预览和纯文本手工编辑，不引入正文富文本编辑器或自动保存。保存必须等待真实写盘；失败保留草稿、编辑位置和可重试提示。

### 2. 内容创建与编辑：直接在稿件中审阅

新建文件、修改正文都属于内容审阅，统一进入右侧稿件工作面。重命名和删除不属于此类，使用上一节的紧凑确认。

收到当前会话的内容确认时，先按“稿件工作面的现场仲裁”决定是否自动展示；获准展示后：

1. 展开稿件工作面并打开目标文件；桌面保留对话，窄屏打开稿件抽屉。用户正在编辑、有未保存草稿或位于计划等非稿件表面时，不执行自动展开，只保留待审阅入口。
2. 顶部说明是谁请求、修改哪个文件、当前第几项；底部固定提供“同意写入”和“拒绝”。拒绝后保留只读记录，不写文件。
3. 修改以全文中的局部差异呈现：新内容绿色、被替换或删除的原文红色，提供足够上下文；多处修改可逐处跳转。长稿件只滚动到首个修改处，不截断差异本身。
4. 新建文件显示完整只读稿件；同意前绝不将预览伪装成已经保存。接受后以实际工具执行结果刷新，不能拿模型入参冒充最终写盘内容。
5. 聊天区只保留轻量“等待你审阅某稿件”和返回入口，不再显示截断的黄色双块确认卡。

文件定位与保护规则：

| 场景 | 固定行为 |
| :-- | :-- |
| 目标文件未打开或面板收起 | 自动打开目标稿件，但不改变其他分类或后台会话 |
| 用户切走阅读、收起面板或进入计划 | 请求不取消；会话和稿件保留待审阅标记，返回可恢复 |
| 当前稿件有人工未保存草稿 | 不覆盖草稿；改为待审阅目标，明确“查看 AI 修改将保留你的草稿”，提供返回 |
| 目标稿件有人工未保存草稿 | 顶部持续提示人工草稿未保存；在“人工草稿 / AI 候选”只读页签间比较，默认展示候选但随时返回草稿。同意写入前必须再次选择“保留草稿并同意本次 AI 修改”，系统保存独立草稿副本后才执行；未确认则完全不写入 |
| 目标文件已有确认，又有人工保存意图 | 先完成或拒绝待审阅请求，再开放人工保存；禁止两个写入源竞争同一文件 |
| 确认前磁盘已变化 | 重新校验版本；失配则暂停确认，展示新版本和候选差异，不能照旧预览直接落盘 |
| 多项、不同文件或非当前会话请求 | 逐项、按会话处理；不自动跳到后台会话，只显示待处理标记与返回入口 |
| 上一个操作刚完成 | 等待工具结果和界面稳定后才显示下一项，防止一次点击误触下一个确认 |

确认过程可离开而不取消；用户主动拒绝才表示拒绝。停止运行时，服务层应收敛等待请求并给出明确状态，不能留下永远等待的面板。

### 3. 自动编辑：定位、红绿提示、缓慢淡出

免确认的新建和内容编辑成功后，以每次实际变更为触发，不等到整个 Agent 任务结束才粗略提示。

1. 打开目标稿件并定位到首个实际修改位置；若当前有草稿或用户正在阅读另一文件，保留现场并显示可点击的变更通知，不强制跳转。
2. 新增或替换后的正文使用低饱和绿色背景；被替换或删除的原文以相邻红色差异层展示，不能把已经删除的文字重新写回磁盘。差异提供前后上下文和“查看本轮全部改动”。
3. 首次定位后稳定显示约 2.5 秒，再在约 1.2 秒内缓慢淡出；淡出后保留“重新查看本轮差异”入口，不反复自动播放。
4. 同一文件连续多处修改以实际修改坐标逐处呈现，可切换上一处、下一处；不同文件形成变更队列，不互相覆盖。历史变更只保留可审阅记录，不在重开会话时重播动画。
5. 本轮通过的文件修改在接受后也走同一套定位与红绿淡出；用户点击的“重新查看”显示稳定差异，不再自动淡出。没有增加撤销能力时，不使用“撤销”文案。
6. 用户减少动态效果时取消自动平滑滚动和淡出，直接呈现稳定差异，由用户主动关闭。

### 4. 精准差异的服务契约，而不是界面猜测

服务层新增“稿件变更场景”，统一支持待确认与已写入两种状态。界面只消费场景，不自行拼接文件、猜测偏移或直接执行工具。

| 契约信息 | 要求 |
| :-- | :-- |
| 身份与归属 | 场景标识、会话、工具调用、确认或变更记录、Agent 归属、目标路径 |
| 文件版本 | 修改前与修改后的内容版本；旧记录可只有片段，必须标为不可精确定位 |
| 修改范围 | 每次实际替换在原稿和候选稿中的范围、原文、新文；批量替换逐处展开 |
| 当前内容 | 待确认时提供原稿与内存候选稿；已写入时提供真实落盘稿，二者不可混称 |
| 定位结果 | 精确位置、仅片段、文件缺失、已移回收站、版本失配等明确状态 |

- 工具执行时记录真实匹配位置和前后版本，与变更账本关联；确认预览使用规范化后的真实操作，不接受预览一套、执行另一套。
- 文件版本使用内容校验，处理连续写入、快速切稿、读取晚到和非激活会话。旧账本继续可读，但没有坐标时不伪造高亮，只显示现有片段差异和“此历史记录不支持定位”。
- 纯文本按统一 UTF-16 源码范围渲染，保留原换行，不先归一化换行后继续使用旧坐标。Markdown 以同版本源码到渲染块的映射定位：普通段落、标题和列表文本支持块内差异；嵌套结构、表格、链接和代码块至少定位到完整块，并在块旁展示原码差异。无法建立块内映射时，**只停在对应块顶部，旁边展示原文 / 新文片段，不给渲染正文添加伪造的块内高亮**。元信息头按源码块处理，不当作小说正文。
- 定位测试覆盖同段多处修改、连续段落、嵌套列表、链接、代码块、元信息头、Windows 与 Unix 换行和映射失败；纯文本与 Markdown 分别验收，不能用短段落样例代表全部格式。
- 版本失配、坐标无效或文件被改名时降级为片段审阅和明确提示，永不因追求高亮而覆盖新内容。
- 这项服务扩展属于稿件反馈能力，不改变 Agent 权限判断、模型协议或项目文件格式。

### 5. 草稿、保存与外部修改

**本期采用浏览器持久恢复草稿，不是只保留内存，也不是自动保存正文。** 每个项目与原始文件路径保存一份未提交草稿、编辑基线版本、原文件名、更新时间和阅读模式，存放在浏览器本地恢复区，不写入小说项目、不进入模型上下文、不产生版本历史。编辑时短延迟保存恢复副本，页面隐藏时尽力立即落恢复区；正常保存或明确放弃后清除。刷新、正常关闭重开和浏览器意外退出后，恢复最后一次成功写入恢复区的草稿，并重新检查正式文件版本；浏览器数据被清除、隐私模式限制或最后一次极短输入尚未落恢复区不在保证范围内。

- 草稿按项目和文件保留，跨预览/编辑、收起稿件、切文件、切分类、切会话、返回首页、刷新和正常重开项目均能恢复。恢复时展示未保存状态与基线版本，不以恢复草稿覆盖磁盘。
- 切文件和返回首页若恢复区已保存，可直接离开并在返回时继续；仍有未落恢复区的更改、保存中或恢复区不可用时，提供“保存并继续 / 放弃草稿 / 继续编辑”。保存失败不能继续原操作。关闭或刷新浏览器继续提供系统未保存提醒。
- AI 或外部编辑不覆盖人工草稿。保存以编辑开始时的版本校验，冲突时提供“查看差异”“重新读取并保留草稿副本”“明确覆盖”三个有后果说明的操作。
- 为同意 AI 修改而暂存的人工草稿，也先进入同一恢复区，成功后才允许工具写入；保留原路径和“因审阅 AI 修改暂存”的原因，能在目标稿件的人工页签恢复。
- 文件被重命名或删除时，恢复副本按原路径与稳定文件身份关联；无法识别新路径时作为“原文件已移动或删除”的孤立草稿展示，可另存或复制，不静默丢弃。
- 异步读取和保存都按项目、文件、请求序号和版本归属处理，旧响应不得覆盖新现场。

### 6. 稿件工作面的现场仲裁

内容确认和自动写回共用同一工作面，但**待用户决定的内容确认优先于自动反馈，人工草稿优先于一切自动跳转**。每个请求只在首次成为当前项时尝试自动展示一次；用户手动离开后不因状态刷新反复抢回。

| 场景 | 自动编辑成功 | 当前会话内容确认 |
| :-- | :-- | :-- |
| 目标就是当前稿件，且没有人工草稿 | 定位到真实修改并显示差异 | 当前稿件切为只读候选审阅，底部提供同意、拒绝 |
| 正在阅读另一稿件，没有未保存内容或编辑焦点 | 自动打开目标稿件；同会话多项修改进入顺序队列 | 自动打开目标稿件并进入候选审阅 |
| 正在编辑任一稿件，或有未保存草稿 | 不跳转、不清空输入；在稿件和会话显示可点击的变更通知 | 不覆盖人工现场；显示待审阅通知，用户明确点击后才打开候选 |
| 当前位于计划等非稿件表面 | 不强制切分类；保留待查看通知，点击后回稿件 | 不强制切分类；保留待确认标记和进入入口 |
| 后台会话的修改或确认 | 不自动打开或切换会话；只更新对应会话的变更或待处理标记 | 同左 |
| 同文件已有候选审阅 | 后续实际修改排队，版本变化使旧候选失效时先要求重新审阅 | 同会话逐项串行；上一项接受后的真实结果稳定后，才展示下一项，不抢回已离开的用户 |
| 目标稿件有人工草稿 | 不合并、不覆盖；通知版本冲突并保留恢复副本 | 按前述“人工草稿 / AI 候选”只读页签与二次选择处理 |

用户拒绝、接受或离开只影响相应请求和显示状态，不取消其他会话任务。计划文件的改动只刷新计划工作流，不套用章节高亮；新建、编辑之外的结构操作不进入稿件候选模式。
