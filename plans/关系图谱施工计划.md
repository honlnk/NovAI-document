> 状态：已完成（2026-11-21 四阶段落地并真机验收；同日 review 修复批收口，见文末施工日志末条）。设计方向与产品定位见[关系图谱设计构想](关系图谱要素计划.md)；本文解决该构想第十节列出的八项定稿事项，并给出字段契约、模块划分、阶段门禁与验收标准。施工状态、偏差与验收结果见文末施工日志。

## 一、八项定稿决策

对应设计构想第十节的顺序：

| # | 事项 | 决策 | 要点 |
| :-- | :-- | :--- | :--- |
| 1 | 要素标识唯一性与旧项目兼容 | **懒分配写回 frontmatter** | 现有要素 frontmatter `id` 是半成品（缺失兜底空串、无唯一性校验）。关系域首次引用某要素时为其生成稳定标识并写回该文件 frontmatter，其余要素保持原样。改名走纯文件移动（RenameFile 不重写 frontmatter），引用天然不受影响。旧项目零迁移：没有关系数据前一切不变。 |
| 2 | JSON 文件名与字段契约 | **`elements/relations.json` 单文件** | 顶层 `version` + `relations` 有序列表 + `layout` 坐标表；节点引用为 `{ kind, id }` 对象，`kind` 预留 `event`。契约见第二节。非法数据不静默丢弃：单条异常保留在文件中、加载时以 issue 呈现；整文件损坏进入只读损坏态。 |
| 3 | 有向与多重关系的画布呈现 | **Vue Flow + 箭头 + 平行偏移边** | 引入 `@vue-flow/core`（构想第七节明示的选型参考）。有向边带箭头；同一对节点间的多重关系渲染为按序偏移的平行曲线，边标签为关系类型；节点按要素类型着色并展示名称与摘要。 |
| 4 | 工具清单与权限 | **主 Agent 专属 7 工具** | RelationList / Read / Create / Update / Delete / Query / Check。装配对象与伏笔、节奏工具一致（主智能体，要素管理员不装配）；写工具走 `buildConfirmation` + `extractFileChange` 与计划/伏笔同一确认链与变更账本机制。 |
| 5 | 要素删除、改名的联动 | **改名零联动；删除级联清理** | 改名不触碰 frontmatter，无需联动。删除要素时移除引用该要素的全部关系：UI 删除在确认框中列明受影响关系数量；Agent DeleteFile 删除要素成功后自动级联并在结果中说明。悬空引用兜底：画布幽灵节点 + RelationCheck 报告 + 关系弹窗一键清理。 |
| 6 | 人工与智能体的并发保护 | **域级写锁 + 内容哈希版本** | 关系域对单项目账本的所有写入（UI、工具、坐标）串行经过同一进程内互斥队列；每次结构写入携带预期内容哈希，不匹配即冲突。关系编辑接入 save-session 引擎获得两秒自动保存与冲突四出口；坐标写入走重基合并（per-node last-wins）不产生冲突。智能体工具冲突时明确报错要求重读，不自动重试。 |
| 7 | 历史、视角与真相边界 | **第一版只有当前态** | 不实现关系变化历史、人物视角分栏、作者真相与故事内生效时间；这些等时间线模块完成后统一设计（构想 3.3 既定边界）。字段契约中不预留假结构，避免半成品字段污染数据。 |
| 8 | 规模与性能验收 | **默认最小图 + 限流输出** | 画布默认只展示有关系（或被显式加入）的节点，搜索添加、按类型筛选、聚焦直接关系；工具输出截断并给出总数。验收基线：80 节点 / 150 关系种子数据下拖拽、筛选可用（真机验收，见第八节）。 |

## 二、数据契约

### 2.1 稳定标识

- 要素标识：`ELM-` + 10 位小写字母数字（如 `ELM-3k9x2mqa07`）。首次被关系引用时由关系域生成，写入该要素文件 frontmatter 的 `id` 行（原文件无 `id` 行则插入首行之后，已有则原样保留）。写入带内容哈希版本校验，失败重读重试一次。
- 关系标识：`REL-` + 10 位，域内创建时生成。
- 节点引用统一为 `{ kind: 'element' | 'event', id: string }`；第一版只接受 `element`，`event` 为时间线预留（出现即校验拒绝并说明）。
- 节点类型范围：人物、地点、实体、情节、世界观五类要素。旧时间线要素不是关系节点（引用 `timeline` 类型要素直接拒绝，教学式说明事件账本完成后可引用事件）。

### 2.2 账本文件

`elements/relations.json`：

```json
{
  "version": 1,
  "relations": [
    {
      "id": "REL-a1b2c3d4e5",
      "from": { "kind": "element", "id": "ELM-xxxxxxxxxx" },
      "to": { "kind": "element", "id": "ELM-yyyyyyyyyy" },
      "type": "盟友",
      "description": "少年时同门修行，甲一直单方面回护乙",
      "createdAt": "2026-11-21T12:00:00.000Z",
      "updatedAt": "2026-11-21T12:00:00.000Z"
    }
  ],
  "layout": {
    "ELM-xxxxxxxxxx": { "x": 120, "y": 80 }
  }
}
```

| 字段 | 必填 | 约束 |
| :-- | :-- | :-- |
| `version` | 是 | 当前恒为 `1`；不识别的版本按损坏态处理 |
| `relations[].id` | 是 | `REL-` 前缀，域内唯一 |
| `relations[].from` / `to` | 是 | 节点引用对象；两端不得指向同一节点（自环拒绝） |
| `relations[].type` | 是 | 非空自由文本，建议短词；第一版不建封闭枚举 |
| `relations[].description` | 否 | 自然语言描述，允许空串（不强迫每条关系写散文） |
| `createdAt` / `updatedAt` | 是 | ISO 时间戳，域内维护 |
| `layout` | 是 | 节点 id → 视口坐标；纯展示状态，不参与语义判断 |

**重复关系定义**：`from.id + to.id + type` 三元组（方向敏感）完全一致即重复，创建时拒绝并指出既有关系标识。同对节点不同类型、反向同类型均合法。

### 2.3 损坏与非法数据

- **整文件损坏**（JSON 解析失败、根结构不是对象、`version` 不识别）：进入损坏态——UI 只读呈现原始内容并提供「重新初始化」出口（先把原文件副本存入 `.novel/trash/relations-<时间戳>.json` 再写空账本）；智能体工具返回教学式错误引导告知作者，不自动重置。
- **单条非法**（字段缺失、自环、引用格式坏、id 重复）：保留在文件中不丢弃，加载时进入 issue 列表，画布与 RelationCheck 呈现，可在弹窗中逐条删除修复。

## 三、公共地基（阶段 1）

为时间线复用而建，不含任何时间语义，也不含关系专属判断。

| 模块 | 位置 | 职责 |
| :-- | :--- | :--- |
| JSON 账本原语 | `core/ledger/json-ledger.ts` | 按路径读取、JSON 解析、版本识别、预期内容哈希写入、损坏错误类型；文件不存在视为空账本 |
| 稳定引用索引 | `core/elements/reference-index.ts` | 扫描六类要素目录构建 `id/name → 条目（类型、名称、摘要、路径）` 索引；报告重复 id、同名等 issue；提供 `ensureElementId`（生成并带版本写回 frontmatter）；解析结果统一处理缺失与无法解析，不把同名要素静默合并 |
| 受保护路径 | `core/tools/path.ts` | `elements/relations.json` 列入受保护名单：通用文件工具读写改删全部教学式报错，目录列表、文件查找、内容搜索、遍历一律不可见（对齐 `novel.config.json` 的单一来源机制）；UI 文件树同步隐藏 |
| 工作区弹窗骨架 | `app/components/layout/WorkspaceModal.vue` | 基于 BaseModal 组合：标题/副标题/操作区/关闭、主体滚动责任、桌面与窄屏统一尺寸、加载/空/错误插槽；不含任何领域分支，契约测试见第八节 |

要素目录披露与语义索引不受影响：`scanElementCatalog` 只收四类子目录 `.md`，根级 JSON 天然不进入；RAG 索引前缀只匹配要素子目录，账本不进入语义索引（补测试钉死）。

## 四、关系领域模块（阶段 2）

`core/relation/`（领域核心）+ `core/services/relation-service.ts`（UI 门面）：

- **校验**：引用合法性（解析得到且类型在五类内）、自环、重复三元组、type 非空、REL/ELM 标识格式、id 唯一。
- **CRUD**：create / update（含改端点，改后重校验）/ delete，均走「域内互斥队列 → 读账本 → 校验 → 变异 → 带哈希写盘」。
- **查询**：单要素关系、集合内关系（覆盖两对象间与当前场景人物两种意图，按入参个数区分）、异常检查。
- **坐标**：`saveLayout` 重基合并——读最新账本、只替换 `layout`、无版本检查写回（仍在互斥队列内）。
- **级联**：`removeReferencesTo(elementId)` 供删除要素链路调用；改名零联动。
- **变更通知**：`subscribeRelationChange(listener)` 模块级事件（对齐 rag-service 模式），UI 与工具写入后广播，画布据此刷新；带来源标记避免自身写入触发自刷新循环。
- **服务门面**：getGraph（节点+边+解析摘要+issue）、create/update/delete、saveLayout、cleanup、corrupt 状态与重新初始化；经 project-runtime 取项目。

## 五、智能体工具（阶段 2）

| 工具 | 读写 | 作用 |
| :-- | :-- | :-- |
| RelationList | 读 | 列出关系，可按要素、类型过滤；输出截断 + 总数 |
| RelationRead | 读 | 单条关系详情，端点带解析后的名称与类型摘要 |
| RelationCreate | 写 | 新建关系；自动为无 id 要素分配标识；重复/自环/坏引用明确报错 |
| RelationUpdate | 写 | 按 REL 标识修改类型、描述或端点 |
| RelationDelete | 写 | 按 REL 标识删除 |
| RelationQuery | 读 | 一个要素 id → 其全部关系；一组 id → 集合内部关系（两对象间 / 当前场景人物） |
| RelationCheck | 读 | 重复关系、悬空引用、单条非法数据报告 |

- 主 Agent 专属，要素管理员不装配（对齐伏笔/节奏先例，边界记录于施工日志）。
- 写工具 `buildConfirmation` 进 AI 写入确认链，`extractFileChange` 进变更账本（确认面板与变更记录以「关系账本」呈现）；智能体写入后画布经变更通知刷新。
- 工具冲突（内容哈希不匹配）返回明确错误要求重读，不自动重试。
- 主 Agent 提示词补两处：目录结构段登记关系账本；使用引导（写到人物互动前先 RelationQuery 既有关系）。

## 六、界面（阶段 3）

- **入口**：ActivityBar 动作区新增受控 Lucide 图标（`app-icons.ts` 注册），点击打开弹窗；不新增分类、不动 CategoryPanel（对齐 rag 先例）。
- **RelationModal**：组合 WorkspaceModal，内含画布、工具条（搜索添加节点、按关系类型/要素类型筛选、聚焦、检查入口）、右侧内嵌详情区（查看/编辑/新建关系表单）。
- **画布**：Vue Flow；默认只放有关系节点与幽灵节点（无法解析的引用），搜索添加其余要素；拖拽定位、缩放平移；拖拽停止后去抖保存坐标；节点按类型着色展示名称+摘要；有向箭头边、多重关系平行偏移曲线、边标签为类型；点击边开详情、点击节点聚焦直接关系。
- **详情编辑**：类型（文本 + 廸议词 datalist）、描述（多行）、端点（选择器复用引用索引搜索）；接入 save-session 引擎：两秒自动保存、状态灯、失败重试、冲突冻结 + 比较四出口、切选/关闭立即收口。
- **AI 写入联动**：变更通知触发画布重载（保持视口与坐标）；AI 修改命中编辑中详情时走同一冲突链。
- **窄屏**：弹窗全宽、画布区独立滚动、详情区改纵向堆叠（480 宽验收）。
- **依赖**：`packages/app` 新增 `@vue-flow/core`，样式在组件内引入，不动全局 CSS 入口。

## 八、验收标准

**契约测试（公共组件与地基，随阶段 1-3 落地）**

- WorkspaceModal：尺寸与滚动责任、关闭收口（遮罩 + 按钮）、加载/空/错误插槽、项目切换隔离、无领域分支断言。
- 稳定引用：重复 id 报 issue 不合并、缺失 id 懒分配写回、改名后引用不丢、删除后悬空可检。
- json-ledger：版本识别、损坏错误、哈希写入冲突。
- path 保护：relations.json 对读写改删/列表/查找/搜索全部教学式报错且不可见。

**阶段 4 OPFS 真机清单**（用 novai-opfs-testing 配方种入测试项目）

1. 旧项目（无账本）打开弹窗 → 空态引导，不产生文件；首次写入才建账本。
2. 新建关系全链路：搜索添加节点 → 填表 → 自动保存落盘 → 重开弹窗恢复（含坐标）。
3. 真实模型主会话：创建 → 查询 → 修改 → 删除关系，确认链完整，画布实时刷新。
4. 删除被引用要素：UI 确认框列明关系数量并级联移除；Agent DeleteFile 同。
5. RenameFile 改名要素：关系保留、画布名称更新。
6. 手工制造重复 id / 悬空引用：issue 呈现、创建被拒、一键清理有效。
7. 外部改盘：详情冲突四出口完整；损坏态两出口（查看原始 / 重新初始化入回收站）。
8. 480 / 375 窄屏弹窗布局可用。
9. 80 节点 / 150 关系种子：加载、拖拽、筛选不卡顿（目视验收）。
10. 要素管理员会话无关系工具；通用文件工具对账本全部教学式报错。

## 九、边界与暂缓（尾巴清单）

- 事件节点、关系变化历史、人物视角、作者真相与生效时间：等时间线模块，统一设计。
- 画布自动布局（力导向等）：第一版仅默认圆形 + 手动拖拽。
- relations.json 的 UI 原始 JSON 查看出口：损坏态已有只读呈现，正常态不提供。
- 批量删除关系、关系类型管理（收藏/自定义枚举）：不做。
- RelationList 输出分页：第一版截断 + 总数提示。
- RagIndexModal 迁移到工作区弹窗骨架：不在本计划范围，留给时间线阶段评估。
- 弹窗 Esc 关闭：BaseModal 无 Esc 先例，不为此破例。
