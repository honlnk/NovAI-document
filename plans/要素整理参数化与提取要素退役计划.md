## 背景与范围

### 为什么退役 `/提取要素`

`/提取要素`（2026-06-19 `483fae7`，UI 重构计划 R6）是前 Agent 时代的硬编码流水线：固定六分类、固定 prompt、单次 LLM 调用、预览-确认-写入，全程不经过 Agent Loop。当时底层能力（core 提取/写入服务）先于交互设计落地，R6 只是把 ContentPanel 角落里的提取按钮升级为斜杠指令入口——立项时并没有想清楚这个功能最终形态该是什么样。

2026-09-25 起，园丁子智能体体系（Phase 1/Phase 2）落地后，我们有了完整的 LLM WIKI 要素管理方案：

- **Raw Sources** = 小说章节原文（给人看的）
- **Schema** = `prompts/ELEMENT.md`（要素规范）
- **The Wiki** = `elements/` 要素文件（给 AI 看的——服务创作主智能体，解决长篇项目跨会话记忆问题，避免百万字后翻原文成本指数增长）

与 Karpathy 原始 LLM WIKI 方案「AI 整理笔记给人看」相反，我们是「AI（园丁）服务 AI（主智能体）」。在这个体系下，园丁懂 Schema、能读既有要素做增量归并、能按自然语言指令精确控制范围——`/提取要素` 的固定流水线能力是其严格子集（不会增量合并、不遵守 Schema、prompt 不可配置），没有保留价值。

### 本期四件事

1. **W1 要素整理参数弹窗**：ChapterPicker 改造为参数采集弹窗（自由文本 + 快捷选项 + 章节选择双列表），接两个入口——输入框斜杠指令/按钮（当前会话）与左侧栏按钮（新会话）。
2. **W2 快捷选项配置**：新建 `.novai/gardener-presets.json` 项目级配置 + 设置页「要素整理」tab 编辑区。
3. **W3 斜杠命令新范式**：选中斜杠命令后落文本进输入框（dsh claim 模式的简化版），`/整理要素`、`/生成项目记忆` 一并迁移，斜杠菜单瘦身为纯命令补全器。
4. **W4 退役 `/提取要素`**：UI、composable、core 提取器全量删除，文档同步。

施工顺序 **W1 → W2 → W3 → W4**：W1/W2 是参数化能力本体（弹窗先做空快捷选项的降级态也能用）；W3 改斜杠交互范式；W4 在前三波验证新链路完整覆盖提取场景后再删，留安全网。

### 明确不做（二期）

- **输入框富文本化**（textarea → Lexical/ProseMirror 级编辑器）：dsh 用 Lexical + TextNode 着色实现命令高亮（非 chip），我们二期再做，届时 `/命令`、`@场景` 一起高亮，自动补全 GhostTextOverlay 同步适配。本期斜杠命令落纯文本，可编辑可删除，行为与普通文字一致。
- 委派消息的硬编码前缀（`/整理要素` 字样本身不进 prompt 解析，仅作为用户可见的自然语言一部分，主 Agent 凭语义委派；不做 dsh 式的命令解析管线）。

## 已拍板决策（本计划定稿即生效，审阅时可推翻）

### D1 两个入口的会话归属不动摇

- 输入框斜杠指令选中 `/整理要素`、输入框上方「🌿 整理要素」按钮 → 参数弹窗确认后消息发到**当前会话**。
- 左侧栏「整理要素」按钮 → 参数弹窗确认后**先 `createNewSession` 再发送**（沿用现状 `ProjectView.vue:193-196` 链路）。

依据：园丁是子智能体，主 Agent 有 `DelegateToGardener` 委派工具（Phase 1 落地），当前会话发消息天然支持委派；侧栏按钮的定位是「整库大扫除」入口，独立会话不污染创作上下文。

> **修订（2026-10-07，用户拍板）**：斜杠指令选中**不再打开参数弹窗**——W3 落文本新范式下斜杠命令一视同仁只落文本（补参数后 Enter 发送，前缀拦截替换为驱动 prompt 全文）；参数弹窗只属于按钮入口（工具栏按钮=当前会话、侧栏按钮=新会话）。W3 施工时 gardener 曾保留「落文本+开弹窗」混合行为，本次修订收口。D1 的会话归属不变。详见施工日志后记。

### D2 参数弹窗形态（ChapterPicker 改造）

弹窗内容自上而下：

1. **任务描述文本域**：自由文本，placeholder 示例引导（如「例：提取最新两章中新出现的人物」）。
2. **快捷选项列表**：复选，选项来自 `.novai/gardener-presets.json`。
3. **章节选择列表**：复选，项目章节清单（沿用 ChapterPicker 现有列表 UI，去掉筛选框——章节筛选在整理场景没有作用）。
4. **右上角开关**（「选择章节」）：开启时弹窗同时显示快捷选项与章节两个列表，两列表勾选状态互相独立、可同时保留；关闭时只显示快捷选项列表。

**降级态**：未配置任何快捷选项时——开关默认开启（显示章节列表）；用户关闭开关后快捷选项区为空态，给「新建快捷选项」按钮，点击跳转设置页「要素整理」tab。

**确认按钮文案**：未选择/未输入任何内容时显示「直接整理」（发送裸 `GARDENER_TASK_PROMPT`）；有任何输入或勾选时显示「确认发送」。

**同一组件两个出口**：弹窗通过 prop `target: 'current' | 'new'` 区分确认后的发送目标（当前会话 / 新会话），不靠隐式判断。

### D3 消息拼装规则

确认后将参数拼成自然语言任务消息：

```
{GARDENER_TASK_PROMPT}
{用户自由文本（如有）}
{勾选的快捷选项 prompt 逐条拼接（如有）}
{勾选的章节拼为「涉及章节：第NNN章-〈标题〉.txt、…」（如有）}
```

章节选项最终以文本形式拼进消息（不是结构化数据）——园丁自己会读文件，文本指明范围即可。空参数时发裸 `GARDENER_TASK_PROMPT`，与现状行为一致。

### D4 快捷选项配置文件 = `.novai/gardener-presets.json`

不堆进 `novel.config.json`（用户拍板），新建项目级隐藏配置目录 `.novai/`（此前不存在，本期首创）：

```jsonc
// .novai/gardener-presets.json
{
  "presets": [
    {
      "label": "只更新变更章节",      // 列表显示名
      "prompt": "只整理指定章节涉及的要素，不动其他要素文件"  // 勾选后拼进消息的文本
    }
  ]
}
```

- core 侧在 project-fs / settings-service 层加读写函数（照 `readProjectConfig`/`writeProjectConfig` 模式新增，文件不存在时返回空数组，不报错）。
- 默认不给任何预置选项（用户拍板），由用户在设置页自行新建。
- `.novai/` 需加入 file-tools 的写保护名单：现状 `common.ts:28` 为 `folded === 'novel.config.json' || folded.startsWith('.novel/')`（小写比较），本期扩为追加 `|| folded.startsWith('.novai/')`——与 novel.config.json 同等级，Agent 工具（含园丁）不可写，仅 app service 层可读写。

### D5 设置页编辑区

GardenerSettingsPanel 新增「快捷选项」区块（沿用现有区块模式：`border-t` 分隔 + 标题说明行）：

- 选项列表：每行 label + prompt 摘要 + 删除按钮。

- 保存走独立读写（不走 SettingsModal 的 gardenerForm 自动保存链路——presets 在 `.novai/` 不在 novel.config.json），编辑即写文件（防抖或无防抖直写，文件小）。

### D6 斜杠命令新交互（W3）

- 选中 `/整理要素` → 清掉 `/token` → 填入 `/整理要素 `（尾部带空格）→ 光标置后 → 打开参数弹窗（target=current）。用户在弹窗里配参数；弹窗确认后**以弹窗拼装的消息为准发送**（输入框里残留的 `/整理要素 ` 文本在发送时清空）。若用户关掉弹窗，`/整理要素 ` 文本留在输入框里，可直接手输参数按 Enter 发送——纯文本，无解析，主 Agent 凭语义识别。

- 斜杠菜单瘦身：`extract` 项删除后（W4），菜单数据源只剩两条，组件逻辑不变。
