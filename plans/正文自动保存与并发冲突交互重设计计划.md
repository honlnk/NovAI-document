# 正文自动保存与并发冲突交互重设计计划

## 文档状态

- 记录日期：2026-11-09。
- 当前状态：**已定稿，待施工（2026-11-19 用户确认）；尚未开始代码改造**。
- 本计划重新设计章节、提示词和要素正文的人工编辑体验。它替代旧计划中「正文不自动保存」「不建立新的自动保存机制」的范围约束，不否定已经落地的数据安全机制。
- 本计划不自动批准共享文件修改、代码提交或推送。没有 goal 指令时，施工完成后停止并等待用户审查。

## 一、为什么重设计

现有版本已经证明：人工内容可以保留，跨文件和跨项目不会串稿，AI 先写盘时也不会被旧草稿直接覆盖。但用户需要理解并管理「草稿、保存、冲突再入口、恢复提示」，功能安全却不好用。

本次目标是把正常编辑变成无保存心智：

> 用户只管写；应用负责落盘。只有磁盘写入失败，或人工与 AI 修改确实需要选择时，才请求用户处理。

NovAI 不能直接照搬单写者编辑器的每次击键覆盖写盘：人和 AI 会修改同一正文，AI 又直接写项目文件。因此删除的是用户侧的「管理草稿」，不是底层的版本校验、未落盘缓冲和崩溃恢复。

## 二、目标、边界与已定取舍

### 1. 用户最终得到的体验

1. 打开支持的文件，进入编辑后直接输入；停止输入约两秒，正文自动写入项目磁盘。
2. 正常情况只显示「已保存」或「正在保存」。没有保存按钮，没有常驻「未保存草稿」管理入口。
3. 切换文件、分类或项目，关闭内容面板，页面隐藏时都会立即尝试收口写入；不要求用户想起保存。
4. AI 修改当前正在编辑的文件时，不强制跳走、不清空输入、不自动用任一方覆盖另一方。
5. 发生冲突后仍可继续编辑；顶部持续说明当前内容尚未落盘，用户主动打开版本比较后再决定采用哪一份。
6. 写入失败、冲突或刷新恢复的内容都仍保存在浏览器中，并明确说明它尚未进入正文文件。

### 2. 固定取舍

| 项目 | 本期固定方案 |
| :-- | :-- |
| 编辑模式 | 自动保存是唯一体验，不增加手动/自动保存开关 |
| 触发频率 | 最后一次输入后 2000ms 触发；关键离开时机立即触发；不逐击键写正文 |
| 正常反馈 | 「已保存 / 正在保存」；等待落盘期间使用克制的「等待保存」状态 |
| 编辑入口 | 保留现有预览/编辑切换与支持的文件范围，不重做编辑器 |
| 保存快捷键 | Ctrl/Cmd+S 作为立即收口的可选快捷方式保留，不显示「必须保存」提示 |
| 冲突处理 | 非阻塞提示 + 用户主动展开比较；不自动弹走编辑现场 |
| 冲突出口 | 返回继续编辑、另存副本、采用 AI 版本、采用我的当前内容；后两种继续二次确认 |
| 合并策略 | 不做自动三方合并、逐段采纳或模型代选版本 |
| 底层保护 | 保留版本校验、按项目与路径隔离、保存归属、未落盘缓冲及 IndexedDB 恢复 |
| AI 写入确认 | 保留现有确认链与真实工具执行语义，不以自动保存绕过确认 |

### 3. 适用范围

- 仅正文内容面板当前支持人工编辑的文件：章节、提示词、要素 Markdown。
- 创作计划卡、伏笔卡、节奏卡及设置页已有各自保存链路，本期不改成正文自动保存。
- AI 的新建、编辑、重命名、删除仍走 Agent 工具及确认机制；本计划不重写 Agent Loop。

## 三、两条并发防线的职责

| 时序 | 已存在的保护 | 本计划要改变的部分 |
| :-- | :-- | :-- |
| AI 先落盘，人工随后保存 | 保存携带人工编辑所依据的磁盘版本；不一致时取消写入，旧草稿不能覆盖 AI 修改 | 冲突不再整页突然接管；冻结该文件自动保存、保留继续输入，提供稳定的比较与处理入口 |
| 人工先落盘，AI 随后编辑 | EditFile 在真实执行前检查 ReadFile 后的文件状态，文件已变化则要求重新读取 | 保留现有工具防线并补自动保存时序验收；不把「AI 自动重新读取」写成本功能新增能力 |

第二条防线不是正文冲突界面的职责。若 AI 在思考期间读到旧版本，工具应报读后写状态失配，由 Agent 按既有教学式错误重新读取再尝试；不得为消除报错而跳过校验或强制写入。

## 四、目标状态机与统一保存编排

### 1. 每个「项目 + 文件」独立管理

把人工编辑、自动保存和冲突处理收敛到一个可独立测试的编辑器会话模块，避免继续在组件监听器、草稿表和保存回调中分别拼状态。文件面板只负责展示和发送用户操作。

每个会话至少明确记录：

- 项目、当前路径与起源路径；
- 最新人工输入、开始编辑时的磁盘正文与版本；
- 最近一次成功写入的正文与版本；
- 待写内容、写盘在途快照、失败原因；
- 已感知的外部版本与冲突代次；
- 当前是否因冲突、删除/重命名守护而禁止自动写入。

IndexedDB 草稿表不再被描述成用户工作流中的「草稿目录」，而是这个会话的**未落盘恢复镜像**。权威正文仍是项目磁盘；内存仍保存运行期最新输入。

### 2. 固定状态与文案

| 状态 | 用户看到的正文状态 | 是否允许自动写入 |
| :-- | :-- | :-- |
| 无待写内容 | 已保存 | 无需写入 |
| 输入后等待去抖 | 等待保存 | 到触发时机后写入 |
| 写盘在途 | 正在保存 | 同键串行，不并发写同一正文 |
| 普通写入失败 | 保存失败，内容尚未写入正文；提供重试 | 首次失败后台最多自动重试 1 次；仍失败则持续提示，之后由「重试」或下一次新输入重新触发 |
| 检测到外部版本 | 有另一版本，当前输入尚未落盘；提供「比较并处理」 | 禁止，直到用户解决冲突 |
| 删除/重命名守护 | 保留现有明确去向提示 | 禁止，直到用户选择去向 |
| 恢复镜像已回填 | 已恢复上次未写完的内容；按版本检查结果续存或处理冲突 | 只有磁盘版本与恢复基线一致时允许 |

「已保存」只表示磁盘正文已经包含当前输入。写盘在途、等待去抖、恢复未校验、冲突和失败都不能显示「已保存」。

### 3. 触发与串行规则

1. 输入先实时进入内存与恢复镜像，重置该文件 2000ms 去抖计时；恢复镜像继续使用自己的去抖策略，不以正文写盘替代。
2. 切文件、切分类、切项目、关闭内容面板、编辑切回预览时，立即请求该文件收口；页面隐藏、`pagehide`、`beforeunload` 同时尝试正文与恢复镜像收口。
3. 同一文件的写盘请求串行。写盘期间的新输入不清除、不回滚；旧写盘完成后仅承认其携带的快照，再按新基线处理剩余输入。
4. 一次写盘成功不得把「当时正在输入的新内容」误判为已保存。若仍有新输入，立即安排下一次写盘。
5. 切换归属后，旧保存只完成其固定项目与路径的写入和恢复镜像处理，不得改变新文件/新项目的界面状态。
6. 浏览器不保证关闭前异步写盘完成。收口不能完成时，恢复镜像仍作为崩溃保护；存在未写入正文内容时继续保留离开提醒，不宣称绝对零丢失。
7. 冲突与删除/重命名守护在写盘前再次检查，不能只靠提示出现时的状态；等待写盘期间才到达的冲突也要阻止后续旧基线写入。
8. 普通写入首次失败后在当前去抖窗口基础上追加 1000ms，再自动重试一次；重试仍失败则保持失败状态，不再定时循环。用户点击「重试」或产生新输入时才重新进入保存流程。
9. 保存服务继续以磁盘版本校验为最终防线。在现有磁盘更新时间校验外，人工保存同时携带由编辑基线正文计算的内容哈希；磁盘正文已不同于该基线且不是幂等写入时，即使时间戳未能识别变化也判为冲突。不得以跳过校验或静默强写换取自动保存。

### 4. 先修已定位的真实缺陷

在接入自动保存前，先修复 2026-11-08 真机补验发现的问题：保存成功替换同路径文件对象，却被文件/项目切换监听误判为切换，导致编辑态、冲突入口与保存错误被清掉。

- 文件/项目初始化监听必须按标量值比较，而不是靠每次新建数组的引用判断。
- 「同路径磁盘版本更新」「切换到另一个文件」「同路径切换到另一个项目」必须是三个不同事件。
- 先增加真实回写文件对象的组件事件序测试，证明旧监听器会失败；再接入自动保存状态机。
- 不得用保留旧文件对象或隐藏界面的办法绕过；最新磁盘版本仍要正确进入保存会话。

## 五、AI 修改与冲突交互

### 1. AI 写盘到达时

- 当前文件没有人工待写内容，且用户不在编辑中：沿用现有重读、差异高亮与通知行为。
- 当前文件正在编辑但输入已全部落盘：可以更新磁盘展示基线，不强行切预览；用户没有待处理选择。
- 当前文件有待写、在途写入或已存在冲突：立即冻结该文件后续自动写入，保留输入；读取最新磁盘版本并登记冲突。
- 若人工保存已在途，先让它按原快照完成；该成功只承认原快照已落盘。以最新 AI 磁盘版本重定人工输入基线并保留冲突，不能因旧保存晚到成功就解除冲突、继续自动覆盖或把后续输入标为已保存。
- 冲突读取在途时，显示「正在检查另一版本」，不能暂时退回「已保存」。读取失败只说明无法读取另一版本，不能伪装成文件已删除。
- 不自动展开整页冲突、不自动覆盖编辑器、不自动抢滚动位置。顶部出现持续的琥珀色状态条：「AI 更新了此文件，你的当前输入尚未落盘」，提供「比较并处理」。
- 冲突按项目与路径保存，切换文件、分类、项目、刷新恢复后仍有再入口。回到文件时恢复当前输入与冲突状态，而不是只剩一份找不到处理入口的草稿。

### 2. 用户主动比较时

在现有内容面板展开版本处理区，不新增全局弹窗或独立页面：

- 标题使用「此文件有两个版本」，不再以「保存失败」描述正常并发。
- 默认显示「你的当前内容」和「磁盘上的 AI 版本」的并列差异，以及双方位置、保留状态和有损操作后果。
- 差异使用用户点击处理时的**最新人工输入**与刚重新读取的磁盘版本；不是冻结在第一次冲突时的旧快照。
- 读取期间保留编辑现场；读取失败或文件缺失继续分开提示。
- 默认收起时只占紧凑状态条，不长期挤压正文；用户切走不视为已处理。

### 3. 四个出口

| 操作 | 固定行为 |
| :-- | :-- |
| 返回继续编辑 | 收起比较，不写盘、不删除内容，冲突再入口保留 |
| 将当前内容另存为副本 | 新建文件语义，不覆盖已有文件；成功后仍保留原冲突与原文件待处理状态 |
| 采用 AI 版本 | 二次确认；重新读取成功后才放弃对应人工内容，读取失败绝不先删内容 |
| 采用我的当前内容 | 二次确认；整份覆盖 AI 磁盘版本，等待期间新输入按新基线保留 |

采用操作期间继续输入仍须安全：旧采用结果不能清掉新输入、切走编辑模式或错误解除新冲突。采用完成后若仍有未落盘输入，保留冲突或按明确的新基线继续处理，不把不同版本混称为「已保存」。

### 4. AI 写入确认面板

现有确认面板继续承担「同意 AI 候选前」的审阅，与「AI 已写盘后」的正文冲突不是同一界面。

- 保留最终磁盘复检、最终未落盘内容复检、新建目标占用拦截、真实工具执行及工具读后写校验。
- 「保存人工草稿后重审」改为同一保存会话的立即收口，磁盘已变化时不得绕过版本校验直接强写；用户需要先通过版本比较明确选择，再回来审阅 AI 候选。
- 「保留副本后放弃草稿」保留新建语义，按钮直接标明「另存副本后放弃当前内容」；二次确认说明原文件内容仍未落盘。副本只保存操作开始时的快照，成功后才清除该快照；等待期间新增输入继续保留并进入重审，不能被一并删除。
- 自动保存可能恰好在确认审阅期间落盘。复检必须读取保存会话的最新状态，不能只查旧内存表；在途写入完成后再给出候选是否仍可安全同意的结论。
- 确认面板出现与当前文件冲突时，不两套面板各自强写。正文版本冲突未解决前，AI 候选保持等待，不能用「仍要同意」绕过。

## 六、迁移、恢复与旧机制去向

### 1. 新旧机制替代表

| 旧机制 | 新去向 |
| :-- | :-- |
| 编辑区底部保存按钮与「Ctrl/⌘+S 保存」提示 | 删除按钮与提示；快捷键改为可选的立即收口 |
| 常驻「未保存」与人工管理草稿心智 | 替换为「等待保存 / 正在保存 / 已保存」；只有异常时解释未落盘内容 |
| 手动保存函数与快照 rebase | 保留并扩展为自动保存统一编排，不重写另一套旁路 |
| 内存草稿表 | 保留为未落盘编辑会话数据，不再作为用户需要理解的独立草稿概念 |
| IndexedDB 草稿备份 | 保留数据库与记录格式，作为恢复镜像；不建项目草稿目录 |
| 恢复只回填、绝不写正文 | 替换为恢复后先核对磁盘版本，再自动续存或保留冲突 |
| 恢复横幅「未保存草稿」 | 替换为「已恢复上次未写完的内容」；续存成功可消失，冲突/失败持续显示原因 |
| 保存冲突自动整页接管 | 替换为非阻塞状态条，点击后展开比较 |
| 冲突状态随文件切换消失 | 替换为按项目与路径保留会话、冲突及再入口 |
| 删除/重命名草稿守护 | 保留安全语义，文案改为「尚未写入正文的内容」 |
| AI 写入确认与读后写校验 | 保留，接入同一保存会话，不增加绕过入口 |

### 2. 存量恢复记录迁移

- 不升级或清空现有 IndexedDB 数据库，不批量改写小说项目文件，不迁移聊天记录或项目设置。
- 旧记录缺少新增会话/冲突字段时，按「有人工内容、待校验」处理，不能因字段缺失丢弃。
- 恢复时逐文件读取磁盘，不能只看磁盘更新时间：内容与磁盘一致则清理冗余恢复记录；将当前磁盘内容与恢复记录中的基线正文直接比较，一致才自动续存；不一致则保留并建立版本冲突。后续若扩展恢复记录字段，内容身份仍须可验证，不能凭相同时间戳猜测安全。
- 已删除原路径的记录进入现有删除守护，不自动复活原文件；有起源路径的重命名记录沿用迁移选择。
- 恢复校验失败时保留恢复镜像并提示，当前正文不得以空值覆盖。
- 恢复流程不能因 toast 已读、切文件或刷新再次丢失冲突；冲突可从未落盘记录与磁盘差异重建。

### 3. 离开提醒与恢复边界

- 正常自动保存完成后，不再因短暂编辑历史弹出离开提醒。
- 有待写、在途、失败、冲突、恢复未校验或守护未处理内容时，离开提醒继续存在。
- IndexedDB 只保证本浏览器恢复，不跨设备同步，也不是历史版本系统。清理浏览器数据后，只能保留已写入项目磁盘的内容。

## 七、分阶段施工与门禁

### 阶段 1：保存身份修复与状态机地基

任务：

- [x] 用真实文件对象回写补回归测试，修复同路径保存被误判为切换文件的问题。
- [x] 建立按项目与路径隔离的编辑会话状态机，统一待写、在途、成功、失败、冲突和守护状态。
- [x] 把现有保存快照、归属校验、rebase、恢复镜像串行语义迁入统一编排；保留现有公共保存服务作为唯一正文写入口。
