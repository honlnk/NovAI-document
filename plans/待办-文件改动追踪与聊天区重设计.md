## 这份文档要做什么

用户拍板的四件事（原话浓缩）：

1. **聊天区改成 dsh 风格**：过程条目（工具调用、上下文注入等）默认折叠成窄行，一轮任务执行完毕后整体可折叠；**取消现在左右两个头像的气泡风格**（"不好看甚至有点土"）。
2. **任务完成后出一个 zcode 风格面板**：列出本轮修改了哪些文件，每个文件可展开看具体 diff。
3. **右下角状态区显示整个会话总共修改了多少文件**，不需要具体 diff。
4. **新增「文件修改历史」模块，做成工具按需加载**：不长期注入上下文；压缩把过程消息压掉后，模型想回忆"之前改过什么"可以自己调工具把记录拉回来。小说场景查历史不高频，不常驻。

顺带修复两个原始 bug（见下节），它们是本次重设计的起点。

## 现状与两个原始 bug

「本轮改了哪些文件」这件事目前没有被统一可靠地记录，散落在两处各有一个 bug：

- **Bug 1：压缩后改动清单丢准。** 右下角数据来自 `collectChangedFiles`（`packages/core/src/services/agent-service.ts:550-567`），它的做法是**翻 `modelView.messages`** 找带 `fileChange` 的 tool 消息。压缩把旧 tool 消息换成摘要后纸条全丢 → 清单不准（用户实测确认：压缩前准确，压缩后不准）。
- **Bug 2：完成总结只报一个文件。** 结尾那句「本轮 Agent Loop 完成，已写回 xxx」读 `session.lastWrittenPath`（`packages/core/src/core/chat/session.ts:235, 299-301`），它是**单值**，每来一个 fileChange 就覆盖，改 3 个文件最后只报第 3 个。

**关键反差**：`lastWrittenPath` 是事件驱动的（tool-result 事件顺手记），压缩后依然对；`collectChangedFiles` 是翻 modelView 的，压缩后才错。正确做法（事件驱动）已经现成跑通，只是没用到清单上。dsh 的同类功能（turn-deliverables，见锚点节）也是事件驱动派生，**反向验证了这个方向**。

fileChange 的产生机制本身是可靠的，保持不变：四个写工具干完活后通过 `extractFileChange(output)` 结构化报出 `{type, path}`（`create-file.ts:52`、`edit-file.ts:100`、`rename-file.ts:60`、`delete-file.ts:48`），在 `tool-execution.ts:134` 提取，同时贴进 modelView 和经 `tool-result` 事件（`tool-execution.ts:10`）实时广播。

## dsh 调研结论（2026-09-19，代码级核实）

| 需求 | dsh 有没有 | 结论 |
| :--- | :--- | :--- |
| 折叠聊天（无头像、工具行折叠、任务组折叠） | **有，完整** | 抄形状，不抄代码（它是 React + Cordis slot，我们是 Vue） |
| 任务后 diff 面板 + 撤销 | **只有一半** | 有单次工具调用的 diff 卡片机制（写时拿 before/after 算 hunk diff 并随会话持久化）；**没有**跨文件聚合面板、**没有**撤销。面板照 zcode 样子自己画，diff 机制抄 dsh |
| 会话级改动总数 | **没有** | 用我们自己的事件驱动账本；dsh 的回合清单同样是事件驱动，验证方向 |
| 历史查询工具（按需） | **有，一整套** | 5 个 session-query 工具 + SQLite 索引 + 官方明确「默认不挂载、按需 opt-in」。模式可抄，我们的实现简单得多：账本就在会话 JSON 里，工具只负责读出来 |

三条可直接复用的 dsh 经验：

1. **工具调用和工具结果不是两行，是同一行的状态迁移**（按 callId 原地合并）——我们现在「调用一条卡片、结果一条卡片」的双倍噪音就是没做这个。
2. **折叠行摘要按工具类型挑关键参数**（Read 显示路径、搜索显示 query），写工具行尾带 `+N -M`——不是甩一整段文本。
3. **任务组折叠摘要用计数**（"N 次工具调用 · M 条消息"）而不是 AI 摘要；用户消息、报错、最终回答永不折叠。

## 总体设计

### 1. 数据层：改动账本 `changeLedger`（核心新增）

在会话上新增一个 **append-only 的改动账本**，与 modelView 彻底无关，因此天然免疫压缩：

```ts
// packages/core/src/core/tools/types.ts（FileChange 旁边新增）
export type ChangeDiff = {
  oldText: string        // 被替换掉的原文片段；CreateFile 时为 ''
  newText: string        // 替换后的新片段；DeleteFile 时为 ''
  linesAdded: number
  linesRemoved: number
}

// packages/core/src/types/chat.ts（ChatSessionState 上方新增）
export type FileChangeRecord = {
  id: string
  runId: string          // 哪一轮任务产生（session.ts 每轮已有 runId，session.ts:63）
  at: string             // ISO 时间
  change: FileChange     // 现有四类：created/updated/renamed/deleted
  diff?: ChangeDiff      // created/updated 有；renamed/deleted 无
}
```

- `ChatSessionState`（`types/chat.ts:99-121`）新增 `changeLedger?: FileChangeRecord[]`。可选字段：旧会话 JSON 没有它，加载时视为空数组，**不需要迁移**。
- **累积点**：`session.ts:232-236` 现有的 `if (event.ok && event.fileChange)` 分支里，顺手 append 一条记录（`runId` 就是本轮的 runId）。注意 session 是 spread 浅拷贝来的（`session.ts:55-59`），追加时用不可变方式重建数组（`session.changeLedger = [...(session.changeLedger ?? []), record]`），不污染入参的会话对象。
- **持久化免费获得**：`saveSession` 序列化整个 session 落盘 `.novel/sessions/<id>.json`，账本随之落盘；重载后还在。
- **派生视图**（都是纯函数，随用随算）：
  - 本轮清单 = `ledger.filter(r => r.runId === 当前runId)` → 喂给 change-summary 面板（§5）和历史工具；
  - 会话级去重数 = 按目标路径（renamed 取 toPath）去重后的个数 → 喂给右下角；
  - 全文清单 = 整个账本 → 喂给历史工具。
- 体积评估：edit 的 diff 是片段级（几百字节到几 KB）；create 会带一次完整新文件内容（一章约 3-8KB）。一个会话几十次写入 ≈ 几百 KB 级 JSON，本地文件可接受。**先不设上限**，观察到膨胀再议。
- **删除 `lastWrittenPath`**：被账本完全取代。清理点：`types/chat.ts:112`、`session.ts:58, 235, 275-327` 全部引用、`agent-service.ts` 的 `toChatSessionView(..., changedFiles[last])` 传参（`agent-service.ts:306`）及 `ChatSessionView.lastChangedFile`（`services/types.ts:369`，全局搜索确认无 UI 消费后删）。

### 2. diff 数据留存：写工具 output 扩展

现状 `extractFileChange` 只报 `{type, path}`，没有改动内容。抄 dsh 的机制（写时拿 before/after → 算 diff → 存起来），但存**片段级**而不是整文件：

- `EditFileOutput`（`tools/types.ts:115-121`）新增 `oldText: string`、`newText: string`——`edit-file.ts` 的 `run()` 里 `actualOldText`/`actualNewText`（`edit-file.ts:64-76`）是现成局部变量（经过 `findActualText`/`preserveQuoteStyle` 校正后的**实际应用**文本，不是模型入参原样），直接放进返回值。`linesAdded/linesRemoved` 已有。
- `CreateFileOutput`（`tools/types.ts:128-133`）新增 `content: string`（`run()` 里现成）。`linesAdded` 已有。
- `RenameFile`/`DeleteFile` 不改（删除的行数统计 `linesRemoved` 已在 `DeleteFileOutput`；删除内容不落账本——`trashPath` 已记，要看原文去回收站）。
- `ToolDefinition`（`tools/types.ts:60-77`）新增可选钩子 `extractChangeDiff?(output): ChangeDiff | undefined`；EditFile/CreateFile 实现它。
- `tool-execution.ts` 在 `extractFileChange`（:134）旁边一并取 diff，`tool-result` 事件类型（:10）加 `diff?: ChangeDiff` 字段一起广播。session.ts 累积账本时带上。
- **modelView 里的 tool 消息不挂 diff**（模型不需要逐行 diff，省 token）；账本才是 diff 的唯一载体。

### 3. service 与 store 接口

- `collectChangedFiles`（`agent-service.ts:550-567`）**改为读账本**，不再翻 modelView —— Bug 1 修复落点。
- `RunAgentTurnResult`（`services/types.ts:401-407`）调整：
  - 新增 `turnChanges: FileChangeRecordView[]`（本轮账本切片，含 diff，喂面板）；
  - 新增 `sessionChangedFileCount: number`（会话级去重数，喂右下角）；
  - `changedFiles` 字段删除或重命名为上述二者之一，实施时全局清理消费方（`stores/chat.ts:205, 319`）。
- `ChatSessionView`（`services/types.ts:363-374`）新增 `changedFileCount?: number`，加载会话时即从账本算出 → **重载后右下角计数不丢**。
- `file-changed` 实时事件保留（UI 刷新文件树用），载荷可升级为完整 record。
- chat store（`stores/chat.ts`）：`changedFiles` 改为「会话级清单」（来源：run-finish 的账本全量 / 加载会话时的 view），`ProjectView.vue:118-127` 的 watch 改为 watch 数量或清单均可。面板数据**不经 store**，见 §5（change-summary 消息自带解析后的 records）。

### 4. UI：聊天区 dsh 风改版（工作量最大的一块）

现状（要被替换的）：`MessageItem.vue` 双头像气泡（用户右蓝泡带头像、AI 左灰泡带头像）、工具调用和工具结果是**两张独立系统卡片**、工具卡片只显示「调用工具：名字」没有参数摘要。

目标形状（全部照 dsh 调研结论）：

- **去头像**：用户消息保留右对齐气泡但删头像；AI 回复全宽左对齐纯 markdown，不套气泡框。时间戳弱化保留或删。
- **工具行合一**：一次工具调用从头到尾只占一行——调用时该行转圈，结果回来原地变结果。需要给显示层两类消息加配对字段：`ToolCallMessage`/`ToolResultMessage`（`types/chat.ts:44-60`）加 `toolCallId?: string`（`session.ts:216-251` pushMessage 时有 `event.call.id` 现成可用）；`ChatMessageView` 的 system 分支（`services/types.ts:353-361`）同步加。**旧会话消息没有此字段，配不上对**：fallback 为各自独立成行（套用新行样式），不报错。
- **工具行组件 `ToolCallRow.vue`**：24px 单行，默认折叠 = [状态图标] 工具名 · 一行参数摘要（`inputSummary` 现成，`summarizeInput` 各工具已实现）· 写工具尾部 `+N -M`（从账本/diff 取，可取不到就不显示）。点击展开显示结果全文；失败行摘要换成错误首行、图标变红。
- **任务组折叠 `TurnProcessGroup.vue`**：一轮任务 = 从一条 user 消息到下一条 user 消息之间。组内「过程消息」（context-summary、工具行、中间 assistant 文本）默认整体折叠成一行摘要：`N 次工具调用 · M 条过程消息` + chevron。**永不折叠的白名单**（照 dsh `TURN_PROCESS_INDEPENDENT_KINDS` 思路）：user 消息、最终回答（组内最后一条 assistant text）、**change-summary 面板**（§5，它是本轮的交付物）、error 消息。纯问答轮（没有过程消息）不出折叠行。运行中的轮次不折叠，run-finish 后自动收起。展开状态按组 id（= 组首 user 消息 id）记在 store 的 Map 里，切换会话不清。
  - Vue 里直接用「包裹容器」实现即可（dsh 是兄弟节点各自隐藏 + `hidden="until-found"` 让 Ctrl+F 能搜到折叠内容；**这个 until-found 技巧列为可选增强**，不阻塞本期）。
- **渲染序列预处理**：chat store 新增 computed `renderItems`，把 `messages` 数组转成渲染树（user / assistant / tool-row(已配对) / process-group / error / summary），`ChatPanel.vue:457-458` 的 `v-for message` 改为渲染 `renderItems`。配对与分组逻辑都收在这一个 computed 里，组件只负责渲染。
- `context-summary` 消息（每轮固定两条「本轮目标」「任务类型」）不再单独做卡片样式，作为过程消息折进组内。

### 5. UI：任务完成 diff 面板（zcode 风，**由原「完成总结」消息改造而来**）

**关键决策：文字版完成总结与面板二选一，合并为一个东西。** 现在每轮结尾那条「本轮 Agent Loop 完成，已写回 xxx / 未写入文件」的 `action-summary` 气泡（`session.ts:268-306`）**不再产生**，它的职责由面板整体接替——不存在「文字报一遍、面板再列一遍」的并存。Bug 2 随之消解：不再有任何「报几个文件」的文案，面板直接展示全部。

实现方式：把原来的 action-summary 消息**改造成一条结构化的「改动汇总」消息**——它本身就是面板在消息流里的占位，随消息持久化，重载后每一轮的面板都还在原位：

```ts
// packages/core/src/types/chat.ts 新增（取代 AssistantActionSummaryMessage 的生态位）
export type ChangeSummaryMessage = {
  id: string
  role: 'system'
  kind: 'change-summary'
  runId: string        // 只存 runId；面板数据渲染时从账本按 runId 解析，不重复存 diff
  aborted?: boolean
  createdAt: string
}
```

- **产生时机**（`session.ts` 结尾逻辑改写，原来的两段 action-summary push 整体替换）：
  - 正常结束且本轮账本非空 → push `{ kind:'change-summary', runId }`；
  - 正常结束且无改动（纯问答轮）→ **什么都不 push**（聊天不该有「回答完毕」噪音）；
  - 被停止（aborted）→ 一律 push `{ kind:'change-summary', runId, aborted:true }`：有改动渲染为面板并带「已停止」标记；无改动渲染为一行「本轮已被用户停止」。
- **view 解析**：`toChatMessageView`（`agent-service.ts:530` 附近）遇到 change-summary 时，从 `session.changeLedger` 按 `runId` 捞出 records 装进 view：`{ kind:'change-summary', runId, aborted, changes: FileChangeRecordView[] }`。UI 拿到就是现成的，不需要自己访问账本。账本缺该 runId（异常旧数据）时渲染为一行降级文本。
- **旧数据兼容**：`AssistantActionSummaryMessage` 类型保留、旧会话里的 action-summary 继续按现在的瘦行样式渲染，但**标注「不再产生新消息」**；`ChatMessageView` assistant 分支的 `action-summary`（`services/types.ts:347`）同理保留只读。
- **面板组件 `TurnChangesPanel.vue`**（渲染 change-summary 消息）：
  - 标题行：`本轮写回 N 个文件 · 合计 +X −Y`（N = 本轮去重路径数；X/Y = 各记录 linesAdded/linesRemoved 求和）；`aborted` 时前缀「已停止 · 」。
  - 文件列表逐条列**操作记录**（同一文件改两次就是两行，各自带 diff；账本天然顺序，不做按文件聚合）：类型图标（新建/修改/改名/删除）+ 路径 + `+N -M`。改名显示 `from → to`；删除显示「已删除，原 N 行」。
  - 点击某条展开 diff 视图：引入 `diff` 包（jsdiff，dsh 同款依赖），对 `oldText/newText` 做 `diffLines` 行级对比，红/绿行渲染；新建文件自然全绿。新小组件 `DiffLines.vue` 负责渲染。
  - **默认状态：最新一轮的面板展开文件列表，历史轮的面板折叠成标题行**；展开状态组件内管理。diff 区默认全收起、点开才算（lazy，避免长章节一次性渲染）。
- **撤销按钮本期不做**（zcode 有，dsh 也没有）。扩展注记：未来要做的话，账本的 diff 数据已够支撑——edit 反向应用（需唯一性校验）、create 撤销 = 删除、delete 撤销 = 从回收站恢复（trashPath 现成）、rename 撤销 = 改回；链路冲突时拒绝并提示。
- `ChatTurnResult.writtenPath`（`types/chat.ts`，完成/停止两处 return 里的字段）随 action-summary 一起清理，全局搜消费方后删或改为 `turnChanges`。

### 6. UI：右下角会话总数

- 底部状态区现状文案是「本轮执行完成，变更 N 个文件」（`stores/chat.ts:320-324`），改为：完成后状态区**常态显示会话级总数**「本会话共修改 N 个文件」（数据来自 `ChatSessionView.changedFileCount` / run-finish 的 `sessionChangedFileCount`），本轮明细由面板承担，不再塞进状态文案。
- 文件树自动刷新逻辑（`ProjectView.vue:118-127` watch）保留，watch 源换成新字段。

### 7. 工具：`GetFileChangeHistory`（按需取回）

- 新增**只读**工具，让模型在压缩后想回忆「本会话此前改过哪些文件」时自己调用。**不长期注入任何内容**——工具挂在列表里、description 写清用途即可（dsh 验证的模式：可发现性靠工具描述，压缩摘要里也不专门提）。
- description 建议文案：`查询本会话此前的文件修改历史（改了哪些文件、什么时间、增删行数）；当你需要回忆或核对之前的改动时使用。`
- 参数（全部可选）：`limit`（默认 20，最大 100）、`path`（只看某文件）、`runId`（只看某轮）。
- 返回：纯文本清单，新→旧逐条 `[时间] 类型 路径 (+A −B)`，末尾「共 N 条记录」；无记录时明说「本会话暂无文件修改记录」。
- **数据来源链路**（新增，需透传）：工具的 `ToolRuntime`（`tools/types.ts:13-16`）目前只有 `project` + `readFileStates`，拿不到账本。链路为 `session.ts`（调 query 时传 `session.changeLedger`）→ `query.ts`（input 加字段）→ `runAgentTools`（透传）→ `tool-execution.ts:128-131`（组 runtime 时带上）→ 工具 `run()` 读取。传数组只读引用即可。
- 注册与类型同步点（全局搜 `RagSearch` 可找全）：`AgentToolName`（`agent/messages.ts:3-12`）、`CoreToolName`（`tools/types.ts:3-11`）、`ChatToolName`（`types/chat.ts:6-14`）、`ToolNameView`（`services/types.ts:286-295`）四个联合类型 + `createAgentTools` 注册（`agent/tools.ts:43`）+ `isAgentToolName`（`agent/tools.ts:388`）。
- 结果自控 limit，**不进** `SPILLABLE_TOOLS`。

## 明确不做

- **不引入事件溯源/投影框架**——坚持 [[参考系切换-ClaudeCode转向DeepSeekHarness]] 已定决策，账本就是一个普通数组随会话 JSON 落盘。
- **不做撤销按钮**（本期）；账本 diff 数据已为其预留。
- **不做跨会话历史查询、不引入 SQLite 索引**（dsh session_search 的跨会话部分不抄；小说场景用不上）。
- **工具行不做子调用嵌套树**（我们没有 subagent）。
- **不抄 Cordis slot 注册机制**；UI 就是普通 Vue 组件。
- `hidden="until-found"` 折叠可搜索列为可选增强，不阻塞验收。

## 验收要点

- 改多个文件后：本轮结尾**不再出现**「已写回 xxx」文字气泡，而是出现一张 diff 面板，列出本轮全部操作记录，每条可展开看行级 diff，标题合计 +X −Y 正确；纯问答轮结尾没有任何额外消息。
- 停止运行：有改动时面板带「已停止」标记，无改动时只有一行「本轮已被用户停止」。
- 构造触发压缩的长对话：压缩前后右下角会话总数一致且准确；面板数据不丢。
- 重载会话后：右下角计数仍在；**每一轮**的面板都在原位（change-summary 消息持久化 + 账本持久化），无需重建逻辑。
- 压缩后问模型「你之前改过哪些文件」：模型能调 `GetFileChangeHistory` 拿回记录并正确回答。
- 聊天区：无头像；工具调用全程只占一行；一轮任务完成后过程默认折叠成一行计数摘要；用户消息、最终回答、错误不折叠；旧会话消息（无 toolCallId）打开不报错。
- `pnpm test` 全绿（含新增：账本累积、压缩后存活、diff 提取、历史工具返回格式）。
