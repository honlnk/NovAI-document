# 创作计划板交互优化计划

## 文档状态

- 记录日期：2026-11-06。
- 当前状态：**进行中（goal 指令施工，2026-11-06 开工）**。
- 本文档是计划板手动交互优化的独立设计与施工依据。动工前须获得用户批准；开工后按阶段更新状态、施工日志、验收结论和偏差。

## 背景与现状调研

用户在真实项目中使用计划板后，提出五项体验问题：

1. 新建计划在看板顶部展开一块输入区，挤占看板空间，希望改到右侧抽屉中完成。
2. 在详情抽屉切换分组后，主看板已经移动卡片，但抽屉中的分组按钮仍显示旧选中状态。
3. 计划名不能直接修改；修改名称时，真实文件名也要同步变化，而不只是改变正文。
4. 详情正文没有占满抽屉高度，保存与删除被拆在两个区域。
5. 详情一直显示多行文本框，希望默认渲染 Markdown，双击或点击编辑后再进入编辑态；不需要实时混排。

### 已确认的代码事实

- `PlanBoardPanel.vue` 同时承载看板、新建表单和右侧详情。新建开关与输入内容是组件局部状态；侧栏「新建计划」在 `ProjectView.vue` 中只切换分类，已经位于计划页时不会打开表单。
- 新建事件发出后立即清空并关闭输入区，没有等待创建结果；失败时可能丢失尚未落盘的内容。
- 抽屉分组按钮根据 `activeCard.status` 高亮；`stores/plan.ts` 的 `moveCard()` 调用更新服务后丢弃返回详情，只刷新看板，因此卡片位置和抽屉高亮使用了两份新旧不同的数据。继续保存正文还可能携带移动前的内容哈希。
- 计划展示名来自正文首个非空行，frontmatter 没有独立标题字段。创建文件名为 `计划-<创建序号>-<短标识>.md`，正文变化不会引起重命名。
- 计划正文已具备显式保存、未保存标记、内容哈希冲突检测和回收站删除；当前没有真正执行「切卡或关闭前确认保存 / 放弃」的离开守卫。
- 现有 `MarkdownRenderer.vue` 可直接复用，不新增 Markdown 依赖；其默认浅色文字主题需要为深色抽屉提供局部变体。
- 现有自动化测试覆盖 core 领域、服务和 Pinia store，没有 Vue 组件交互测试设施。双击、模式切换、布局和视觉状态必须由浏览器验收补足。

## 目标与范围

1. 所有手动新建入口统一打开右侧抽屉，创建成功后再落盘并展示新计划详情。
2. 分组切换后，看板位置、卡片选中态、详情高亮和后续保存版本保持一致。
3. 计划名可以独立编辑；一次保存同步更新正文首个非空行和真实文件名。
4. 详情正文占满抽屉可用高度，保存和删除位于同一操作行。
5. 已有计划默认预览 Markdown，按需进入编辑，只保留预览 / 编辑两种状态。
6. 新建和已有详情的未保存内容都有明确的离开保护，不因视图切换或操作失败丢失。

## 交互设计

### 新建计划抽屉

1. 顶部「新建计划」、看板空状态入口、侧栏「新建计划」都打开同一个右侧新建抽屉。
2. 删除看板顶部原展开输入区，不再在看板上方插入新内容。
3. 抽屉提供「计划名」单行输入和「正文」多行输入。创建时将计划名作为正文首个非空行，其余内容保持为用户输入的 Markdown；不新增 frontmatter 标题字段。
4. 新计划默认进入收集箱列尾，不因当前查看其他分组或已搁置筛选而改变默认落点。
5. 主按钮为「创建」，次按钮为「取消」。创建期间禁止重复提交。
6. 点击创建后等待真实保存结果：成功则退出新建态、刷新看板、打开新计划的预览详情；失败则保留计划名、正文和抽屉，并显示错误。
7. 空表单可以直接取消；有计划名或正文时，关闭或切换到其他计划先确认「保存 / 放弃 / 继续编辑」。选择保存时才执行创建，成功后继续原跳转。
8. 新建抽屉不显示删除按钮，也不伪造尚未落盘的卡片 ID。

### 详情分组与草稿同步

1. 点击分组按钮后仍立即保存到目标列末尾，保留拖拽排序和已搁置筛选的现有规则。
2. 状态更新成功后，接收服务返回的完整详情，并按计划 ID 更新当前抽屉；看板与按钮高亮读取同一份最新状态。
3. 同步最新内容哈希，保证移动后继续保存正文使用当前文件版本。
4. 状态切换不得清空或覆盖未保存正文草稿。若用户在操作期间已打开另一张卡片，不回写旧卡片详情。
5. 切换到已搁置后，即使当前卡片从默认看板隐藏，也保留其详情，直到用户主动关闭或打开另一张卡片。

### 计划改名与文件名

1. 详情头部提供独立的计划名输入框；名称与正文通过底部同一个「保存」按钮提交。
2. 名称仍对应正文首个非空行，不形成第二个名称事实来源：
   - 首行是 Markdown 标题时，保留原 `#` 层级，只替换标题文本。
   - 首行是普通文本时，只替换该行文本。
   - 保留首个非空行之后的全部正文。
3. 新计划创建后采用 `计划-<创建序号>-<清理后的计划名>-<短标识>.md`。改名保留原序号和原短标识，只更新可读名称部分。
4. 已有旧格式文件不批量迁移，首次通过详情改名时转换为上述格式。外部手建且无标准序号的文件，只规范其文件名主体，不编造序号。
5. 展示名去除首尾空白且不能为空；文件名部分清理路径分隔符、控制字符和跨平台文件系统非法字符，清理后不能为空。
6. 同名计划允许共存，依靠序号和短标识避免路径冲突。目标路径已存在时拒绝保存，不能覆盖其他文件。
7. 改名保持计划 ID、状态、排序、创建时间和未修改正文不变，只更新名称对应的正文行、更新时间和来源路径。
8. 改名纳入现有内容哈希冲突检测；文件已被外部修改时拒绝覆盖，并保留当前用户草稿。
9. 名称未变化时只做正文更新，不重命名文件。名称变化时一次写入完整目标文件，再删除旧文件；旧文件不进入回收站。
10. 当前文件系统没有原子重命名原语。目标写入失败时保留旧文件；旧文件删除失败时清理刚写入的新文件并报告失败，避免留下同 ID 双卡。
11. 成功后看板、详情和文件树都采用新名称与新路径，重新打开项目仍能通过原 ID 找到同一计划。

### 详情预览、编辑与布局

1. 打开已有计划默认显示渲染后的 Markdown；计划名仍在独立输入框中，正文预览显示完整正文。
2. 双击正文预览或点击「编辑」进入多行文本框；点击「预览」返回渲染态。
3. 编辑时不渲染实时预览，不做 Obsidian 式动态混排，也不引入富文本编辑器。
4. 正文继续使用 store 中唯一的草稿。切换预览 / 编辑只改变视图，不清空草稿；预览可以显示尚未保存的内容，并保留「未保存」标记。
5. 保存成功后回到预览；保存失败或发生冲突时保留编辑态、草稿、错误和冲突处理入口。
6. 抽屉使用固定头部、固定分组区、弹性正文区、固定底部操作区。正文占满剩余高度并内部滚动，不让长正文把整个操作区推出抽屉。
7. 「保存 / 删除」位于底部同一行。删除沿用两步确认、取消和回收站语义；更新时间等次要信息不与操作按钮争抢空间。
8. 切换卡片时回到预览，并清除上一张卡片的删除确认状态。
9. 有未保存名称或正文时，切换卡片、关闭抽屉或离开计划页先确认「保存 / 放弃 / 继续编辑」。保存成功后继续原操作，保存失败则停留当前编辑现场。
10. 复用 `MarkdownRenderer.vue` 的安全解析、链接与块级渲染能力，为其增加深色主题变体；不在计划组件里全局覆盖样式，不改变聊天和文件预览的现有外观。

## 新旧机制替代与数据迁移

| 项目 | 旧机制去向 | 新机制 |
| :-- | :-- | :-- |
| 看板顶部新建输入区 | 删除 | 右侧新建抽屉 |
| 侧栏只切换分类的新建入口 | 替换 | 与顶部、空状态共用新建抽屉 |
| 状态切换只刷新看板 | 替换 | 同步当前详情、分组高亮和内容哈希 |
| 无独立名称编辑 | 替换 | 名称输入框，与正文一次保存 |
| 创建后永久不变的编号文件名 | 兼容旧文件 | 新建采用可读名称；旧文件首次改名时迁移 |
| 常驻正文 textarea | 替换 | 默认 Markdown 预览，按需编辑 |
| 分离的保存区和删除区 | 替换 | 底部同一操作行 |
| 无实际离开确认 | 补齐 | 保存 / 放弃 / 继续编辑 |

不迁移旧计划的正文、ID、状态、排序或时间；不新增 JSON 索引，不新增 frontmatter 标题字段。旧文件名继续可读、可改状态、可删除，只有用户主动改名时才改变路径。
