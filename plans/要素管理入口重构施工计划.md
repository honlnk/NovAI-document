# 要素管理入口重构施工计划

## 记录时间

2026-10-22 定稿。

## 文档性质

本文档是**施工计划**，是「要素管理入口」讨论定稿后的落地执行依据。它把入口交互的四项改动拆成四个波次（W1–W4），每波带门禁；验收结论与偏差记录随施工追加在文末施工日志。

## 背景

要素管理员子智能体的能力已经就位（改名 + 提示词升级 + 放开 RenameFile 均已完成），但**入口形态**仍是早期形态：五个入口全部汇聚到「给主 Agent 发一段长提示词」，靠主 Agent 读完提示词后自由解读再委派。讨论后确认方向：入口收敛、提示词瘦身、并新增「直聊会话」这一全新交互形态。

### 当前入口的五个形态（将被重构）

| 入口 | 现状行为 | 会话 |
| :--- | :--- | :--- |
| 斜杠 `/管理要素 <参数>` | 落纯文本命令，发送时前缀拦截替换为长提示词全文 | 当前 |
| 斜杠 `/管理要素` 裸发 | 同上，裸发即长提示词本身 | 当前 |
| 输入框上方按钮 | 开参数弹窗，拼装长提示词发当前会话 | 当前 |
| 侧栏按钮单击/双击 | 单击开弹窗（新会话）、双击直发裸任务（新会话） | 新建 |
| 全局快捷键 Ctrl/Cmd+Shift+G | 直发裸任务 | 当前 |

### 目标入口形态（本计划落地后）

| 入口 | 目标行为 | 会话 |
| :--- | :--- | :--- |
| `/管理要素 <参数>` | 短提示词发给主 Agent，模型自行委派 | 当前 |
| `/管理要素` 裸发 | placeholder 提示可补范围；留空 = 全权委托直接委派 | 当前 |
| 输入框按钮（滑入式提醒） | 阈值触发 → 滑入 → 点击落模板到输入框 → 退回 | 当前 |
| 侧栏按钮（仅单击） | 新建**直聊会话**，与要素管理员多轮对话 | 新建 |

删掉的：参数弹窗（两处）、侧栏双击、全局快捷键、输入框按钮的常驻入口职责。

保留不动的：主 Agent 主动委派路径（模型在写作中发现要素问题时走 `DelegateToElementManager` 工具，是模型真决策，与入口无关）。

## 已拍板决策（施工不可更改）

1. **斜杠瘦身**：`ELEMENT_MANAGER_TASK_PROMPT` 压缩为一句，不带括号限制——「自包含」约束已由 `DelegateToElementManager` 工具 description 承载（「子智能体看不到当前对话，task 必须自包含」），提示词不重复。最终文案：

   ```
   请调用 DelegateToElementManager 委派要素管理员处理以下要素管理需求：
   ```

2. **裸发**：placeholder 提示可补范围；留空 = 全权委托，主 Agent 直接委派，**不反问**。

3. **提醒按钮**：位置在输入框上方工具栏（「完全访问」旁），从左往右滑入，非常驻。阈值触发。

4. **直聊会话**：侧栏单击 = 新建直聊会话；用户与要素管理员多轮对话；UI 明确区分。

5. **删除**：双击、快捷键、两处参数弹窗、快捷选项 presets 全套。

6. **提醒模板默认值**：`/管理要素 对新增章节：{章节名列表}，提取要素，要求：`（`{章节名列表}` 由代码用最近 N 章真实章节名填充）；存项目配置可编辑。

7. **阈值默认**：距上次整理新增 ≥ 2 章即提醒。

## 新旧机制替代表

| 旧机制 | 去向 | 说明 |
| :--- | :--- | :--- |
| `ELEMENT_MANAGER_TASK_PROMPT` 长文 | **替换** | 压缩为一句；旧长文的所有引用点同步改 |
| 参数弹窗 `ElementManagerTaskDialog.vue` | **删除** | 两处实例（ChatPanel 弹层 + ProjectView 模态）连同 `element-manager-task.ts` 逻辑层一起删 |
| 快捷选项 presets（`.novai/element-manager-presets.json` + 设置页编辑区） | **删除** | 弹窗没了，presets 失去载体；设置页「要素管理」tab 的快捷选项编辑区整块移除 |
| 侧栏双击直发 | **删除** | 只留单击（新建直聊会话） |
| 全局快捷键 Ctrl/Cmd+Shift+G | **删除** | `composables/keyboard.ts` 的 `isElementManagerShortcut` + ChatPanel 的 window 监听一起删 |
| 输入框按钮开弹窗 | **替换** | 改为滑入式提醒触发器，语义从「常驻入口」降格为「按需提醒」 |
| 侧栏单击开弹窗 | **替换** | 改为新建直聊会话 |
| 主 Agent 主动委派（`DelegateToElementManager`） | **保留不动** | 模型真决策路径，与本计划无关 |

## 迁移条款

**总原则：本功能未上过生产，不做任何兼容，彻底清理，不留历史包袱。** 所有「为兼容旧数据/旧配置」的保守设计一律推翻，能删就删干净。

1. **`.novai/element-manager-presets.json`**：**直接删文件**，不只是停读。提供一个一次性清理（启动时检测到该文件即删），或干脆在 W2 施工时手动删掉测试项目里的该文件、代码里彻底移除读写链。**不保留**「文件留在磁盘」的妥协形态。

2. **会话元数据 `agent` 字段**：`ChatSessionState` 新增 `agent?: 'main' | 'element-manager'`，缺省视为 `'main'`。现有 `.novel/sessions/` 下的旧会话**全部是主会话**，加字段后它们自动归为主会话，语义天然正确，**不算历史遗留，无需迁移也无需清理**。但代码里**不写**「为兼容旧会话而保留」之类的注释——`agent` 就是新会话的固有字段，旧会话恰好都是 main 而已。

3. **顺势清理开发期兼容性残留**（「干净」原则的延伸）：下列为兼容开发期旧数据而写的代码，本计划一并删除——
   - `session-store.ts` `normalizeSession` 里 `agentMessages → modelView` 的旧字段迁移逻辑（双结构时代遗物）；
   - `types/chat.ts`、`session-store.ts` 等处的「旧会话无此字段，视为空」类兼容注释（字段保留，但注释改为陈述字段本身语义，不再提「旧会话」）；
   - `.novai/` 写保护名单里的 presets 条目（随 presets 删除一并评估去留）。
   清理范围以「删掉后现有测试项目仍能正常打开」为界——凡会真实影响 test-novel 正常使用的删除，回退为保留并在施工日志记为偏差。

4. **设置页「要素管理」tab**：移除快捷选项编辑区；`getElementManagerPresets`/`saveElementManagerPresets` 及 core 的 `readElementManagerPresets`/`writeElementManagerPresets` 全部删除，不留导出。

## 波次划分

> 波次顺序按「风险递增 + 依赖方向」排：W1/W2 纯删改（低风险、独立），W3 提醒（中风险、依赖 W2 的按钮位腾空），W4 直聊（高风险、动 core、依赖前三波清理完毕）。每波独立提交、独立门禁。

### W1 —— 斜杠瘦身 + 裸发 placeholder

**范围**：
- `element-manager.ts`：`ELEMENT_MANAGER_TASK_PROMPT` 压缩为一句（见决策 1）。
- `constants/slash-commands.ts`：`/管理要素` 的 description 文案同步更新（去掉「可在其后补充参数」的旧语义，改为新交互说明）。
- 裸发 placeholder：斜杠命令落文本后，若行尾无参数，在光标处预置浅灰提示（「← 可在此补充范围/目标，留空则整理整个要素库」）。实现走 Lexical 编辑器的 placeholder 机制（输入框富文本化已有基建），不发消息、仅视觉提示。

**门禁**：`pnpm exec vitest run` 相关测试（slash-commands 测试需改断言）+ `pnpm --filter @novai/app typecheck` + `pnpm --filter @novai/core typecheck` 全绿。

**验收点**：
- 输入 `/管理要素` 后跟参数，发送后消息流显示短提示词 + 参数（不再是长文）。
- 裸发 `/管理要素`，输入框出现 placeholder 提示；直接 Enter 发送短提示词本身。
- `/生成项目记忆` 命令不受影响（INIT_NOVEL_PROMPT 不动）。

### W2 —— 删弹窗 + 删双击 + 删快捷键 + 删 presets

**范围**：
- 删 `ElementManagerTaskDialog.vue`、`element-manager-task.ts`（含各自测试）。
- 删 ChatPanel 与 ProjectView 里所有弹窗接线（`isElementManagerDialogOpen`、`loadElementManagerPresets`、`handleElementManagerConfirm`、`handleElementManagerNewSession*`、`openElementManagerSettings` 相关 emit）。
- 删 ProjectView 的 `handleElementManagerDirectNewSession`（双击）与 ActivityBar 的 `element-manager-direct` 事件。
- 删 `composables/keyboard.ts` 的 `isElementManagerShortcut` + ChatPanel 的 `handleGlobalKeydown` window 监听（含测试）。
- 删 settings-service 的 presets 读写导出 + core 的 `readElementManagerPresets`/`writeElementManagerPresets` + 设置页快捷选项编辑区 + `ELEMENT_MANAGER_PRESET_OPTIONS` 引用（若仅此处用）+ 测试项目的 `.novai/element-manager-presets.json` 文件本身 + `.novai/` 写保护名单里的 presets 条目（评估去留）。
- 输入框上方按钮与侧栏单击暂时变为**无操作占位**（W3/W4 接管），本波先把「开弹窗」的旧行为拆掉。

**门禁**：`pnpm exec vitest run` 全绿（大量删除需同步删测试）+ 双 typecheck 绿 + `pnpm build` 绿。

**验收点**：
- 全仓 grep 无 `ElementManagerTaskDialog`、`buildElementManagerTaskMessage`、`isElementManagerShortcut`、`element-manager-presets` 残留。
- 设置页「要素管理」tab 只剩模型/权限/思考档配置，无快捷选项编辑区。
- 应用启动无报错，斜杠命令仍可用（W1 成果不回退）。

### W3 —— 提醒按钮（滑入式）

**范围**：
- 阈值检测：读取 chapters 最新 mtime 与 elements 最新 mtime（或章节计数差），新增 ≥ 2 章触发。检测逻辑放 service 层（纯函数可测），UI 只读结果。
- 滑入式按钮：输入框上方工具栏「完全访问」旁，从左往右滑入动画；触发时出现，点击或关闭后退回。
- 点击行为：把提醒模板（默认 `/管理要素 对新增章节：{章节名列表}，提取要素，要求：`，`{章节名列表}` 用最近 N 章真实章节名填充）落进输入框光标处。
- 提醒模板可配置：项目配置新增字段（如 `elementManager.reminderTemplate`），设置页「要素管理」tab 加一个文本框编辑（占位 presets 编辑区腾空后的位置）。

**门禁**：`pnpm exec vitest run`（阈值检测纯函数测试 + 模板填充测试）+ 双 typecheck 绿。

**验收点**：
- 构造一个新增 2 章未整理的项目状态，输入框上方滑入提醒按钮。
- 点击按钮，模板落进输入框，`{章节名列表}` 被替换为真实章节名。
- 设置页可编辑模板，保存后下次提醒用新模板。
- 未达阈值时按钮不出现；达阈值但不点击时按钮不反复骚扰（同一状态只提醒一次，落「已提醒」标记）。

### W4 —— 直聊会话（前置依赖《角色注册机制施工计划》）

> **本波的前置地基已由《角色注册机制施工计划》承接**：会话角色字段、按角色切装配、委派会话化、确认链收进委派会话、会话列表按角色分组——这些 core 机制全部在那份计划里落地。本计划的 W4 **只做入口侧的接线**，且必须等角色机制计划完工后才能开工。
>
> **〔2026-10-22 解禁标注〕《角色注册机制施工计划》四波已全部完成**（W1–W4，含真机三链路回归；详见该计划施工日志）——**角色机制地基已就绪，本波可开工**。且角色机制 W2 落地时已把侧栏单击改为「新建要素管理员直聊会话并切换」、横幅与角色化 placeholder 也已就位（该计划 W2 施工日志），本波的实际剩余工作以「入口接线验收 + 与 W3 提醒按钮的全链路回归」为主，动工前先对照本波验收点逐条核对现状。

**范围**（仅入口接线，不含 core 机制）：
- 侧栏单击 → 调服务层新建要素管理员会话并切换过去（角色机制已提供该入口）。
- 会话列表：要素管理员会话的角色区分展示由角色机制计划承担，本波只确认入口触发正确。
- 聊天页顶部细横幅：「正在与要素管理员对话 · 仅可管理 elements/ 目录」；输入框 placeholder 换文案（如「向要素管理员描述任务…」）。

**门禁**：`pnpm exec vitest run` + 双 typecheck 绿。

**验收点**：
- 侧栏单击能从入口走到「新建要素管理员会话」。
- 直聊会话的横幅与 placeholder 文案符合角色定位。
- 主会话入口行为不受影响。

## 明确不做清单（本期排除）

1. **ELEMENT.md 内容改写**——「园丁工作守则」→「要素管理守则」是 LLM WIKI Schema 的内容问题，留下一轮。
2. **DeleteFile 放开**——删除需求继续走汇报「建议删除」。
3. **提醒的「智能触发」**——本计划只做阈值触发（新增章节数），不做「主 Agent 发现要素问题时主动建议」之外的任何 AI 驱动提醒。
4. **直聊会话的「主动汇报」**——要素管理员在直聊里被动响应用户，不做巡检/主动发起。
5. **提醒模板复用旧 presets 内容**——presets.json 直接删除，内容不读入模板。
6. **其他子智能体的直聊泛化**——本计划只落地要素管理员一个；将来新增子智能体时，`agent` 字段可扩展枚举，但泛化框架不在本期。
