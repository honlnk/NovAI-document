# 时间轴甘特图改造计划

> 状态：已完成（2026-11-21 开工并收口）：阶段 1、2 合并一笔 `8597a38`，阶段 3 OPFS 真机验收 9 项全过并修复一处布局缺陷；偏差与验收结论见文末施工日志。本计划只改时间轴弹窗的**呈现层**：把单轴时间轴换成「按故事顺序为横轴、事件动态排布到最多 6 行」的甘特视图。时间线账本、领域层、服务层、六个智能体工具、详情编辑面板均不改动。
>
> 前置：[时间线事件账本施工计划](时间线JSON化改造计划.md)已完成（含 2026-11-21 review 修复批 `7024f4d`）。概念与数据契约（标记、列表顺序即故事内顺序、区间成对标记）以该计划第三、八节为准，本文不重复。

## 一、要解决的问题

现行时间轴（`TimelineAxis.vue`，自绘 SVG）把全部标记排在一条横线上，区间画成轴上方的分轨横带。真机走查暴露三个体验问题：

1. **标题被截断**：节点下方只能放下约 5 个字（「林远离开青…」），事件一多就只能靠点开详情辨认。
2. **区间难读**：区间开始是小方块、结束是轴上一道竖线，横带与轴分离，并行与嵌套关系不直观。
3. **全部挤在一条线上**：事件越多越密，只能横向拉长。

甘特视图把每个事件画成「行里的一个条目」，标题完整写在图上，区间就是一根横条；行数随拥挤程度自动决定，封顶 6 行。

## 二、定稿决策（用户已拍板，施工不得改动）

| # | 决策 | 说明 |
| :-- | :-- | :-- |
| 1 | **横轴 = 列表顺序** | 第 N 个时间标记（point / start / end 都算）占第 N 列，与真实时间无关；不按明确时间排位、不按时长缩放。沿用决策 0008 |
| 2 | **横条规则不变** | 区间横条从开始标记所在列画到结束标记所在列，长短只表示「跨过了几个标记」，不表示时长 |
| 3 | **行与事件不绑定，动态排布** | 同一行可先后放多个横向不重叠的事件；行数由拥挤程度决定，不是一个事件一行，也不按人物分行 |
| 4 | **最多 6 行，超出则加宽列宽** | 6 行放不下时不加行，而是加大列宽后重新排布（横向滚动容纳）；唯一例外见第四节「深度兜底」 |
| 5 | **均匀分配** | 多行都能放下时选当前条目最少的行，避免全部堆在第一行 |
| 6 | **暂不允许用户拖动** | 去掉时间轴上的拖拽入口；调整事件顺序暂时只能由 AI 经工具完成 |
| 7 | **变更后整体重排** | AI 或界面的任何写入（新建、修改、删除、移动）后，基于最新账本整体重新计算排布，不做「保持原行」的稳定性优化 |
| 8 | **明确时间写在图上** | 填了 `storyTime` 的事件，在标题后以灰色小字显示（如「苍穹历·320年（春）」），并计入排布宽度 |
| 9 | **相对时间不在图上显示** | 「后 3 天」这类相对时间不画在图上，仅在详情面板显示与编辑 |
| 10 | **去掉相对时间锚点弧线** | 现行轴下方的锚点连线删除；锚定关系在详情面板查看 |
| 11 | **缩放滑块保留，语义改为「最小列宽」** | 用户可手动拉宽；自动加宽只在此基础上往宽调，永不窄于滑块设定 |

## 三、视觉规格

- **列与表头**：每个标记占一列，列中心 `x(i) = PAD_LEFT + i × step + step / 2`。图顶部一行显示列序号 1…N（灰色 11px，与现行 `ordinal` 一致）。end 标记占列但不单独绘制图形（它就是横条的右端）。
- **行**：行高 34px，行间以 0.5px 浅虚线分隔；行数 = 排布结果行数（空账本时不画行，见空态）。
- **点事件**：菱形（10px 方块旋转 45°）落在列中心，标题文字紧跟在菱形右侧（12px），有明确时间时标题后空 6px 跟灰色 11px 日期。
- **区间事件**：圆角横条，左缘 = 开始列中心 − 8px，右缘 = 结束列中心 + 8px。标题写在横条内（左内边距 8px）；**标题（含日期）比横条长时，文字越过横条右端继续写在条外**，横条本身长度不变（决策 2）。
- **颜色**：沿用现行时间轴配色——点事件与区间用同一主色系（indigo），区间横条用浅底 + 深色文字；不新增颜色语义。
- **选中态**：选中事件的菱形加外圈、横条加深色描边；点击菱形、横条或其标题文字均选中该事件（打开右侧详情），沿用 `select-event` 事件。
- **筛选命中**：不命中的条目降透明度到 0.25，不移除、不改变排布（排布与筛选无关，避免筛选时整张图跳动）。
- **空态**：0 个事件时不渲染 SVG 网格，只显示现有空态文案；修掉现行空时间轴左上角残留的一小段横线。
- **窄屏（≤480px）**：时间轴区域独立横向滚动，高度按行数自适应；详情仍纵向堆叠在下方（现行布局不变）。

## 四、排布算法（store 纯函数，单测直测）

新增纯函数 `layoutTimelineGantt(input) → { items, rowCount, step }`，替代现行 `allocateSpanLanes`。输入为按列表顺序的标记视图、最小列宽 `minStep`（滑块值）、文字测宽函数 `measure(text, fontSize)`。

**1. 条目与占位范围**（只为 point / start 生成条目；end 只提供区间右端列号）

- 点事件：`left = x(i) − 7`，`right = x(i) + 7 + 6 + 文字宽`。
- 区间事件：`barLeft = x(s) − 8`，`barRight = x(e) + 8`；`left = barLeft`，`right = max(barRight, barLeft + 8 + 文字宽 + 8)`。
- 文字宽 = 标题宽 + （有明确时间时）6 + 日期宽。

**2. 逐个放行**：条目按 `left` 升序（相同则按列表顺序）扫描。候选行 = 「该行最后一个条目的 `right` + 12px 间隙 ≤ 本条 `left`」的行；在候选行中选**条目数最少**的，再相同选**最后 `right` 最小**的，再相同选行号最小的。无候选行且当前行数 < 行数上限时开新行；否则本轮失败。

**3. 加宽重排**：本轮失败则 `step += 8` 从头重排，直到成功。

**4. 深度兜底（6 行例外）**：若同一列上「覆盖该列的区间数 + 该列是否有点事件」的最大值 `D` 超过 6（例如 7 个区间层层嵌套），无论列宽多大都排不进 6 行。此时行数上限取 `max(6, D)`。另设列宽封顶 480px：加宽到 480 仍失败时，以 480 列宽、不限行数完成排布，保证算法必然终止。

**5. 确定性**：同一输入必得同一输出（测试可断言具体行号）。

测宽实现：组件侧用 `CanvasRenderingContext2D.measureText`（字体与 SVG 文字一致）；纯函数通过参数注入 `measure`，单测注入「每字 12px」之类的固定测宽，不依赖 DOM。

## 七、验收标准

**单测（阶段 1，`stores/timeline.test.ts` 或新建 `timeline-gantt.test.ts`）**

1. 互不重叠的若干点事件（列宽足够）全部落在 1 行。
2. 两个区间重叠 → 分到 2 行；首尾不重叠的区间可复用同一行。
3. 点事件落在区间覆盖范围内 → 与该区间不同行。
4. 均匀分配：两行都可放时选条目少的行（构造可断言具体行号的用例）。
5. 标题过长：相邻两个点事件标题会相撞 → 分到不同行或触发加宽；明确时间计入宽度（有日期比无日期更早触发换行）。
6. 超过 6 行需求 → 列宽加大且行数 ≤ 6，返回的 `step` 大于输入 `minStep`。
7. `step` 永不小于 `minStep`（滑块拉宽后排布用拉宽值）。
8. 深度兜底：7 个层层嵌套的区间 → 行数 7，算法终止。
9. 区间标题比横条长：横条范围不变（右缘 = 结束列 + 8），占位范围延伸到文字末尾。
10. 空输入 → 0 行、0 条目。
11. 确定性：同一输入两次调用结果全等。

**组件测试（阶段 2，`*.test.ts` + happy-dom）**

12. 点击菱形 / 横条 / 标题文字均触发 `select-event`，且不再存在 `move-marker` 事件。
13. 选中态与筛选降透明度正确渲染；空账本不渲染网格与残留线。

**OPFS 真机清单（阶段 3，`novai-opfs-testing` 配方；本机无 `~/note/test-novel` 时按 2026-11-21 使用记录的 `repairProject` 种法自建项目）**

14. 种 20 个事件（含 3 个互相重叠/嵌套的区间、若干带明确时间的点事件）→ 行数 ≤ 6、标题完整不截断、日期灰字跟在标题后、相对时间不在图上。
15. 种 7 层嵌套区间 → 行数为 7（深度兜底），其余正常。
16. 拖动缩放滑块 → 列宽变宽、排布随之重算；拉到最小时若 6 行放不下，实际列宽自动大于滑块值。
17. 在详情里改标题（变长）→ 自动保存后整张图重排；界面新建事件 → 落在末列并重排。
18. AI 写入（无 API key 时降级：页面内直接调用 `timeline-service` 的 `createTimelinePointEvent(pid, …, 'agent')` 模拟 Agent 来源写入，触发同一变更通知链路）→ 时间轴自动重排，横向滚动位置保持。
19. 时间轴上按住标记拖动 → 无任何移动效果（拖拽入口已移除）。
20. 搜索 / 筛选 → 不命中条目变淡，排布不跳动。
21. 375 宽：时间轴横向滚动、6 行内高度正常、详情在下方可用。
22. 200 个标记种子：打开、缩放、筛选无明显卡顿（目视）。

## 八、明确不做

- **界面拖拽调整顺序**、以及替代的「前移 / 后移」按钮：本期都不做（决策 6）。
- **重排稳定性**（变更后尽量保持条目原行）：不做（决策 7）。
- **相对时间的换算与录入规范**：不在本计划（见第九节后续任务）。
- **小地图 / 概览导航、行折叠、按行分组标题**：不做。
- **时间线账本格式、领域层、服务层、六工具、详情面板的任何改动**：不做；如施工中发现必须改，先记入日志并回用户拍板。
