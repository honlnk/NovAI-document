# 章节格式调整计划

## 记录时间

2026-06-09

## 文档目的

本文档用于调整 NovAI 的章节文件格式策略。

新的约定是：

- 章节组内容改用 `txt`
- 章节正文中不主动使用特殊符号

这里的“特殊符号”主要指那些会干扰章节纯文本阅读、编辑或后续格式统一的标记字符。章节内容应尽量保持为干净、连续、便于直接创作和阅读的纯文本。

## 背景

此前 NovAI 的章节文件默认使用 `md`，这与要素文件、提示词文件的统一 Markdown 体系一致。

但在真实小说创作中，章节正文更适合采用更轻量的纯文本格式，因为：

- 用户更关注正文本身，而不是章节的格式标记
- 章节写作希望尽量避免额外符号干扰阅读流畅度
- 后续如果需要做章节正文提取、片段检索、自动排版，纯文本更容易作为稳定输入

## 核心结论

章节文件改为使用 `txt`，不再以 `md` 作为章节正文的默认格式。

## 新的章节约定

### 文件格式

- 章节文件统一使用 `.txt`
- 章节文件名仍保留章节编号与标题信息
- 章节正文保持纯文本风格

示例：

```txt
chapter-001-火中拾婴.txt
chapter-002-留他一命.txt
```

### 正文要求

- 不主动使用 Markdown 标题语法
- 不主动使用列表符号
- 不主动使用引用块、表格、代码块等结构化标记
- 正文尽量以自然段推进

### 允许保留的内容

如果章节中为了叙述效果需要少量纯文本分隔，也应尽量采用最朴素的方式，例如：

- 空行分段
- 章节编号作为文件名信息

## 与现有体系的关系

### 章节与要素的分离

章节改为 `txt` 不影响要素体系继续使用 `md`。

建议保留如下分工：

- `chapters/`：章节正文，使用 `txt`
- `elements/`：人物、地点、实体、剧情、时间线、世界观等要素，继续使用 `md`
- `prompts/`：提示词配置，继续使用 `md`

### 为什么章节不和要素同格式

章节正文是连续创作文本，重点在阅读流畅和生成一致性。

要素文件则更像结构化知识卡，重点在可检索、可更新、可对比。

所以两者的最优文件格式并不相同。

## 对开发的影响

### 需要调整的部分

1. 标准项目结构中 `chapters/` 的文件类型约定。
2. 文件扫描与预览逻辑对章节 `.txt` 的支持。
3. Agent 写章节时的默认输出格式。
4. 章节生成、续写、修改流程中对纯文本的处理方式。
5. 章节解析、要素提取、RAG 上下文装配时对 `txt` 章节的读取支持。

### 不需要调整的部分

- `elements/` 目录结构
- `prompts/` 提示词文件格式
- 项目配置文件格式
- RAG 索引与要素文件主结构

## Agent 行为要求

后续 Agent 在写章节时应遵守：

1. 默认输出 `txt` 章节文件。
2. 章节正文避免出现 Markdown 结构符号。
3. 若用户明确要求特定格式，再按用户指令调整。
4. 章节内容完成后，可继续从纯文本中提取要素并写入 `elements/`。

## 实施计划

### Step 1：章节目录格式切换

将章节默认文件扩展名从 `.md` 切换为 `.txt`。

### Step 2：读取与预览适配

确保文件树、右侧预览、正文查看都能正确打开 `txt` 章节。

### Step 3：写入链路适配

让 Agent 默认创建和编辑 `txt` 章节，而不是 Markdown 章节。

### Step 4：要素提取兼容

保证从 `txt` 章节提取人物、地点、剧情、时间线、实体时不依赖 Markdown 标记。

### Step 5：历史项目兼容策略

旧项目里的 `.md` 章节可以先兼容读取，不强制立即迁移。

后续可提供整理工具，在用户确认后批量改名为 `.txt`。

## 验收标准

当前落地状态：

1. 新建项目与 Agent 创建章节时默认使用 `chapters/*.txt`。
2. 工具层会拒绝新建或移动到 `chapters/*.md`。
3. 旧项目里的 `.md` 章节可继续读取、预览、计数、参与近期章节上下文，并可通过 `RenameFile` 迁移为 `.txt`。
4. 要素提取链路可直接从 `txt` 章节读取文本，也兼容旧 `.md` 章节。

后续仍待补齐（已拆分到独立计划）：

1. **章节命名规范** + **旧项目批量整理工具**：见 [章节命名规范与整理工具计划](章节命名规范与整理工具计划.md)。统一命名为 `第NNN章-标题.txt`，工具层格式校验 + 重号检测，EditFile 对称强制，配套批量整理工具。
2. **生成结果结构化处理**：章节写完后的后处理链路（计数刷新、自动打开变更文件、章节级元数据），属另一条待办，暂未立独立计划。
