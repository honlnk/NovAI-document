# 时间线 JSON 化改造计划

> 状态：占位，待讨论
>
> 背景：时间线目前以纯 Markdown 记录，结构化程度不足以支撑可靠的时间推理。
>
> 核心想法：时间线改用 JSON 格式记录，让"事件发生在什么时间、持续多久、与哪些事件有先后/重叠关系"成为可计算的数据，而不是靠模型从自然语言里猜。

## 待讨论

- JSON Schema 设计：事件对象包含哪些字段？（时间点/时间段、参与人物、地点、关联事件、因果链？）
- 时间表达方式：绝对时间（"第三纪元 3021 年春"）vs 相对时间（"第 15 章后第 3 天"）vs 混合？
- 与现有 timeline/*.md 的迁移策略：一次性迁移、双写过渡、还是新建项目才用 JSON？
- Agent 读取方式：直接读 JSON 文件，还是通过专用查询工具（如"查询某时间窗口内所有事件"）？
- 与向量检索的关系：JSON 化后时间线是否还进入 Orama 索引？
- 可视化：时间轴视图是否必要？
