# 要素召回渐进式披露施工计划

## 记录时间

2026-10-23 定稿。

## 文档性质

本文档是**施工计划**，是「要素召回机制重构」（决策 `docs/decisions/0007-要素召回机制重构-从RAG单通道到渐进式披露.md`）的落地执行依据。施工按 W1–W4 四个波次推进，每波带门禁；验收结论与偏差记录随施工追加在文末施工日志。

## 目标

把 characters / locations / entities / worldbuilding 四类要素的召回从「LLM 自主调 RagSearch」改为「渐进式披露」：

- **L1 目录**：所有要素的 `type + name + summary` 清单，作为 user 角色 reminder 紧跟 system prompt 注入，digest 驱动原位替换
- **L2 加载**：新增 `LoadElements` 工具，模型按需批量加载要素完整正文
- **RAG 收窄**：RagSearch 只检索 plots / timeline 两类，索引范围同步收窄

参考系：dsh `packages/skill/`（见决策 0007「参考系」一节）。

## 已拍板决策（施工不可更改）

> 完整论据见决策 0007。这里只列施工必须遵守的硬约束。

1. **目录只放稳定信息**：`type + name + summary`，**不含** `lastUpdatedChapter`、内容 hash、mtime 等任何版本标记。
2. **不做版本追踪、不做变更推送**：要素正文变了，不在历史里追加新 reminder，也不修改旧 tool result。模型靠历史消息追踪状态变化。
3. **目录消息结构**：user 角色 + `<system-reminder>` 包裹 + 紧跟 system（index 1）+ digest 驱动原位替换。完全复用 `syncNovaiReminder` 的既有模式。
4. **LoadElements 支持批量**：`{ names: string[] } → ElementContent[]`。
5. **RAG 收窄范围**：`elements/plots/**/*.md` + `elements/timeline/**/*.md`，其余四类从索引中移除。
6. **不做 @要素名 手势、不做 Router skill、不做 element-manager 工作流改动**。
7. **element-manager 提示词补强**：写 summary 时明确「只写稳定身份定义，不写随章节变化的状态」——这是目录 digest 稳定的前提。

## 范围外（本计划明确不做）

- chapters/*.txt 召回（现状如此，本计划不改）
- `@要素名` 输入框手势
- 变更推送机制（方案三）
- 版本号/hash 进目录（方案二）
- element-manager 子智能体内部流程改造
- RAG 算法本身的调优（rerank、chunk 切分策略等）

## 波次门禁

### W1 - core 目录扫描与 catalog 数据层

**目标**：产出"扫 elements/ → 生成 catalog entries → 算 digest"的纯函数层，不带 UI、不带注入。

**任务**

1. 新建 `packages/core/src/core/elements/catalog.ts`：
   - `scanElementCatalog(tree: TreeNode[]): ElementCatalogEntry[]`：扫 `elements/characters|locations|entities|worldbuilding/**/*.md`，**跳过 plots/timeline**，对每个文件读 frontmatter（复用 `parser.ts` 的 `parseElementFile`），产出 `{ type, name, summary }`
   - `digestElementCatalog(entries: ElementCatalogEntry[]): string`：对 entries 数组算 sha256（照搬 dsh `tool-skill/src/index.ts:330-337` 的做法——`JSON.stringify([name, summary])` 每行拼接再 hash）
   - 类型 `ElementCatalogEntry` 定义在 `packages/core/src/types/elements.ts`（与 `ElementFrontmatter` 并列）
2. 单测 `catalog.test.ts`：
   - 扫描四类目录，跳过 plots/timeline
   - frontmatter 缺 summary 时的兜底（用 name 或跳过该条，定稿时选一个）
   - digest 对条目数量、name、summary 敏感；对文件正文、mtime 不敏感

**门禁**

- `pnpm test` 全绿
- `pnpm --filter @novai/core typecheck` 通过
- 单测覆盖上述三条用例

### W2 - 目录注入：reminder 模式复用

**目标**：把 W1 产出的 catalog 注入到 Agent 循环的 ModelView，机制完全对齐 `syncNovaiReminder`。

**任务**

1. 新建 `packages/core/src/core/agent/element-catalog-reminder.ts`：
   - `buildElementCatalogReminder(entries: ElementCatalogEntry[]): string`：产出 `<system-reminder>` 包裹的 Markdown 清单文本
   - `syncElementCatalogReminder(input: { view, entries }): void`：digest 判定 → 原位替换 / 插入 / 不动（复用 `insertAfterSystem` 和 `replaceMessage`）
   - 文案定稿（首注）：

     ```
     <system-reminder>
     以下是本书的要素清单（角色/地点/实体/世界观设定），按类型分组：

     <available_elements>
     - [角色] 林晚 — 冷静克制的外科医生，隐藏身份是前特工
     - [地点] 临江医院 — 故事主舞台，地下三层有秘密实验室
     ...
     </available_elements>

     当你需要使用某个要素的完整定义时，调用 LoadElements 工具并传入其名称。本清单只包含摘要，不要在未加载完整定义前凭空推断要素细节。
     </system-reminder>
     ```

2. 接到 Agent 循环：在 `packages/core/src/core/agent/query.ts` 的合适位置（参照 `syncNovaiReminder` 的调用点）调用 `syncElementCatalogReminder`
3. 单测：
   - 首次注入位置正确（index 1，system 之后）
   - digest 不变时不替换
   - digest 变时原位替换（消息对象 id 保持）
   - reminder 被压缩吞掉后，下一次 sync 能检测缺失并重新插入

**门禁**

- `pnpm test` 全绿

### W3 - LoadElements 工具

**目标**：给主 Agent 一个批量加载要素完整正文的工具。

**任务**

1. 新建 `packages/core/src/core/tools/load-elements.ts`：
   - 工具名 `LoadElements`，schema `{ names: string[] }`
   - execute：按 names 在四类目录下定位文件（`{type}/{name}.md`，name 匹配 frontmatter 的 name 字段），读完整文件，返回数组
   - 未知名称：在结果里明确标记 `notFound: true`，不抛错（让模型自己处理，与 dsh 一致）
   - 输出 render：`<element_content name="..." type="...">...</element_content>` 格式（仿 dsh `renderSkillContent`）
2. 注册到主 Agent 工具集（`packages/core/src/core/agent/tools.ts`）
3. 改 `prompt.ts:69` 的 RagSearch 规则，变成两条：

   ```
   - LoadElements：批量加载角色/地点/实体/世界观要素的完整定义。当上下文的要素清单中出现与当前任务相关的要素时，先用本工具加载再写作。
   - RagSearch：从情节（plots）和时间线（timeline）索引中语义检索剧情线索与章节事件。返回的 sourcePath 可用于 ReadFile 精读。
   ```

4. 单测：
   - 单个/批量加载
   - 未知名称的容错
   - 工具结果格式符合 `<element_content>` 规范
