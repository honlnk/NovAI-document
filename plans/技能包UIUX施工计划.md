## 一、目标

1. 作者能在界面上看到项目里有哪些技能、每个技能是否被 AI 看见；看不见的写明原因。
2. 作者能查看与编辑技能文件，能新建空白技能、导入本地技能文件夹、让 AI 代写技能。
3. 作者能在输入框用 `@技能名` 点名本条消息要用的技能。
4. 对话里 AI 加载技能的过程一眼可读。

## 三、契约

### 3.1 技能服务（`packages/core/src/services/skill-service.ts`，新增）

服务层桥接，内部调用 `discoverSkills` 与 project-fs，不改领域层：

- `listSkills(projectId)` → `{ skills: SkillView[]; broken: BrokenSkillView[] }`
  - `SkillView`：`name`、`displayName?`、`description`、`whenToUse?`、`directory`、`skillFilePath`、`files: { path; size; kind }[]`、`filesOmitted?`、`warnings: { code; message }[]`。
  - `BrokenSkillView`：被跳过的技能——`name`（文件夹名）、`directory`、`reason`（人话）、`code`。
  - 诊断按 `skillName` 归到对应技能；无法归属的诊断（如 SKILL.md 读失败）按文件夹名归入 broken。
- `createBlankSkill(projectId, folderName)` → 新建 `skills/<folderName>/SKILL.md`（模板见 3.4）。文件夹已存在则报错「已有同名技能」，不覆盖。
- `importSkillFolder(projectId, sourceHandle)` → 把用户选中的本地文件夹整体复制为 `skills/<源文件夹名>/`。
  - 源文件夹根下必须有 `SKILL.md`，否则拒绝并提示「所选文件夹不是技能包（缺少 SKILL.md）」。
  - 目标已存在：拒绝并提示改名后重试（本期不做覆盖/合并）。
  - 只复制，不解析不执行；脚本文件原样复制（清单里会标已忽略）。
  - 文件数超过底层清单上限（200）照样复制，诊断由发现层给出。
- `deleteSkill(projectId, name)` → 删除 `skills/<name>/` 整个文件夹。
- 写操作完成后触发项目文件刷新（与现有文件操作同一刷新通道），技能列表随之重算。

### 3.2 技能分类面板（`components/category/SkillList.vue`，新增）

- 顶部操作：「新建技能」「导入文件夹」「让 AI 写」。
- 列表：每个技能一行——名称（frontmatter name 与文件夹名不同时以文件夹名为主、副标显示 frontmatter name）、一句描述（两行截断）、附属文件数、warning 标记。点击展开文件清单；清单首项是 SKILL.md。
- 文本文件点击后在右侧文件详情打开；脚本/不支持文件灰显不可点（决策 7）。
- broken 技能排在列表末尾，灰显，行内直接显示原因，例如「缺少描述，AI 看不到这个技能。打开 SKILL.md 补上 description 即可」；SKILL.md 可点开修复。
- 行尾更多菜单：删除技能（二次确认，文案写明「将删除 skills/<名> 整个文件夹，不可撤销」）。
- 空状态：说明技能是什么（可复用的写作方法，AI 在任务相符时自动加载，或你用 `@技能名` 点名），并给出三个获取入口。
- 刷新：随项目文件树刷新重算（AI 通过文件工具改动技能后列表同步）。

### 3.3 `@技能` 输入

- 弹层：现有 `@` 弹层（`OutlineCommandPopover`）扩展为两组，或新建合并弹层；筛选词同时过滤两组；键盘上下跨组导航。只列合格技能，broken 技能不出现。
- 选中技能：用 `@技能名 ` 替换光标前的 `@筛选词`，标签着色（`TextRefKind` 新增 `skill`，lexicon 新增 skill 名单）。
- 发送展开：草稿中每个命中技能名单的 `@技能名`（同名去重，保持出现顺序）汇总为一句追加到发给模型的文本末尾：
  `（作者点名使用技能：去AI味、文风仿写。请先用 LoadSkill 逐个加载，再按技能方法完成本条请求。）`
  `displayLabel` 为原草稿。斜杠命令展开与技能展开可同时存在，技能句追加在展开结果之后。
- 名字冲突：已选中的大纲不会在草稿留下 `@` 文字，所以草稿中的 `@X` 一律按技能识别；技能名单里没有的 `@X` 不展开、不着色。
- 排队消息编辑重推导：QueueDock 编辑后按同一规则重新展开。

### 3.4 空白技能模板

```markdown
---
name: <文件夹名>
description: 一句话说明这个技能做什么、什么时候该用（AI 靠这句话决定是否加载）
---

# <文件夹名>

## 适用场景

## 方法步骤

1.

## 注意事项
```

新建后立即在右侧打开 SKILL.md 进入编辑。模板里的 description 是占位文字，作者不改也合格——不做特殊拦截（作者自负其责，列表上能看到这句描述）。

### 3.5 「让 AI 写」

点击后在输入框预填（不自动发送）：`请在 skills/ 下帮我新建一个技能：`，光标落在末尾，作者补充需求后发送。AI 走通用文件工具写入，受确认卡与写权限档位管辖（底层计划决策 9）。

### 3.6 对话中的 LoadSkill 工具行

`ToolCallRow` 对 LoadSkill 给专属摘要：
- 不带 file：`加载技能 · <name>`
- 带 file：`读取技能文件 · <name> / <file>`（有分页时附 `第 N 行起`）
- 失败（not-found / unavailable）沿用现有失败行：显示错误首行。

## 六、验收矩阵

| 场景 | 预期 |
| :-- | :-- |
| 无 `skills/` 的项目 | 技能分类显示空状态与三个入口；其余界面无变化 |
| 有一个缺 description 的技能 | 列表末尾灰显，原因可读；补上描述后自动变为合格 |
| 技能含脚本 | 清单中灰显标「已忽略」，不可打开 |
| 导入同名技能 | 拒绝并提示改名，原技能不受影响 |
| 让 AI 新建技能 | 弹确认卡，同意后列表出现新技能 |
| `@去AI味 帮我改这段` | 气泡显示原文；模型收到点名句并调用 LoadSkill；工具行显示「加载技能 · 去AI味」 |
| `@` 弹层 | 大纲组与技能组同时可见、行为说明清楚；选大纲照旧激活 |

## 七、明确不做

- 技能启停、版本管理（决策 4）。
- 压缩包导入、粘贴导入、技能市场、远程拉取、全局技能目录。
- 导入时覆盖或合并同名技能。
- 任何 core 领域层或 Agent 链路改动（含「直接注入技能正文」）。
- 技能详情专属布局（决策 6）。

## 八、方案形成记录

### 2026-11-22：UI/UX 方向讨论

- `@技能` 两种方案对比：提示式（core 不改、加载过程可见、偶尔多一轮调用）vs 直接注入（最可靠但需 core 显式加载路径与去重）。用户拍板提示式。
- 底层计划阶段 4 真机已证明真实模型会按目录主动调用 LoadSkill，提示式的可靠性有实证基础。
- 现状核对：`@` 已用于激活大纲（选中后清掉 token、跨消息生效），技能点名语义不同，故有决策 2；`displayLabel` 显示/指令分离已存在，提示式无需 core 改动。
