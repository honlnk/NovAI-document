- 上游：《[技能包体系设计构想](技能包体系设计构想.md)》（定位与红线）、《[技能包底层能力施工计划](技能包底层能力施工计划.md)》（core 已完成：技能发现与诊断、技能目录 reminder、LoadSkill、AI 经通用文件工具管理技能）。

- 前置依赖：写入确认卡在 CreateFile 新建文件时「同意写入」被矛盾警告禁用的缺陷（底层计划阶段 4 真机发现）——已于父仓 ab622d1 修复（测试覆盖，真实模型批准链未真机复测）。阶段 2 的「让 AI 写技能」真机验收顺带完成该复测。

## 一、目标

1. 作者能在界面上看到项目里有哪些技能、每个技能是否被 AI 看见；看不见的写明原因。
2. 作者能查看与编辑技能文件，能新建空白技能、导入本地技能文件夹、让 AI 代写技能。
3. 作者能在输入框用 `#技能名` 点名本条消息要用的技能。
4. 对话里 AI 加载技能的过程一眼可读。

## 三、契约

### 3.1 技能服务（`packages/core/src/services/skill-service.ts`，新增）

服务层桥接，内部调用 `discoverSkills` 与 project-fs，不改领域层：

- `listSkills(projectId)` → `{ skills: SkillView[]; broken: BrokenSkillView[] }`
  - `SkillView`：`name`、`displayName?`、`description`、`whenToUse?`、`directory`、`skillFilePath`、`files: { path; size; kind }[]`、`filesOmitted?`、`warnings: { code; message }[]`。
  - `BrokenSkillView`：被跳过的技能——`name`（文件夹名）、`directory`、`reason`（人话）、`code`。
  - 诊断按 `skillName` 归到对应技能；无法归属的诊断（如 SKILL.md 读失败）按文件夹名归入 broken。
- `createBlankSkill(projectId, folderName)` → 新建 `skills/<folderName>/SKILL.md`（模板见 3.4）。文件夹已存在则报错「已有同名技能」，不覆盖。
- `scanImportSource(sourceHandle)` → 判定所选文件夹是单个技能（根下有 SKILL.md）还是技能合集（一级子文件夹含 SKILL.md），返回候选列表 `{ folderName; hasConflict }[]`；两者都不是则报「所选文件夹里没有找到技能包（缺少 SKILL.md）」（决策 12）。
- `importSkills(projectId, sourceHandle, folderNames)` → 把选中的候选逐个整体复制为 `skills/<文件夹名>/`，返回每个的成功/跳过结果。
  - 目标已存在：跳过并标「同名已存在」（本期不做覆盖/合并）。
  - 只复制，不解析不执行；脚本文件原样复制（清单里会标已忽略）。
  - 文件数超过底层清单上限（200）照样复制，诊断由发现层给出。
- `deleteSkill(projectId, name)` → 删除 `skills/<name>/` 整个文件夹。
- 写操作完成后触发项目文件刷新（与现有文件操作同一刷新通道），技能列表随之重算。

### 3.2 技能分类面板（`components/category/SkillList.vue`，新增）

- 头部：「已安装技能 · N」，右侧「刷新」「导入」「新建 ▾（空白技能 / 让 AI 写）」；技能多于 8 个时显示搜索框（决策 11）。
- 列表：每个技能一行——名称（frontmatter name 与文件夹名不同时以文件夹名为主、副标显示 frontmatter name）、一句描述（两行截断）、附属文件数、warning 标记。点击展开文件清单；清单首项是 SKILL.md。
- 文本文件点击后在右侧文件详情打开；脚本/不支持文件灰显不可点（决策 7）。
- broken 技能排在列表末尾，灰显，行内直接显示原因，例如「缺少描述，AI 看不到这个技能。打开 SKILL.md 补上 description 即可」；SKILL.md 可点开修复。
- 行尾更多菜单：删除技能（二次确认，文案写明「将删除 skills/<名> 整个文件夹，不可撤销」）。
- 空状态：说明技能是什么（可复用的写作方法，AI 在任务相符时自动加载，或你用 `#技能名` 点名），并给出三个获取入口。
- 刷新：随项目文件树刷新重算（AI 通过文件工具改动技能后列表同步）。

### 3.3 `#技能` 输入

- 弹层：新增 `SkillCommandPopover`，与 `@` 大纲弹层、`/` 斜杠菜单同构（触发规则：`#` 在行首或空白后，`#` 到光标间无空白；Markdown 标题 `# 标题` 因 `#` 后紧跟空格不触发）。列出合格技能的名称与一句描述，筛选词过滤名称与描述；broken 技能不出现；无技能时弹层显示「还没有技能，可在左侧「技能」中新建或导入」。
- 选中技能：用 `#技能名 ` 替换光标前的 `#筛选词`，标签着色（`TextRefKind` 新增 `skill`，lexicon 新增 skill 名单，`scanTextRefs` 识别 `#` 触发符）。
- 发送展开：草稿中每个命中技能名单的 `#技能名`（同名去重，保持出现顺序）汇总为一句追加到发给模型的文本末尾：
  `（作者点名使用技能：去AI味、文风仿写。请先用 LoadSkill 逐个加载，再按技能方法完成本条请求。）`
  `displayLabel` 为原草稿。斜杠命令展开与技能展开可同时存在，技能句追加在展开结果之后。
- 名单外的 `#X`（如作者写的话题标签）不展开、不着色。
- 排队消息编辑重推导：QueueDock 编辑后按同一规则重新展开。

### 3.4 空白技能模板

```markdown
---
name: <文件夹名>
description: 一句话说明这个技能做什么、什么时候该用（AI 靠这句话决定是否加载）
---

# <文件夹名>

## 适用场景

## 方法步骤

1.

## 注意事项
```

新建后立即在右侧打开 SKILL.md 进入编辑。模板里的 description 是占位文字，作者不改也合格——不做特殊拦截（作者自负其责，列表上能看到这句描述）。

### 3.5 「让 AI 写」

点击后在输入框预填（不自动发送）：`请在 skills/ 下帮我新建一个技能：`，光标落在末尾，作者补充需求后发送。AI 走通用文件工具写入，受确认卡与写权限档位管辖（底层计划决策 9）。

### 3.6 对话中的 LoadSkill 工具行

`ToolCallRow` 对 LoadSkill 给专属摘要：
- 不带 file：`加载技能 · <name>`
- 带 file：`读取技能文件 · <name> / <file>`（有分页时附 `第 N 行起`）
- 失败（not-found / unavailable）沿用现有失败行：显示错误首行。

## 八、方案形成记录

### 2026-11-22：UI/UX 方向讨论

- `@技能` 两种方案对比：提示式（core 不改、加载过程可见、偶尔多一轮调用）vs 直接注入（最可靠但需 core 显式加载路径与去重）。用户拍板提示式。
- 底层计划阶段 4 真机已证明真实模型会按目录主动调用 LoadSkill，提示式的可靠性有实证基础。
- 现状核对：`@` 已用于激活大纲（选中后清掉 token、跨消息生效），技能点名语义不同，故有决策 2；`displayLabel` 显示/指令分离已存在，提示式无需 core 改动。

### 2026-11-22：用户确认与 ZCode 页面对照

- 用户确认决策 3、4、5、10；触发符改为 `#`（`@` 已用于大纲，不复用），推翻初稿「`@` 弹层分两组」方案。
- 对照 ZCode v3.18.2 `packages/ui/src/settings/SkillsSection.tsx`：技能页在设置里，行 = 图标 + 名称 + 一行描述 + 启停开关 + 删除；分组标题带数量与「刷新/导入/新建」；空状态给「新建 / 导入」；详情为只读元信息弹窗；顶部可展开诊断横幅；「新建」= 开一个带 skill-creator 技能点名的新任务（AI 写）；导入对话框扫描外部 Agent 技能目录、批量勾选、标「目录已存在 / 同名已存在」；聊天里用 `$skill-name` 点名。吸收为决策 11–13，不照搬项见决策 14。
- 技能广场后端：参照 linkseek 先例（独立仓库、不做子模块，跨仓施工计划写在本文档仓库）放独立 git 仓库；客户端浏览与安装界面属 NovAI，另立计划。

### 2026-11-22 阶段 0：技能服务

- 落地 `packages/core/src/services/skill-service.ts` 与 `services/types.ts` 视图类型（SkillView / BrokenSkillView / SkillImportScanView / SkillImportOutcomeView 等），`services/index.ts` 注册 `skillService` 命名空间导出。18 项单测（无 skills/、好坏并存、warning 归属、broken 人话原因、新建模板/重名/非法名、单技能与合集扫描导入、同名跳过、缺 SKILL.md、整夹删除、不存在删除）全过；全量 138 文件 1761 用例 + typecheck 全绿。
- 契约偏差（签名）：`scanImportSource` 补 `projectId` 首参——计划契约只写 `scanImportSource(sourceHandle)`，但候选的 `hasConflict` 必须对照目标项目 `skills/` 现状，无项目上下文无法判定。
- 契约偏差（字段）：`BrokenSkillView` 在计划三字段（name/directory/reason/code）之外补 `skillFilePath?`——§3.2 要求 broken 技能的 SKILL.md 可点开修复，取自诊断的 path。
- 实现决策：broken 的 `reason` 按诊断码映射为「人话 + 修复动作」（如 skill_missing_description →「缺少描述，AI 看不到这个技能。打开 SKILL.md 补上 description 即可」），不复用发现层面向开发者的 message（skill_read_failed 例外，保留原始错误信息）。
- 实现决策：导入复制跳过点开头条目（.DS_Store 等）——发现与清单层都不见它们，复制只浪费空间；「整体复制」语义按「AI 可见的包内容」执行。文件按二进制流复制（脚本原样、不解析）。
