# Agent 主动提问工具计划

## 文档状态

- 记录日期：2026-11-03。
- 当前状态：**已形成独立计划，尚未开工**。
- 本文档是该功能的独立设计与施工依据。动工前须获得用户批准；开工后将状态改为「进行中」，按阶段记录验收、偏差和提交信息，完成后改为「已完成」。

## 背景

Agent 已经能够在普通回复中向用户提问，但这种方式会结束当前回复，用户需要再次发送消息才能继续。缺少一种在任务执行中途暂停、获得用户答案并继续原任务的正式交互。

主动提问工具填补这一空白。它服务创作协作，不是文件写入的权限确认，也不替代一般聊天中的自由提问。

参考 DeepSeek Harness 的 `interaction/tool-ask-user`，但只借鉴「工具暂停、用户作答、答案作为工具结果返回」的交互形状，不引入其插件框架或事件溯源存储。

## 目标与边界

1. 仅向主智能体提供主动提问工具，工具名为 `AskUserQuestion`。
2. 当继续当前任务确实需要用户决策或补充信息时，Agent 可提出一个结构化问题。
3. 问题支持单选、多选和自由文本补充，答案回到原 Agent Loop，作为该工具的结果继续当前任务。
4. 提问在聊天消息流中显示为独立卡片，不折叠进普通工具过程。
5. 普通聊天提问继续存在：闲聊、一般讨论和非阻塞问题仍用普通文本；需要等待答案才能继续原任务时才使用工具。
6. 提问不是写入前的强制步骤，不新增「先声明、再确认」等写操作原则，也不改变现有权限与文件确认机制。

## 工具契约

### 输入

一次调用只提出一个问题，字段如下：

| 字段 | 是否必填 | 含义 |
| :-- | :-- | :-- |
| `question` | 是 | 简洁、具体的问题正文 |
| `header` | 否 | 短标题，例如「剧情方向」 |
| `options` | 否 | 候选项，每项包含短标签和一句影响说明；有推荐项时排在首位，并在标签末尾标注「推荐」 |
| `multiSelect` | 否 | 是否允许多选，默认单选 |

候选项用于降低选择成本，不限制用户只能从这些答案中选择。问题应能在项目上下文中理解，避免要求用户重复已经提供的设定。

### 输出

工具返回结构化结果，至少包含：

- 所选候选项标签的数组；
- 用户补充的自由文本；
- 本次回答的结局：已回答、已取消。

答案以明确的工具结果文本进入模型视图，使 Agent 能据此继续当前任务。工具结果不包含文件变更，也不产生写入确认。

### 输入校验

1. 问题正文去除首尾空白后不能为空。
2. 候选项标签不能为空，也不能重复；影响说明可以为空。
3. 至少选择一个候选项或填写非空补充文本才可提交；不提供空答案。
4. 多选时必须保留完整选择集合，不能只返回最后一项。
5. 非法参数由工具返回可理解错误，让模型修正后重试，不中断整个会话。

## 交互设计

### 提问卡片

1. 卡片显示在提问工具调用的消息位置，普通工具行保留为过程记录。
2. 卡片显示短标题（若提供）、问题正文、候选项及影响说明。
3. 候选项使用单选或多选控件；多选项允许不选择任何选项。
4. 卡片提供「补充说明」多行文本框，允许只填写文本而不选择候选项，也允许同时选择并补充。
5. 主按钮为「提交回答」，次要按钮为「跳过问题」。没有候选项也没有补充文本时，提交按钮禁用。
6. 提交期间禁用重复提交；提交成功后卡片变为只读，展示所选答案与补充说明。
7. 卡片使用中性界面样式，与警示色的文件写入确认卡明确区分；使用现有的消息与工具区域，不新增弹窗或全局入口。
8. 提问消息与卡片不进入默认折叠的工具过程组；会话切换或重新读取历史后，问题、答案和结局仍可见。

### 等待期间的操作

| 操作 | 行为 |
| :-- | :-- |
| 提交回答 | 解除当前工具等待，原任务从该工具结果继续 |
| 跳过问题 | 返回明确的取消结果，Agent 可在不获得答案的情况下调整后续处理 |
| 停止运行 | 结束本次提问等待，标记为取消，保留当前会话与未消费队列，不自动继续 |
| 普通输入 | 作为对当前问题的自由文本回答提交，不创建新的用户轮次；输入框保留用于必要补充说明 |
| 排队与编辑队列 | 保留现有入口；排队内容在回答后继续按原顺序处理 |
| 插话 | 优先作为当前问题的补充回答；若用户要终止问题或改变任务，使用「跳过问题」或「停止运行」后再发送 |
| 切换会话 | 保留等待状态，返回该会话后可继续回答；会话列表显示待回答标记 |

普通输入直接回答当前问题后，输入框和待回答状态恢复为通常的聊天形态。实现时可复用现有收件箱的输入接收方式，但不能把答案包装成与工具调用并列的新任务，导致一次回答被执行两次。

### 停止、异常与刷新

1. 工具等待期间不自动超时，也不默认替用户选择。
2. 停止、删除会话或运行异常时，必须清理对应的等待回调和待回答标记，不能遗留不可操作的卡片。
3. 页面刷新或项目重新打开后，**不自动恢复原工具调用或续跑**。历史中的问题保持可见，未回答的卡片标记为「等待已中断，请继续发送消息让 Agent 接着处理」，不能再提交旧等待请求。
4. 后续用户消息启动正常的新一轮处理；Agent 可从持久化的问题记录和当前任务上下文继续。无需把尚未完成的旧工具调用重新挂回模型历史。
5. 本期不承诺从模型调用中断点无损恢复；恢复能力如需提升，另立会话恢复计划。

## 角色、权限与生命周期

1. 主智能体的直聊会话可以使用主动提问工具。
2. 要素管理员直聊和独立委派会话**不使用**该工具。委派任务需要补充信息时，向主智能体汇报；主智能体决定是否询问用户。
3. 提问不走文件写入权限判断，不修改文件，也不进入文件变更账本。
4. 工具等待时运行仍归属原会话；待回答状态不得被误记为已完成，也不得阻塞其他会话。
5. 工具按现有顺序执行语义运行，一次只处理一个提问，不为并行提问设计额外队列。

## 实现方向

1. 在会话层组装提问工具：它依赖当前会话的提问回调，不作为只依赖项目文件系统的纯工具注册。
2. 在核心类型与服务契约中定义问题、候选项、答案和结局；通过服务事件向界面提供待回答请求及快照，不暴露内部回调。
3. 应用层新增提问卡片，并接入回答、取消、停止和会话切换；不从组件直接操作 Agent Loop。
4. 将问题、所选答案和取消结局作为可持久化的会话消息保存，供聊天历史和界面恢复使用。
5. 复用现有会话状态与事件路由，避免另建跨项目的全局提问状态；如现有「等待用户」语义不足以区分运行收敛和等待回答，按实际行为细化服务视图与状态同步。
6. 仅补充与主动提问相关的提示词和工具说明，不重写主提示词体系。

具体文件与内部接口由施工方按上述边界选择，并在施工日志中记录；不得把界面交互、生命周期或角色范围的取舍留给施工方自行决定。

## 分阶段施工与门禁

### 第一阶段：工具与会话等待闭环

**任务**

1. 实现问题、答案及结局的输入输出和校验。
2. 将提问回调接入主智能体会话，保持工具调用与结果的协议配对。
3. 建立会话归属的待回答请求、回答与取消链路。
4. 保存提问记录和答案；处理停止、删除、异常及重复回答。

**门禁**

- 全量测试通过，全项目类型检查通过。
- 测试覆盖单选、多选、纯文本、选择与文本并存、跳过、停止和重复回答。
- 测试覆盖切换会话后答案仍路由到原请求，以及错误会话不能回答。
- 以事件顺序测试验证「提问 → 等待 → 回答 → 原任务继续」和「提问 → 停止 → 不再继续」。
- 文档记录本阶段验收、偏差；完成并获准提交后补充实际提交哈希。

### 第二阶段：聊天卡片与输入协作

**任务**

1. 实现独立提问卡片及提交后的只读历史。
2. 实现待回答标记、普通输入作答、排队、插话与停止的既定行为。
3. 实现页面重新打开后的中断提示与旧请求禁用。
4. 保持普通工具轨迹、文件确认和变更面板现有行为。

**门禁**

- 全量测试、全项目类型检查与应用构建通过。
- 使用常驻测试项目 `~/note/test-novel`，通过现有开发服务 `http://localhost:5173` 真机验收；不得另起开发服务器或写入仓库中的真实密钥。
- 若内置浏览器无法授予目录权限，采用《真机测试 OPFS 仿真目录方案》进行全真验证。
- 真机覆盖剧情选择、自由补充、多选、跳过、切换会话后回答、停止、刷新及排队后续处理。
- 验证提问不会写入项目文件，也不会被折叠到不可发现的过程组中。
- 文档记录本阶段验收、偏差；完成并获准提交后补充实际提交哈希。

### 第三阶段：回归与结项

**任务**

1. 回归四种对话协议下的工具调用和回答回传；真实端点不可用的情况使用协议夹具验证，并明确列出未覆盖的真实供应商。
2. 回归普通聊天提问、文件写入确认、要素管理员直聊和委派，确认角色边界没有扩张。
3. 更新 UI 协作接口契约、当前进度及本计划状态；本计划的施工日志在阶段门禁处同步落盘。
4. 按核心工具闭环、界面协作两个逻辑单元分别提交；文档随结项统一提交，先提交文档子模块再更新父仓库指针。提交前须取得用户批准，不执行推送。

**验收标准**

- 用户能用选项或文字回答，Agent 在原任务中使用答案继续工作。
- 多选答案完整保留，取消与停止不会留下永久等待或误续跑。
- 会话切换、刷新和异常后的界面状态可理解、可操作。
- 要素管理员不能直接向用户发起该工具提问。
- 所有自动化门禁通过，真机验证范围与未验证项均有记录。

## 数据兼容与旧机制去向

1. 新增会话消息和运行状态采用可选字段或带类型识别；旧会话缺少这些字段时按普通历史读取，不迁移既有消息。
2. 不修改小说正文、要素、项目配置和文件变更账本的格式。
3. 普通文本提问保留，与结构化工具并存；文件写入确认保留原有入口和职责。
4. 不迁移或恢复刷新前遗留的运行时等待，因为本期没有已上线的提问请求数据。

## 明确不做

- 一次调用提出多个问题、复杂表单、倒计时与自动默认回答。
- 独立的提问设置页、全局弹窗、通知中心或跨项目提问。
- 要素管理员直接提问，以及主智能体代替用户回答。
- 把主动提问用于每次写入、创作前的强制审批或固定工作流。
- 从页面刷新前的模型调用中断点无损恢复。
- 多步任务工具或其他短期执行清单能力；长期创作意图由 [创作计划板施工计划](创作计划板施工计划.md) 独立承接。

## 风险与约束

- 提问过于频繁会打断创作；验收要观察 Agent 是否只在真正需要用户决策时使用工具，但不新增硬编码频率限制。
- 等待期间普通输入的语义发生变化，必须由卡片与输入区清楚提示，避免用户误发新任务。
- 刷新后的恢复是显式降级而非无缝恢复，必须在界面与验收记录中保持这一口径。
- 提问是只读交互，不得借由服务层绕过现有文件权限、会话归属或委派边界。
