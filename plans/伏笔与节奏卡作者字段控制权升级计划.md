# 伏笔与节奏卡作者字段控制权升级计划

## 文档状态

- 记录日期：2026-11-19。
- 当前状态：**方案讨论稿，待用户确认，未开始施工**。
- 计划性质：独立扩展伏笔与节奏卡的作者编辑、人工校正和 AI 回写规则；不以正文自动保存计划完工为前提。
- 关联计划：《看板卡片详情自动保存与状态操作优化计划》继续负责两秒自动保存、伏笔放弃原因和版本比较。本计划负责字段可见、可改以及人工判定优先权，两份计划不得各自实现一套相互覆盖的保存逻辑。
- 本计划不自动批准共享文件修改、代码提交或推送。没有 goal 指令时，施工完成后停止并等待用户审查。

## 一、为什么升级

NovAI 是作者的创作工作台，不是替作者托管作品的封闭系统。作者应当能直接检查和修正项目中的创作信息，而不是为了改一个章节引用、关联角色或实际情绪，再让 AI 代为操作。

当前伏笔与节奏卡的底层能力并不等同于详情页能力：

| 卡片 | 当前主要限制 | 对作者的影响 |
| :-- | :-- | :-- |
| 伏笔 | 埋设章节、回收窗口、关联信息、红鲱鱼标记、关联章节和实际回收章节只读；关联章节只能追加 | 作者发现关联错误时不能在面板内删改，部分字段甚至找不到完整内容入口 |
| 节奏卡 | 关联章节、上下文衔接、作者备注、实际节奏值和自评没有作者编辑入口；状态与偏差只接受自动计算；看板禁止跨列拖动 | 作者只能直接维护写前计划，写后记录和系统判断缺少人工出口 |

本计划确立以下原则：

> 创作字段没有“AI 专属”这一权限层级。AI 负责协助记录和计算，作者始终可以查看、修改和裁决；系统负责格式校验、版本保护和明确反馈。

## 二、目标与范围

### 1. 最终体验

1. 作者在伏笔详情中可以修改全部有创作意义的字段，包括目前只读或只能追加的关联章节。
2. 作者在节奏卡详情中可以修改关联章节、正文三节和全部写后实际值，不再依赖 AI 才能填写或纠正。
3. 节奏状态、偏差标记和偏差说明默认自动计算，同时允许作者明确校正，并可恢复自动判定。
4. AI 写后同步仍形成提案并经作者确认；若会改变人工校正后的判定，必须在确认内容中明确展示，不得静默覆盖。
5. 保留现有详情骨架、领域分区和 Markdown 文件事实来源，不重做整体布局或新建表单。
6. 所有新增人工写入继续使用版本校验；外部修改与未落盘输入不能被静默覆盖。

### 2. 字段范围

| 领域 | 本计划纳入 | 维持现状 |
| :-- | :-- | :-- |
| 伏笔 | 埋设章节、回收窗口、关联角色、关联物品／实体、关联章节、是否红鲱鱼、实际回收章节；已存在放弃原因可查看和修订 | 名称、读者视角、作者真相已经可编辑；主动放弃流程由关联计划负责 |
| 节奏卡 | 关联章节、上下文衔接、作者备注、实际冲突、实际情绪、实际钩子、实际爽点、本章自评；状态、偏差标记和偏差说明的人工校正 | 名称、计划值和节奏意图已经可编辑；自动偏差算法与阈值沿用现有规则 |
| 系统字段 | 只提供清晰的只读说明 | 卡片身份、创建时间、更新时间、排序数值和文件位置仍由系统维护 |

创作计划卡不在本计划范围内。

### 3. 与自动保存计划的先后关系

- 本计划若先施工：新增字段接入现有详情保存链，保留当前手动保存入口；所有新增字段与原文本字段共用同一张卡片的草稿和版本基线。
- 自动保存计划若先施工：新增字段直接纳入统一卡片保存会话，遵守其两秒去抖、离开收口、失败重试和恢复规则。
- 后施工的一份计划必须整合先落地的一份，不能重建独立保存按钮、独立草稿或绕过冲突处理。
- 伏笔放弃仍需要原因和明确确认；不能因本计划增加“放弃原因可修订”就把主动放弃变成普通计时操作。

## 三、伏笔详情：高级信息完整可编辑

### 1. 界面分区

详情保留名称、状态、读者视角和作者真相的现有位置。在主内容区顶部增加默认折叠的「高级信息」，折叠时显示“埋设章节、回收窗口、关联信息等”的辅助说明，展开后在原位展示以下编辑项：

| 信息 | 固定编辑形态 | 允许的操作 |
| :-- | :-- | :-- |
| 埋设章节 | 单行文本输入 | 修改；去除首尾空白后不能为空 |
| 回收窗口 | 起点、终点两个单行输入 | 两端都填写、两端都清空；允许调整两端 |
| 关联角色 | 逗号或顿号分隔的多项输入 | 新增、修改、删除、清空；保存时去空白和去重 |
| 关联物品／实体 | 与关联角色相同 | 同上 |
| 关联章节 | 一行一项的多行文本输入，保留输入顺序 | 新增、修改、删除、调整顺序、清空；保存时去空白和去重 |
| 是否红鲱鱼 | 复选项及“故意误导读者”的说明 | 开启或关闭 |
| 实际回收章节 | 单行文本输入及清除操作 | 填写、修改、清除，规则见下文 |
| 已有放弃原因 | 多行文本输入 | 修订或清空历史说明；仍处已放弃状态时不允许清空为空 |

高级信息不拆出第二张编辑草稿。预览模式展示已有值及明确的“未设置”，编辑模式展示控件；无值字段不再因为从展示列表隐藏而失去补填入口。

### 2. 关联章节从只能追加改为作者可整理

- 底层更新增加“作者替换完整关联章节列表”的能力，保留现有“AI 追加关联章节”的独立入口。
- 完整替换只供作者界面及明确的作者请求使用；AI 写后同步默认仍追加、去重，不得把作者已整理的其他关联项当作冗余删除。
- 作者可以删除错误关联、清空列表或调整顺序；系统不能把这些操作退回为“只能追加”。
- 列表重复项在保存时保留首次出现的位置；空行忽略。除这些规范化外，不擅自按章号重排作者输入。
- 写前检查、章节侧栏反查和 AI 读取继续基于保存后的同一份列表，不建立另一份人工覆盖表。

### 3. 实际回收章节与状态的一致性

现有“离开揭晓／解决状态就清空实际回收章节”的隐式规则不再成立。状态变更不得顺带删除没有提交修改的实际回收章节。

| 操作 | 固定行为 |
| :-- | :-- |
| 在普通未收状态填写实际回收章节 | 展示就地说明“当前状态不是已揭晓或已解决”；不自动替作者切状态，不阻止保存 |
| 从揭晓／解决切回未收状态 | 实际回收章节默认保留，并在高级信息中提示它与当前状态不一致；作者可以保留作为历史记录，也可以手动清除 |
| 再次进入揭晓／解决 | 沿用作者填写值，不要求重新录入 |
| 在已放弃状态查看历史回收章节 | 原样保留和可修订，不因放弃而删除 |

这样保留作者的事实记录，同时不伪装成状态与章节已经一致。后续 AI 查询必须同时呈现状态和实际回收章节，不能仅因存在回收章节就宣称伏笔已解决。

### 4. 回收窗口与输入校验

- 起点和终点必须成对填写或成对留空；只填一端时就地提示，不发送不完整的区间更新。
- 两端都能解析出章号且起点大于终点时，提示调整；无法解析章号的自由章节标识允许保存，不强制引入新的章节格式。
- 埋设章节仍不能为空；其他高级字段可以合法留空。
- 作者输入不合法时保留全部输入，不回退其他已经填写的高级信息。
- 放弃伏笔的领域原因校验继续保留。已放弃卡片的历史原因修订不能绕过该校验；从已放弃恢复普通状态后，原因可以为空或继续保留。

## 四、节奏详情：计划与写后记录都由作者掌控

### 1. 固定布局

详情仍使用现有骨架，不重排整个工作区。内容区从上到下组织为：

1. 当前状态及判定来源。
2. 关联章节输入。
3. 现有写前计划值编辑区。
4. 「写后实际值」区，无论是否已有实际值都可见。
5. 「判定与说明」区，展示自动结果或作者校正入口。
6. 默认折叠的「更多正文」，其中包含上下文衔接与作者备注。
7. 现有节奏意图正文区。

「更多正文」和写后实际区采用轻量分区，不增加全局弹窗。窄屏下这些区域随详情正常纵向滚动，不能挤压节奏意图到无法阅读或操作。

### 2. 全部写后信息可编辑

| 信息 | 固定编辑形态 | 允许的操作 |
| :-- | :-- | :-- |
| 关联章节 | 单行文本输入 | 修改，不能为空 |
| 实际冲突 | 一至十的滑块与数值显示，附“未填写”清除操作 | 填写、修改、清除 |
| 实际情绪 | 与计划值相同的枚举选择，另提供“未填写” | 填写、修改、清除 |
| 实际钩子 | 与计划值相同的枚举选择，另提供“未填写” | 填写、修改、清除 |
| 实际爽点 | 与计划值相同的枚举选择，另提供“未填写” | 填写、修改、清除 |
| 本章自评 | 多行文本输入 | 填写、修改、清除；标题不使用“AI 自评”，作者与 AI 都能贡献 |
| 上下文衔接 | 独立多行正文编辑区，预览时使用现有正文渲染 | 填写、修改、清除 |
| 作者备注 | 独立多行正文编辑区，预览时使用现有正文渲染 | 填写、修改、清除 |

- 实际值不再只有发生回写后才显示。作者可以先看到完整区域并主动补填。
- 实际值区并列展示相应计划值，编辑时也能直接比较，不因进入编辑模式就隐藏计划参照。
- 一次保存可包含计划值、实际值、正文和关联章节，不能拆成多个独立请求相互覆盖。
- 实际值不是章节正文的自动摘要替代品。修改它们只更新节奏卡，不写回章节文件。

## 五、节奏判定：自动为默认，作者可校正

### 1. 两种判定来源

节奏卡增加“判定来源”：自动判定或作者校正。状态、偏差标记和偏差说明仍保存在原卡片中，判定来源、人工说明及最近一次判定采用的冲突阈值作为新增的可选元数据保存。

| 判定来源 | 含义 | 界面表达 |
| :-- | :-- | :-- |
| 自动判定 | 按当前计划值、实际值和项目阈值计算 | 状态旁显示“自动判定” |
| 作者校正 | 作者明确设置状态、偏差结论或说明 | 状态旁显示“作者校正”，提供“恢复自动判定” |

判定来源不是全局模式开关，也不是新增一套看板。三张看板列继续使用现有“规划中／已写／偏差”，曲线、摘要和筛选继续读取同一份有效结果。

### 2. 作者校正入口

在「判定与说明」区提供「作者校正」。点击后在原位展开：

- 状态下拉：规划中、已写、偏差。
- 偏差结论：无偏差、有偏差。
- 偏差说明：多行文本；有偏差时必填，无偏差时留空并清除旧说明。
- 「应用校正」和「取消」。

| 状态下拉 | 允许的偏差结论 | 实际值要求 |
| :-- | :-- | :-- |
| 规划中 | 仅无偏差 | 允许保留已有实际值；校正分类不清空它们 |
| 已写 | 无偏差或有偏差 | 至少一项实际值 |
| 偏差 | 仅有偏差 | 至少一项实际值 |

固定校验与操作规则：

1. 上表在应用校正时统一校验，不满足时就地说明，不自动修改作者选择。
2. 「应用校正」是一次明确操作，不等待自动保存计时；与同一轮尚未落盘的字段修改合并为一次整体保存。存在版本冲突时先保留输入并进入冲突处理，不能绕过版本校验。
3. 取消只退出校正操作态，保留当前已生效结果；未应用输入可以留在卡片编辑会话中，但离开、关闭或刷新绝不能自动应用。

### 3. 自动重算与人工结果的保护

- 自动模式下，任何计划比较项、实际比较项或项目偏差阈值改变，都在保存后以最新完整卡片重新计算状态、偏差标记和系统偏差说明；解决当前“已有实际值时再改计划值不重算”的不一致。
- 自动模式下，仅修改卡名、关联章节、出场角色、自然语言补充或正文，不重算判定。
- 作者模式下，作者自己在详情中修改实际比较项或计划比较项，保存后以新值重算并回到自动模式。保存前就明确提示“保存这些比较值后将恢复自动判定”，避免误以为人工结论仍锁定。
- 作者模式下，作者修改非比较字段，不改变人工状态、偏差结论和说明。
- 项目阈值改变时，人工判定默认保留；看板与详情显示轻量提示“阈值已变化，可重新检查”，由作者主动恢复自动判定，不批量重写卡片。
- 每次自动判定或作者校正保存时记录所采用的冲突阈值。读取时比较该记录与当前项目阈值即可识别变化，不需要扫描正文或重写其他卡片；旧卡没有该记录时按当时默认阈值三解释，只有保存新判定时才补记。
- 「恢复自动判定」使用当前最新计划值、实际值和阈值立即计算，并随当前人工修改一次保存；不另等两秒，不清空实际值。
- 若当前实际值全部为空，恢复自动后回到规划中、无偏差、无系统说明；若仅部分实际值存在，按现有偏差规则判定为已写或偏差。

### 4. AI 写后同步不得静默覆盖

- AI 继续先读取卡片、整理提案，再由作者批准后写入，不获得绕过人工判定的特殊通道。
- 对作者校正卡，AI 写后同步只提交一组实际比较值，不在同一次普通同步中混改计划比较值；确需修改计划时另列独立提案。这样每次回写的判定去向都是确定的。
- 对自动判定卡，AI 实际值提案按现有确认流程保存并重算。
- 对作者校正卡，AI 实际值提案的确认界面固定展示“当前作者结论 → 按提案计算的自动结论”，即使两者相同也不能隐藏来源将改变的事实；作者确认这一次提案即表示接受按新值重算并回到自动模式。
- 对作者校正卡，若 AI 只修改非比较字段，人工判定保留；确认文案不能误称其会重算。
- 已有人工校正标记和说明必须进入 AI 读取、写后同步上下文，提示模型尊重作者结论，但权限保护不能只依赖提示词，写入服务也必须执行上述来源规则。
- AI 普通更新工具不接受作者校正参数，只能按上述确定规则写计划、实际值或非比较字段。人工校正仅由作者详情中的明确操作触发；确需支持“按用户明确要求代为校正”时，另行设计专用工具与确认界面，不在本计划附带扩展。

## 六、节奏看板拖动

本计划取消“一律禁止跨列”的交互限制，但不把拖动伪装成自动计算：

| 拖动场景 | 固定行为 |
| :-- | :-- |
| 同列排序 | 保持现有即时排序，不修改实际值或判定来源 |
| 自动判定卡跨列 | 松手后打开该卡片详情的作者校正操作态，目标状态已选中；原看板位置暂不改变 |
| 作者校正卡跨列 | 同样进入作者校正操作态，显示当前人工结论与目标状态，作者可一并修订偏差说明 |
| 点击「应用校正」 | 一次性保存状态、偏差结论、说明、目标落点和其他待保存修改；成功后看板移动 |
| 取消、关闭或切换卡片 | 不修改原状态或看板位置；未应用输入随编辑会话保留，不自动执行 |
| 拖动到“规划中” | 只校正分类，不清空已有实际值；详情提示这些实际值仍然保留 |
| 拖动到“已写／偏差”且没有实际值 | 「应用校正」禁用，并提示先补至少一项实际值 |

拖动不再静默无效，也不显示一个最终不能落下的目标占位。拖动开始时允许显示合法落点，松手后以“待作者确认”的原因操作态完成；没有应用前真实看板保持原位。

普通字段的保存时序仍由施工时已经生效的保存计划决定；跨列校正始终以「应用校正」为明确出口，不能仅因两秒计时自动完成。

## 七、保存、冲突与错误反馈

1. 所有新增字段进入本领域的同一份卡片草稿，记录字段是否修改，并与原文本字段共享读取版本。
2. 保存时只提交实际变更字段，但携带同一版本校验；更新服务对整次提交原子落盘，不能高级字段成功而正文失败后只清掉部分输入。
3. 保存期间继续输入时，旧请求只清理它实际提交的修订，新输入必须保留到下一轮。
4. 切卡、切项目或关闭详情不能让旧请求改写新现场；不同项目中相同卡片标识也必须隔离。
5. 外部或 AI 修改与人工未落盘内容同时出现时，沿用当前冲突入口。自动保存计划落地后，新增字段必须进入其字段比较、副本和采用操作，不能只比较旧的三项内容。
6. 高级信息中的非法输入只阻止当前卡片写入，并显示具体字段错误；不清空、不跳走、不将合法字段先写一半。
7. 普通成功反馈沿用详情现有状态，不额外制造全局 Toast；失败持续可见，并可重试。
8. 人工判定、自动判定和待保存草稿必须区分。作者校正未应用前不能提前显示“作者校正”，保存失败时原判定来源不变。

## 八、文件格式、旧数据与兼容

### 1. 保留现有内容

- 伏笔继续使用现有 Markdown 字段和两节正文，不重写旧文件，不迁移关联章节到另一目录。
- 节奏卡继续使用现有计划值、实际值、状态、偏差结果和三节正文；新增编辑入口不自动为旧卡片补写空白内容。
- 既有伏笔实际回收章节即使与普通状态不一致，也原样读取、展示，不做启动时清理或批量校正。
- 旧节奏卡没有判定来源元数据时按“自动判定”解释，保留现有状态、偏差标记和说明，不在首次读取时重算或重写。
- 一旦作者主动修改并保存旧节奏卡，按第五节规则处理：修改比较值时重算，修改非比较值时保持旧判定结果。
- 新增判定来源和作者说明只保存在各自卡片文件中，旧版本应用无法识别时最多忽略新增说明，不影响原有计划与实际值读取；不引入浏览器专属事实源。

### 2. 人工校正元数据

- 记录判定来源、人工偏差说明和最近一次判定采用的冲突阈值，不另存一份会与有效状态冲突的“人工状态”。
- 自动模式仍沿用现有系统偏差说明字段；人工模式把作者说明保存在独立的可选字段中，界面以作者说明为当前有效说明。
- 恢复自动判定时保留作者历史说明，但不再作为当前有效说明；界面在默认折叠的“历史人工说明”中查看，不静默删除创作记录。
- 本计划不增加校正时间、操作者账户或历史版本链；当前更新时间继续由系统维护。

## 九、新旧机制替代表

| 现有机制 | 新去向 |
| :-- | :-- |
| 伏笔结构字段只读，提示找 AI 或改文件 | 替换为默认折叠的高级信息编辑区 |
| 伏笔关联章节只能追加 | 保留 AI 追加入口，新增作者完整替换与整理能力 |
| 离开揭晓／解决自动清空实际回收章节 | 删除隐式清空；改为保留并提示状态不一致 |
| 已放弃原因只能只读展示 | 增加历史说明修订，已放弃时仍不能为空 |
| 节奏关联章节只读 | 替换为可编辑输入 |
| 节奏上下文衔接、作者备注无详情入口 | 纳入默认折叠的更多正文 |
| 节奏实际值只在有回写后只读展示 | 替换为始终可见、可增改清的写后实际值区 |
| 节奏状态与偏差禁止人工设置 | 替换为默认自动、明确作者校正、可恢复自动 |
| 作者校正被后续回写静默覆盖 | 替换为比较值变更重算和确认界面明确展示结论变化 |
| 节奏跨列拖动静默无效 | 替换为进入作者校正并暂存目标落点 |
| 节奏计划值改变不重算既有判定 | 自动模式下改为按最新比较值重算 |

## 十二、明确不做

- 不修改创作计划卡，不重新设计其已经合理的字段与状态。
- 不重做整体 UI、导航、配色、看板信息架构或新建卡片表单。

- 不开放卡片身份、创建时间、更新时间、文件位置和排序数值的任意编辑。
- 不取消放弃原因校验、版本冲突保护、AI 写权限或写后提案确认。
- 不将实际回收章节与状态的不一致当成保存失败；明确展示并交由作者处理。
- 不自动清除人工校正，不通过提示词约束代替写入层的来源保护。
- 不引入人工／自动保存双模式；保存时序由关联自动保存计划统一负责。

## 十四、方案形成记录

### 2026-11-19：作者控制权方案讨论

- 用户明确创作计划卡当前边界合理，不纳入改造。
- 伏笔名称、读者视角和作者真相之外的结构信息也应允许作者直接微调；高级信息可以默认折叠，但不能成为 AI 专属能力。
- 节奏卡除跨列拖动曾可勉强接受外，其他创作信息也应由作者直接控制；仅允许 AI 写后回写不符合作者辅助工具的定位。
- 方案采用“默认自动判定、作者明确校正、可以恢复自动”的节奏状态模型，避免开放人工编辑后又被下一次同步静默覆盖。
- 伏笔关联章节增加作者完整整理能力，AI 仍保留追加、去重路径；实际回收章节不再因状态变化被隐式清空。
- 新建表单继续保持轻量，本计划集中完善创建后的详情编辑，不把所有高级输入塞进登记流程。
- 本轮只编写计划，不修改应用代码；方案仍待用户确认。
