## 一、为什么升级

NovAI 是作者的创作工作台，不是替作者托管作品的封闭系统。作者应当能直接检查和修正项目中的创作信息，而不是为了改一个章节引用、关联角色或实际情绪，再让 AI 代为操作。

当前伏笔与节奏卡的底层能力并不等同于详情页能力：

| 卡片 | 当前主要限制 | 对作者的影响 |
| :-- | :-- | :-- |
| 伏笔 | 埋设章节、回收窗口、关联信息、红鲱鱼标记、关联章节和实际回收章节只读；关联章节只能追加 | 作者发现关联错误时不能在面板内删改，部分字段甚至找不到完整内容入口 |
| 节奏卡 | 关联章节、上下文衔接、作者备注、实际节奏值和自评没有作者编辑入口；状态与偏差只接受自动计算；看板禁止跨列拖动 | 作者只能直接维护写前计划，写后记录和系统判断缺少人工出口 |

本计划确立以下原则：

> 创作字段没有“AI 专属”这一权限层级。AI 负责协助记录和计算，作者始终可以查看、修改和裁决；系统负责格式校验、版本保护和明确反馈。

## 二、目标与范围

### 1. 最终体验

1. 作者在伏笔详情中可以修改全部有创作意义的字段，包括目前只读或只能追加的关联章节。
2. 作者在节奏卡详情中可以修改关联章节、正文三节和全部写后实际值，不再依赖 AI 才能填写或纠正。
3. 节奏状态、偏差标记和偏差说明默认自动计算，同时允许作者明确校正，并可恢复自动判定。
4. AI 写后同步仍形成提案并经作者确认；若会改变人工校正后的判定，必须在确认内容中明确展示，不得静默覆盖。
5. 接入已完工的统一详情布局和既有领域分区，继续以卡片 Markdown 文件为事实来源；不恢复已删除的卡片专用骨架，不重做整体布局或新建表单。
6. 章节引用使用统一的搜索、选择和新建交互，同时区分已有章节、计划回收位置与实际回收章节；不要求为未来位置预先创建虚假章节。
7. 所有新增普通人工写入直接进入现有卡片保存会话，继续使用版本校验；外部修改与未落盘输入不能被静默覆盖。
8. 「应用校正」「恢复自动判定」「修订历史放弃原因」和看板跨列落点是明确操作，立即按当时完整快照保存，成功后才改变有效结果，不走两秒计时。

### 2. 字段范围

| 领域 | 本计划纳入 | 维持现状 |
| :-- | :-- | :-- |
| 伏笔 | 埋设章节、回收窗口、关联角色、关联物品／实体、关联章节、是否红鲱鱼、实际回收章节；章节搜索、从选择器真实新建章节和未来位置表达；已存在放弃原因可查看和修订 | 名称、读者视角、作者真相已经可编辑；主动放弃流程由关联计划负责 |
| 节奏卡 | 关联章节的搜索与选择、上下文衔接、作者备注、实际冲突、实际情绪、实际钩子、实际爽点、本章自评；状态、偏差标记和偏差说明的人工校正 | 名称、计划值和节奏意图已经可编辑；自动偏差算法与阈值沿用现有规则 |
| 系统字段 | 只提供清晰的只读说明 | 卡片身份、创建时间、更新时间、排序数值和文件位置仍由系统维护 |

伏笔的关联角色与关联物品／实体仍是伏笔卡内的轻量创作信息：允许自由填写，不要求先建立要素，不迁移到关系账本，也不与关系图谱的节点、连线自动同步。关系图谱记录要素之间的独立关系；本计划只负责伏笔卡自身字段的作者控制权。

创作计划卡不在本计划范围内。

### 3. 与已落地基础能力的承接关系

卡片保存会话与统一详情布局均已完工，本计划不再讨论先后顺序：

- 所有新增普通字段直接纳入当前卡片保存会话，遵守两秒去抖、同卡串行、离开收口、失败补试、恢复镜像和非阻塞冲突规则。
- 新增字段与原字段共用同一张卡片的草稿、版本基线、字段比较和副本出口；不新增保存按钮、独立草稿或第二套冲突处理。
- 伏笔高级信息与节奏新增区域作为领域内容接入统一详情布局；头部保存状态、预览／编辑切换、消息区和底部信息行保持现状。
- 伏笔主动放弃仍使用已落地的原位原因操作态和原子确认；本计划只补充历史原因修订，不能把主动放弃降级成普通计时操作。
- 「应用校正」「恢复自动判定」「修订历史放弃原因」和看板跨列落点属于明确操作：点击时固定当时完整快照并立即保存，成功后才更新有效结果；取消、离开或刷新不得自动执行。
- 未应用的明确操作态与未落盘内容同等对待：外部或 AI 修改先建立版本关系，刷新恢复后仍以待确认状态呈现，不得拿旧基线静默套用。

### 4. 独立 worktree 与关系图谱、时间线的并行边界

- 本计划在独立 worktree 开工，从包含自动保存与统一布局完工成果的当前开发线最新提交建立，并初始化、检出文档子模块，确保读到的是已确认的本计划版本；不共享、不覆盖关系图谱或时间线任务的工作区，也不从其他工作区复制未提交内容。
- 关系图谱已建立或正在建立的能力只作为可选公共实现参考，不构成本计划的前置条件；伏笔关联角色／实体不改为关系节点，节奏卡不进入关系账本。
- 时间线仍是独立方向。本计划不预留事件引用，不为章节提前建立稳定身份；将来时间线若引入稳定章节引用，另定迁移方案，不在本计划内顺手改造。
- 章节查询与创建服务、伏笔／节奏领域更新、卡片详情组件属于本计划改动面；关系图谱的服务注册、工具清单和时间线文档只允许出现合并层面的追加接线，不得重排或改写其语义。

## 三、伏笔详情：高级信息完整可编辑

### 1. 界面分区

详情继续由统一详情布局承载，名称、状态、读者视角和作者真相的位置保持现状。在主内容区顶部增加默认折叠的「高级信息」，折叠时显示“埋设章节、回收窗口、关联信息等”的辅助说明，展开后在原位展示以下编辑项：

| 信息 | 固定编辑形态 | 允许的操作 |
| :-- | :-- | :-- |
| 埋设章节 | 可搜索的章节选择器 | 选择已有章节或从选择器真实新建；不能为空 |
| 回收窗口 | 起点、终点两个计划位置选择器 | 两端都填写、两端都清空；终点可单独留空表示开放终点，规则见下文 |
| 关联角色 | 逗号或顿号分隔的多项输入 | 新增、修改、删除、清空；保存时去空白和去重 |
| 关联物品／实体 | 与关联角色相同 | 同上 |
| 关联章节 | 可搜索的多选章节选择器，保留作者排列顺序 | 选择已有章节或真实新建；新增、删除、调整顺序、清空 |
| 是否红鲱鱼 | 复选项及“故意误导读者”的说明 | 开启或关闭 |
| 实际回收章节 | 可搜索的章节选择器及清除操作 | 选择已有章节；历史值保留原引用并标注待确认；清除；不主动创建章节 |
| 已有放弃原因 | 只读展示与「修订原因」明确操作 | 查看历史说明；修订须经原位操作态明确应用；已放弃状态下应用时原因不能为空 |

高级信息不拆出第二张编辑草稿。预览模式展示已有值及明确的“未设置”，编辑模式展示控件；无值字段不再因为从展示列表隐藏而失去补填入口。折叠与展开只是界面状态，不产生保存；展开后高级信息、双正文和放弃操作态共用当前主内容区的滚动责任，不得挤出统一布局的底部信息或让任一输入失去可达性。

历史放弃原因不是两秒自动保存字段。高级信息默认只读展示已有原因；点击「修订原因」后进入原位输入，提供「应用修订」和「取消」。应用时携带最新版本立即保存原因；已放弃状态下去除首尾空白后不能为空，保存成功才更新展示。取消、离开或刷新不自动应用，未应用输入随卡片编辑会话保留。它与从普通状态主动放弃是两个操作：主动放弃仍由既有关联计划的确认闭环负责，本计划不改变其状态切换语义。

### 2. 关联章节从只能追加改为作者可整理

- 底层更新增加“作者替换完整关联章节列表”的能力，保留现有“AI 追加关联章节”的独立入口。
- 完整替换只供作者界面及明确的作者请求使用；AI 写后同步默认仍追加、去重，不得把作者已整理的其他关联项当作冗余删除。
- 作者可以删除错误关联、清空列表或调整顺序；系统不能把这些操作退回为“只能追加”。
- 列表重复项在保存时保留首次出现的位置。除这些规范化外，不擅自按章号重排作者输入；选择器添加顺序就是初始排列顺序，作者可随后手动调整。
- 写前检查、章节侧栏反查和 AI 读取继续基于保存后的同一份列表，不建立另一份人工覆盖表。

### 3. 实际回收章节与状态的一致性

现有“离开揭晓／解决状态就清空实际回收章节”的隐式规则不再成立。状态变更不得顺带删除没有提交修改的实际回收章节。

| 操作 | 固定行为 |
| :-- | :-- |
| 在普通未收状态填写实际回收章节 | 展示就地说明“当前状态不是已揭晓或已解决”；不自动替作者切状态，不阻止保存 |
| 从揭晓／解决切回未收状态 | 实际回收章节默认保留，并在高级信息中提示它与当前状态不一致；作者可以保留作为历史记录，也可以手动清除 |
| 再次进入揭晓／解决 | 沿用作者填写值，不要求重新录入 |
| 在已放弃状态查看历史回收章节 | 原样保留和可修订，不因放弃而删除 |

这样保留作者的事实记录，同时不伪装成状态与章节已经一致。后续 AI 查询必须同时呈现状态和实际回收章节，不能仅因存在回收章节就宣称伏笔已解决。

### 4. 章节选择器：搜索、选择与真实新建

伏笔的章节字段和节奏卡的关联章节共用同一选择器骨架，按当前项目的真实章节列表展示结果，不要求作者记住完整文件名。

- 结果展示章号和章节标题，支持按章号或标题搜索；数字查询按全本章号匹配，不把章号拆成别的层级。
- 支持键盘上下移动、回车选择、Esc 收起；鼠标与键盘得到同一结果。收起不保存，已选项仍按当前卡片的保存规则处理。
- 单选字段选择一个章节后收起；关联章节保持已选标签列表，可以继续添加、删除或重排，不因为选择一项就清空其他项。
- 加载期间显示读取状态，读取失败时保留当前值和输入并提供重试，不把失败结果显示成“项目没有章节”。
- 已选项不依赖再次读取章节列表才能显示。章节引用保存的是全本章号位置，不是稳定文件身份：标题或文件名变化但章号不变时，引用继续指向同一位置；章节被删除后显示“该章号当前没有章节”；之后若出现同章号新章节，按章号位置恢复展示，并说明系统无法确认它是否就是原章节。不另建章节身份系统，也不承诺仅凭章号区分删后重建的同号章节。
- 新建入口执行章号唯一性校验，正常项目不会出现重复章号。历史项目若存在重复章号，选择器列出全部候选及其标题和路径，但相关字段标记“章号重复，待消歧”：仅凭章号无法持久区分候选，未在章节模块消除重号前不自动选择其一，也不把某次选择伪装成持久身份。
- 章节列表读取、章节身份解析和真实新建全部经过现有 core 项目／文件服务，前端不直接读写项目文件。选择器只复用应用层已有的服务适配，不在组件中引入 Node 文件能力。
- 当前项目与卡片身份固定在选择器会话中。切卡、切项目后，旧搜索结果和新建结果不得填入新现场。
- 已有章节的埋设位置、关联章节和节奏关联章节优先选择真实章节，不能把任意自由文本静默当成正常已有章节。

选择器为埋设章节、关联章节和节奏关联章节提供「新建章节」入口。该入口真正创建章节，不只是向卡片输入框填入一个未来章号：

1. 在选择器内展开新建区，填写章号和可选标题；默认建议当前最大章号的下一章，作者可以修改。章号须为正整数；标题留空时以“未命名”作为初始标题生成符合现有规范的章节文件，作者后续可按现有章节管理方式改名。已有同章号章节时改为选择它，不重复创建；文件名冲突时停止并保留输入。
2. 点击「创建并选择」后，按项目现有章节命名规范创建对应空章节文件。章节正文由作者在章节编辑区另行撰写，不由卡片编辑器代写。
3. 创建成功后才把该章节加入当前选择；创建失败、目标章号或文件名已存在时保留输入和原选择，明确报错，不显示虚假成功，不覆盖已有文件。
4. 创建章节和保存卡片是两件独立的事。章节创建成功后，若作者取消卡片修改、遇到版本冲突或卡片保存失败，不反向删除已经创建的章节；界面明确提示“章节已创建，卡片引用尚未保存”。
5. 若同一张卡片多个字段相继选择同一新章节，复用已经创建的真实章节，不重复创建。未保存的引用仍只属于当前卡片编辑会话，不进入其他卡片。
6. 实际回收章节选择器不提供新建入口；尚未发生的回收应填写计划回收位置，不能通过补建空章节伪装成实际回收。

### 5. 计划回收位置、回收窗口与实际回收章节

这三类信息不共用一种含义。界面与文件数据必须能区分“计划在哪收”“允许在哪一段收”“实际上在哪收了”。

#### 计划回收位置

计划位置选择器提供「已有章节」「最新章节之后第 N 章」「指定未来章号」三个明确入口，另以清除操作表示暂不指定。不能以一段无法区分含义的自由文本代替这些入口。

回收窗口起点支持以下四种位置：

| 选择 | 固定语义 | 界面展示 |
| :-- | :-- | :-- |
| 已有章节 | 指向确定的已有章节 | 章号、标题 |
| 最新章节之后第 N 章 | 以选择时的最新章为固定基准，偏移 N 章 | 显示基准、偏移量及已经确定的目标章号 |
| 指定未来章号 | 指向明确但当前尚未创建的章号 | 章号及“尚未创建” |
| 暂不指定 | 没有计划起点，不要求伪造章节 | 显示“未设置” |

- 偏移量必须为正整数。选择相对位置时记录当时的基准章号与偏移量，不只保存“N 章之后”这句无法还原的文本。
- 基准与目标章号在保存时确定。以后继续写新章，不随“最新章节”继续向后漂移；删除或插入其他章节也不重新计算目标。
- 「指定未来章号」接受尚未存在的正整数章号；若已经存在对应章节，直接转为选择该已有章节，不重复建立相对位置。
- 目标位置可以晚于当前最大章号，也可以是当前编号空隙中的未创建章号。界面显示“尚未创建”，但它是合法计划，不要求先创建空章节。
- 预计目标章已经真实创建后，选择器可以展示对应标题；读取仍使用已保存的目标章号，不因存在同名文件改变基准或偏移记录。
- 作者需要改成另一个固定位置时，显式重新选择已有章节或重新设置相对位置；系统不自动吸附。

#### 回收窗口

- 起点和终点都可以选择已有章节、明确的未来固定章号或相对位置。相对位置在保存时形成确定目标章号，后续不因章节增加而漂移。
- 两端都有计划位置时，以解析后的目标章号比较；起点大于终点就提示调整，不写入倒置窗口。
- 终点允许单独留空，表示从起点开始、暂无截止章的开放窗口；起点留空而终点有值时，提示先补起点。
- 两端都清空表示未设置回收窗口。开放终点与未设置必须在界面和数据中可区分，不能都显示成同一个空区间。
- 原有“该收了”和写前检查按解析后的目标章号判断：进入起点且尚未回收即提示；存在终点时超过终点仍可继续提示逾期，不能因为有终点就停止关注。
- 计划位置只描述创作意图，不创建章节，也不写入实际回收章节。章节侧栏反查只关联已经存在的章节，不为未来目标制造空白关联。

#### 实际回收章节

- 正常新填写时只从已有章节中选择，不自动创建章节，也不接受“最新章节之后第 N 章”这种计划表达。
- 已有实际回收章节原样读取，即使该章节后来被删除或当前状态与回收记录不一致，也保留原事实及“不存在／状态不一致”提示。
- 若已有记录指向当前不存在的章节，保留原值并显示“章节不存在”；作者可清除或改选真实章节。不新设“登记不存在的实际回收章节”入口，避免把计划或误输内容写成已发生事实。
- 清除实际回收章节只清除这项事实记录，不改变计划窗口或关联章节。

### 6. 回收窗口与输入校验

- 埋设章节不能为空；关联章节只接受真实章节或真实新建成功的章节；节奏关联章节不能为空，并从真实章节中选择或新建。
- 相对位置必须有可解析的正整数基准章号与正整数偏移，缺一项不能保存为相对位置。
- 实际回收章节的正常选择只接受当前真实存在的章节；历史不存在值只作保留、提示和清除，不新增此类记录。
- 作者输入不合法时保留全部输入，不回退其他已经填写的高级信息。
- 放弃伏笔的领域原因校验继续保留。已放弃卡片的历史原因修订不能绕过该校验；从已放弃恢复普通状态后，原因可以为空或继续保留。

## 四、节奏详情：计划与写后记录都由作者掌控

### 1. 固定布局

详情继续由统一详情布局承载，不重排整个工作区。内容区从上到下组织为：

1. 当前状态及判定来源。
2. 关联章节输入。
3. 现有写前计划值编辑区。
4. 「写后实际值」区，无论是否已有实际值都可见。
5. 「判定与说明」区，展示自动结果或作者校正入口。
6. 默认折叠的「更多正文」，其中包含上下文衔接与作者备注。
7. 现有节奏意图正文区。

「更多正文」和写后实际区采用轻量分区，不增加全局弹窗。窄屏下这些区域随详情正常纵向滚动，不能挤压节奏意图到无法阅读或操作。

### 2. 全部写后信息可编辑

| 信息 | 固定编辑形态 | 允许的操作 |
| :-- | :-- | :-- |
| 关联章节 | 可搜索的章节选择器，支持真实新建 | 修改，不能为空；不能保存未创建的自由章节标识 |
| 实际冲突 | 一至十的滑块与数值显示，附“未填写”清除操作 | 填写、修改、清除 |
| 实际情绪 | 与计划值相同的枚举选择，另提供“未填写” | 填写、修改、清除 |
| 实际钩子 | 与计划值相同的枚举选择，另提供“未填写” | 填写、修改、清除 |
| 实际爽点 | 与计划值相同的枚举选择，另提供“未填写” | 填写、修改、清除 |
| 本章自评 | 多行文本输入 | 填写、修改、清除；标题不使用“AI 自评”，作者与 AI 都能贡献 |
| 上下文衔接 | 独立多行正文编辑区，预览时使用现有正文渲染 | 填写、修改、清除 |
| 作者备注 | 独立多行正文编辑区，预览时使用现有正文渲染 | 填写、修改、清除 |

- 实际值不再只有发生回写后才显示。作者可以先看到完整区域并主动补填。
- 实际值区并列展示相应计划值，编辑时也能直接比较，不因进入编辑模式就隐藏计划参照。
- 一次保存可包含计划值、实际值、正文和关联章节，不能拆成多个独立请求相互覆盖。
- 实际值不是章节正文的自动摘要替代品。修改它们只更新节奏卡，不写回章节文件。
- 本章自评是写后记录，不参与计划与实际的偏差比较，也不能单独证明本章已写；判定要求见下一节。
- 节奏卡继续遵循一章一卡。修改关联章节时若目标章号已有其他节奏卡，保存被阻止并说明已有卡片，当前输入保留；冲突副本遇到同章占用同样明确报错，不能静默丢字段或伪装创建成功。

## 五、节奏判定：自动为默认，作者可校正

### 1. 两种判定来源

节奏卡增加“判定来源”：自动判定或作者校正。状态、偏差标记和偏差说明仍保存在原卡片中，判定来源、人工说明及最近一次判定采用的冲突阈值作为新增的可选元数据保存。

| 判定来源 | 含义 | 界面表达 |
| :-- | :-- | :-- |
| 自动判定 | 按当前计划值、实际值和项目阈值计算 | 状态旁显示“自动判定” |
| 作者校正 | 作者明确设置状态、偏差结论或说明 | 状态旁显示“作者校正”，提供“恢复自动判定” |

判定来源不是全局模式开关，也不是新增一套看板。三张看板列继续使用现有“规划中／已写／偏差”，曲线、摘要和筛选继续读取同一份有效结果。

### 2. 作者校正入口

在「判定与说明」区提供「作者校正」。点击后在原位展开：

- 状态下拉：规划中、已写、偏差。
- 偏差结论：无偏差、有偏差。
- 偏差说明：多行文本；有偏差时必填，无偏差时留空并清除旧说明。
- 「应用校正」和「取消」。

| 状态下拉 | 允许的偏差结论 | 实际值要求 |
| :-- | :-- | :-- |
| 规划中 | 仅无偏差 | 允许保留已有实际值；校正分类不清空它们 |
| 已写 | 无偏差或有偏差 | 冲突、情绪、钩子、爽点四项实际比较值中至少一项已填写 |
| 偏差 | 仅有偏差 | 冲突、情绪、钩子、爽点四项实际比较值中至少一项已填写 |

本章自评只是写后记录，不计入冲突、情绪、钩子、爽点四项实际比较值；只填写自评不能满足“已写”或“偏差”的校正条件。

固定校验与操作规则：

1. 上表在应用校正时统一校验，不满足时就地说明，不自动修改作者选择。
2. 点击「应用校正」时固定当前完整卡片快照并立即保存，不等待自动保存计时；同一轮尚未落盘的字段修改、判定来源、说明和目标落点合并为一次整体保存。保存成功后才更新有效结果；失败保留全部输入，存在版本冲突时先进入冲突处理，不能绕过版本校验。
3. 取消只退出校正操作态，保留当前已生效结果；未应用输入可以留在卡片编辑会话中，但离开、关闭或刷新绝不能自动应用。
4. 未应用的校正操作态与未落盘内容同等对待。外部或 AI 修改到达时先建立版本关系；刷新恢复后仍呈现待确认校正，不得拿旧基线自动应用。

### 3. 自动重算与人工结果的保护

- 自动模式下，保存某张卡的计划比较项或实际比较项时，按保存当时的项目阈值以最新完整卡片重新计算状态、偏差标记和系统偏差说明；解决当前“已有实际值时再改计划值不重算”的不一致。
- 自动模式下，仅修改卡名、关联章节、出场角色、自然语言补充或正文，不重算判定。
- 作者模式下，作者自己在详情中修改实际比较项或计划比较项，保存后以新值重算并回到自动模式。保存前就明确提示“保存这些比较值后将恢复自动判定”，避免误以为人工结论仍锁定。
- 作者模式下，作者修改非比较字段，不改变人工状态、偏差结论和说明。
- 修改项目阈值不在后台批量重写任何卡片。最近一次判定采用的阈值与当前阈值不一致的卡片，在看板与详情显示轻量提示“阈值已变化，可重新检查”：自动卡在下一次保存比较值或作者明确重算时更新；人工卡始终保留人工结论，只有作者主动恢复自动判定才重算。
- 每次自动判定或作者校正保存时记录所采用的冲突阈值。读取时比较该记录与当前项目阈值即可识别变化，不需要扫描正文或重写其他卡片；旧卡没有该记录时按当时默认阈值三解释，只有保存新判定时才补记。
- 点击「恢复自动判定」时固定当前完整卡片快照，使用最新计划值、实际值和阈值立即计算并一次保存；不另等两秒，不清空实际值。保存成功后才把有效来源切回自动判定，失败或冲突时人工结论与输入保留。
- 若当前实际值全部为空，恢复自动后回到规划中、无偏差、无系统说明；若仅部分实际值存在，按现有偏差规则判定为已写或偏差。

### 4. AI 写后同步不得静默覆盖

- AI 继续先读取卡片、整理提案，再由作者批准后写入，不获得绕过人工判定的特殊通道。
- 对作者校正卡，AI 写后同步只提交一组实际比较值，不在同一次普通同步中混改计划比较值；确需修改计划时另列独立提案。这样每次回写的判定去向都是确定的。
- 对自动判定卡，AI 实际值提案按现有确认流程保存并重算。
- 对作者校正卡，AI 实际值提案的确认界面固定展示“当前作者结论 → 按提案计算的自动结论”，即使两者相同也不能隐藏来源将改变的事实；作者确认这一次提案即表示接受按新值重算并回到自动模式。
- 对作者校正卡，若 AI 只修改非比较字段，人工判定保留；确认文案不能误称其会重算。
- 已有人工校正标记和说明必须进入 AI 读取、写后同步上下文，提示模型尊重作者结论，但权限保护不能只依赖提示词，写入服务也必须执行上述来源规则。
- AI 普通更新工具不接受作者校正参数，只能按上述确定规则写计划、实际值或非比较字段。人工校正仅由作者详情中的明确操作触发；确需支持“按用户明确要求代为校正”时，另行设计专用工具与确认界面，不在本计划附带扩展。

## 六、节奏看板拖动

本计划取消“一律禁止跨列”的交互限制，但不把拖动伪装成自动计算：

| 拖动场景 | 固定行为 |
| :-- | :-- |
| 同列排序 | 保持现有即时排序，不修改实际值或判定来源 |
| 自动判定卡跨列 | 松手后打开该卡片详情的作者校正操作态，目标状态已选中；原看板位置暂不改变 |
| 作者校正卡跨列 | 同样进入作者校正操作态，显示当前人工结论与目标状态，作者可一并修订偏差说明 |
| 点击「应用校正」 | 一次性保存状态、偏差结论、说明、目标落点和其他待保存修改；成功后看板移动 |
| 取消、关闭或切换卡片 | 不修改原状态或看板位置；未应用输入随编辑会话保留，不自动执行 |
| 拖动到“规划中” | 只校正分类，不清空已有实际值；详情提示这些实际值仍然保留 |
| 拖动到“已写／偏差”且没有实际比较值 | 「应用校正」禁用，并提示先补冲突、情绪、钩子、爽点中的至少一项；本章自评不计入 |

拖动不再静默无效，也不显示一个最终不能落下的目标占位。拖动开始时允许显示合法落点，松手后以“待作者确认”的原因操作态完成；没有应用前真实看板保持原位。暂存的目标落点属于快照之外的待处理人工状态：外部修改先建立版本关系，刷新恢复后仍以待确认落点呈现，不能自动应用或静默丢弃。

普通字段的保存时序由已完工的卡片保存会话统一负责；跨列校正始终以「应用校正」为明确出口，不能仅因两秒计时自动完成。

## 七、保存、冲突与错误反馈

1. 所有新增字段进入本领域的同一份卡片草稿，记录字段是否修改，并与原文本字段共享读取版本。
2. 保存时只提交实际变更字段，但携带同一版本校验；更新服务对整次提交原子落盘，不能高级字段成功而正文失败后只清掉部分输入。
3. 保存期间继续输入时，旧请求只清理它实际提交的修订，新输入必须保留到下一轮。
4. 切卡、切项目或关闭详情不能让旧请求改写新现场；不同项目中相同卡片标识也必须隔离。
5. 外部或 AI 修改与人工未落盘内容同时出现时，沿用当前卡片冲突入口。新增字段必须进入字段比较、副本和采用操作，不能只比较旧字段。
6. 高级信息中的非法输入只阻止当前卡片写入，并显示具体字段错误；不清空、不跳走、不将合法字段先写一半。
7. 普通成功反馈沿用详情现有状态，不额外制造全局提示；失败持续可见，并可重试。
8. 人工判定、自动判定和待保存草稿必须区分。作者校正未应用前不能提前显示“作者校正”，保存失败时原判定来源不变。
9. 「应用校正」「恢复自动判定」「修订历史放弃原因」和跨列暂存落点按明确操作保存：点击时固定完整快照，成功才改变有效结果；这些待确认状态进入恢复镜像和外部修改冻结范围，不能被自动执行。
10. 卡片副本携带当时人工视角的完整内容：伏笔副本包含高级字段、计划窗口和两节正文；节奏副本包含关联章节、计划值、实际值、三节正文、判定来源和人工说明。副本遇到领域唯一性冲突（如一章一卡）时明确失败并保留表单，不静默删减字段。

## 八、文件格式、旧数据与兼容

### 1. 保留现有内容

- 伏笔继续使用现有 Markdown 字段和两节正文，不把关联章节迁移到另一目录，也不为选择器建立浏览器专属事实源。
- 计划回收位置在卡片中保存为可机器读取的结构化数据，至少区分已有章节、固定未来章号、相对位置和未设置。相对位置保留基准章号、偏移量和保存时确定的目标章号，不能只保存一段自然语言。
- 新增一组带格式版本的计划窗口数据，包含起点、终点及其位置类型。相对位置同时保存基准章号、偏移量和确定目标章号；固定未来章号保存目标章号；已有章节保存其全本章号。
- 原有回收窗口字段继续保存可读起止标识：两端都是确定位置时写起止章号；有起点、无终点时终点写“开放终点”占位；两端都未设置时保持空值。“开放终点”只是旧版本可读占位，不当作章节引用。
- 新版存在计划窗口数据时以它为有效值，所有经过新版服务的窗口更新同步重写可读旧字段。旧版本没有新增数据时仍读取原窗口。
- 外部修改导致两套数据不一致时，界面并列展示“结构化窗口”和“兼容窗口”，提供三个固定出口：采用结构化窗口时按结构化值重写旧字段；采用兼容窗口时把它解释为固定章号位置或开放终点并重写结构化值，原相对位置记录不保留，确认前明确说明这一后果；返回则保留两套数据和当前输入。兼容窗口无法解析时不能采用，只能重新选择计划位置。系统不自动挑选一套，也不做起点终点级合并。
- 现有仅由章节标识组成的埋设章节、回收窗口、关联章节和实际回收章节继续可读取。首次打开不批量改写；作者保存相关字段时，将能够确认的旧值转换为新表达并保留原章节含义。
- 已有章节标识优先按现有章号规则匹配唯一真实章节。若匹配不到、匹配到多个候选或无法解析，保留原值并标记“待确认／不存在”，不得自动改绑；作者主动确认或替换后才更新。
- 旧的非标准自由章节文本只在高级「兼容原文」中保留和查看，不作为正常章节匹配依据；作者必须明确改为章节、未来位置或清除后才能完成该字段的新版编辑。整个项目不做批量清理或自动迁移。
- 节奏卡没有计划回收窗口，不借用伏笔的新位置结构；其关联章节仍是一章一卡的真实章节引用。
- 节奏卡继续使用现有计划值、实际值、状态、偏差结果和三节正文；新增编辑入口不自动为旧卡片补写空白内容。
- 既有伏笔实际回收章节即使与普通状态不一致，也原样读取、展示，不做启动时清理或批量校正；继续使用原有字段保存真实章节或历史原引用，不新增一套实际位置数据。
- 旧节奏卡没有判定来源元数据时按“自动判定”解释，保留现有状态、偏差标记和说明，不在首次读取时重算或重写。
- 一旦作者主动修改并保存旧节奏卡，按第五节规则处理：修改比较值时重算，修改非比较值时保持旧判定结果。
- 新增判定来源和作者说明只保存在各自卡片文件中，旧版本应用无法识别时最多忽略新增说明，不影响原有计划与实际值读取；不引入浏览器专属事实源。

### 2. 人工校正元数据

- 记录判定来源、人工偏差说明和最近一次判定采用的冲突阈值，不另存一份会与有效状态冲突的“人工状态”。
- 自动模式仍沿用现有系统偏差说明字段；人工模式把作者说明保存在独立的可选字段中，界面以作者说明为当前有效说明。
- 恢复自动判定时保留作者历史说明，但不再作为当前有效说明；界面在默认折叠的“历史人工说明”中查看，不静默删除创作记录。
- 本计划不增加校正时间、操作者账户或历史版本链；当前更新时间继续由系统维护。

## 九、新旧机制替代表

| 现有机制 | 新去向 |
| :-- | :-- |
| 伏笔结构字段只读，提示找 AI 或改文件 | 替换为默认折叠的高级信息编辑区 |
| 章节引用依靠手输或回忆文件名 | 替换为可搜索章节选择器；已有事实字段可从选择器真实新建章节，引用按全本章号位置解释 |
| 回收窗口只能写成当前或未来章号文本 | 替换为已有章节、固定未来章号、选择时固定的相对位置及开放终点 |
| 伏笔关联章节只能追加 | 保留 AI 追加入口，新增作者完整替换与整理能力 |
| 离开揭晓／解决自动清空实际回收章节 | 删除隐式清空；改为保留并提示状态不一致 |
| 已放弃原因只能只读展示 | 增加历史说明修订，已放弃时仍不能为空 |
| 节奏关联章节只读 | 替换为真实章节的搜索选择与新建入口 |
| 节奏上下文衔接、作者备注无详情入口 | 纳入默认折叠的更多正文 |
| 节奏实际值只在有回写后只读展示 | 替换为始终可见、可增改清的写后实际值区 |
| 节奏副本缺少实际值与人工判定信息 | 替换为携带完整人工视角的副本，同章占用时明确失败 |
| 节奏状态与偏差禁止人工设置 | 替换为默认自动、明确作者校正、可恢复自动 |
| 作者校正被后续回写静默覆盖 | 替换为比较值变更重算和确认界面明确展示结论变化 |
| 节奏跨列拖动静默无效 | 替换为进入作者校正并暂存目标落点 |
| 节奏计划值改变不重算既有判定 | 自动模式下改为按最新比较值重算 |

## 十四、方案形成记录

### 2026-11-19：作者控制权方案讨论

- 用户明确创作计划卡当前边界合理，不纳入改造。
- 伏笔名称、读者视角和作者真相之外的结构信息也应允许作者直接微调；高级信息可以默认折叠，但不能成为 AI 专属能力。
- 节奏卡除跨列拖动曾可勉强接受外，其他创作信息也应由作者直接控制；仅允许 AI 写后回写不符合作者辅助工具的定位。
- 方案采用“默认自动判定、作者明确校正、可以恢复自动”的节奏状态模型，避免开放人工编辑后又被下一次同步静默覆盖。
- 伏笔关联章节增加作者完整整理能力，AI 仍保留追加、去重路径；实际回收章节不再因状态变化被隐式清空。
- 新建表单继续保持轻量，本计划集中完善创建后的详情编辑，不把所有高级输入塞进登记流程。
- 本轮只编写计划，不修改应用代码；方案仍待用户确认。

### 2026-11-20：章节选择与未来位置方案

- 章节引用采用可搜索的章节选择器，展示章号和标题，支持键盘选择；已有事实字段可以从选择器真实新建空章节。

- 区分计划回收位置、回收窗口和实际回收章节。计划允许选择已有章节、最新章节之后第 N 章、指定未来章号或暂不指定；实际回收正常只选已有章节，不通过创建空章伪装事实。

- 旧章节标识在作者保存相关字段时按唯一匹配转换；多候选、不存在或不可解析值保留待确认，不批量迁移或自动改绑。
