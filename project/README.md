# 项目执行文档

这个目录用于快速了解项目的阶段性概况：当前大致做到哪里、整体处于什么阶段、后续有哪些方向，以及重要进展记录。

本目录**按阶段不定期整理，可能滞后于真实开发进度**。需要了解某项功能的实际施工状态时，以对应 plan 中的待办、施工记录和验收结果为准；计划导航见 [计划索引](../plans/README.md)。

## 文档清单

| 文档 | 作用 |
| :--- | :--- |
| [项目总览](项目总览.md) | 记录项目当前阶段、目标和整体状态 |
| [开发路线图](开发路线图.md) | 记录项目整体演进阶段和当前验证方向 |
| [当前进度](当前进度.md) | 概览当前主要能力、所处阶段和需要持续观察的风险 |
| [开发日志](开发日志.md) | 按时间记录关键进展、调整和说明 |
| [真机测试 OPFS 仿真目录方案](真机测试OPFS仿真目录方案.md) | 浏览器无法授予文件系统权限时的真机测试配方 |

已完成阶段使命的复盘、历史计划和诊断材料放在 `docs/archive/`。

## 维护原则

1. 阶段性功能完成后，可在下一次集中整理时更新 [当前进度](当前进度.md)，不要求逐次提交同步。
2. 项目整体阶段或验证方向变化后，更新 [开发路线图](开发路线图.md)；具体待办只写在对应 plan 中。
3. 重要实现变化、实际偏差和验收结果首先记录在对应 plan；需要保留阶段性时间线时，再补一条 [开发日志](开发日志.md)。
4. 如果代码现状与设计文档不一致，记录原因并在后续集中整理时修正文档；本目录允许阶段性滞后，但不应保留已经发现的明显错误或状态矛盾。

## 使用建议

- 只想知道项目现在做到哪了，先看 [当前进度](当前进度.md)。
- 想了解项目当前所处的验证方向，看 [开发路线图](开发路线图.md)。
- 想回溯为什么这样做，看 [开发日志](开发日志.md) 和 `docs/decisions/`。
- 想查看某个大功能或重构怎么落地，看 `docs/plans/README.md`。
