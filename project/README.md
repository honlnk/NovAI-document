# 项目执行文档

这个目录只维护 NovAI 的执行状态：当前做到哪里、下一步做什么、每个阶段的目标是什么，以及重要进展记录。

产品愿景、功能需求、技术架构和决策记录已经拆到上一级目录：

- 产品与需求：`docs/product/`
- 技术架构：`docs/architecture/`
- 决策记录：`docs/decisions/`

## 文档清单

| 文档 | 作用 |
| :--- | :--- |
| [项目总览](项目总览.md) | 记录项目当前阶段、目标和整体状态 |
| [开发路线图](开发路线图.md) | 记录阶段划分、里程碑和优先级 |
| [MVP 清单](MVP清单.md) | 记录第一阶段最小可用产品范围与执行顺序 |
| [当前进度](当前进度.md) | 记录已完成、进行中、待开始的事项和风险 |
| [开发日志](开发日志.md) | 按时间记录关键进展、调整和说明 |
| [正式 UI 开发计划](UI开发计划.md) | 记录正式 UI 的开发阶段、页面设计细节和验收标准 |
| [真实创作复盘](真实创作复盘对照.md) | 对照原计划与真实创作案例，区分计划缺失和实现粒度问题 |

## 维护原则

1. 每次完成一个阶段性功能后，更新 [当前进度](当前进度.md)。
2. 每次调整优先级或里程碑后，更新 [开发路线图](开发路线图.md)。
3. 每次发生重要实现变化或范围调整后，补一条 [开发日志](开发日志.md)。
4. 如果代码现状与设计文档不一致，以 [开发日志](开发日志.md) 说明原因，并在后续同步修正文档。

## 使用建议

- 只想知道项目现在做到哪了，先看 [当前进度](当前进度.md)。
- 想知道下一阶段做什么，看 [开发路线图](开发路线图.md) 和 [MVP 清单](MVP清单.md)。
- 想回溯为什么这样做，看 [开发日志](开发日志.md) 和 `docs/decisions/`。
