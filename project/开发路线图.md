# NovAI 开发路线图

本页从项目整体演进角度说明各阶段的方向，不维护具体施工待办。功能实施顺序、任务拆分和验收状态见[计划索引](../plans/README.md)。

## 基础项目与模型接入

目标是让作者能够创建小说项目、配置模型，并通过对话完成正文写入。

形成的能力包括本地目录访问、标准项目结构、模型配置、文件树与内容预览，以及最初的流式生成链路。

## 文件驱动的创作 Agent

目标是让 AI 围绕项目文件工作，而不是只在聊天窗口输出故事。

形成的能力包括文件导航与读写、精确修改、章节命名约束、写入确认、权限档位、停止运行，以及结构化的文件变更记录。

## 长篇上下文与故事记忆

目标是让持续创作不依赖无限增长的聊天上下文。

形成的机制包括模型视图、上下文压缩、文件分页、工具结果溢出、项目记忆、写作大纲、要素目录、按需加载，以及情节和时间线的语义检索。

## 多角色与协作体验

目标是让创作与要素维护各自拥有清晰职责，同时保持统一的用户控制面。

形成的机制包括角色注册、主智能体与要素管理员直聊、真实委派会话、按会话路由确认、变更账本、排队与插话，以及支持长会话的聊天渲染。

## 当前阶段：真实创作验证

核心工作循环已经建立，当前主要通过真实小说项目检验：

| 方向 | 关注问题 |
| :-- | :-- |
| 创作质量 | Agent 是否能稳定理解意图、保持文风并写出可用正文 |
| 故事记忆 | 稳定设定是否完整可见，剧情线索是否能被正确检索和维护 |
| 长任务稳定性 | 压缩、委派、队列和停止机制在复杂任务中是否可靠 |
| 用户控制 | 权限、确认、差异和会话过程是否足以支撑可信协作 |
| 模型兼容 | 不同供应商与代理网关在流式思考、工具调用等场景下是否一致 |

只有验证中发现的具体问题需要实施时，才形成相应计划；本页不提前堆积需求清单。

## 演进原则

后续功能仍应服从同一条主线：对话表达意图，Agent 使用工具，项目文件保存故事，界面提供确认与反馈。新增能力需要嵌入这一工作循环，而不是另建平行的聊天生成管线。
