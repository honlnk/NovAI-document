# NovAI 项目总览

## 项目定位

NovAI 是一个面向长篇小说创作的 AI 工作台。

它的核心目标不是做一个普通聊天工具，而是让 AI 围绕本地文件系统、章节文件、故事要素和 RAG 检索来协助作者持续创作长篇小说。

## 当前阶段

当前处于：

`MVP 早期实现 / Agent Loop 与 RAG 闭环验证阶段`

现状特点：

- 产品规划、需求说明、UI 设计、技术架构文档已经初步成型
- 已完成项目目录初始化、配置读写、模型测试连接与流式生成的第一版实现
- 已完成第一版模型驱动的文件工具 Agent Loop
- 已实现项目级日志与最近项目恢复
- 正式工作台 UI 已经具备首页、主工作区（Activity Bar + 分类面板 + 对话面板 + 可拖拽内容面板）、设置模态框
- 当前保留 `/test` 作为 AI、RAG 和文件工具能力的调试入口
- 需要继续把“工具调用 -> 写入确认 -> 要素提取 -> 检索复用”打通成更稳定的创作闭环
- 近期新增的创作结构优化计划包括章节切换为 `txt`、新增 `elements/entities/`、以及补齐更稳定的要素模板
- 当前最需要补强的是 Agent 控制能力：写入确认、diff 预览、工具约束遵守、system prompt 刷新，以及结构化文件变更事件（Agent 运行中停止已完成）

## MVP 目标

第一阶段重点验证以下闭环：

1. 创建并打开小说项目
2. 配置 LLM 与 Embedding
3. 通过自然语言指令驱动 Agent 读写项目文件
4. 将生成或修改结果写入本地章节文件
5. 从章节中提取要素并建立向量索引
6. 下一次生成时能够检索并利用已有要素

## 当前判断

当前项目最关键的不是补更多想法，而是尽快验证下面两件事：

1. “AI 直接操作小说文件”的交互链路是否顺畅
2. “长篇上下文靠文件 + RAG 管理”是否真的比聊天式记忆更稳定

如果这两点成立，NovAI 的产品方向就成立。

## 当前已落地能力

- 创建、打开与修复小说项目目录
- 初始化标准项目文件结构
- 读写 `novel.config.json`
- 测试 LLM / Embedding 配置
- 发起 LLM 流式生成
- 读取与保存 `prompts/system.md`
- 将生成结果写入 `chapters/`
- 在正式工作台中通过 Activity Bar + 分类面板浏览章节、要素、提示词，预览章节与项目文档
- 在测试页中调试项目文件、模型调用、要素提取和 RAG 检索
- 通过 `ReadFile / EditFile / CreateFile / RenameFile / DeleteFile / ListDirectory / FindFiles` 让模型主动查找、读取、创建、修改、重命名和删除项目文件
- 将工具结果回灌模型，支持多轮 Query Loop
- 将章节要素写入 `elements/`，并在要素更新后标记 RAG 索引过期
- 要素提取采用 LLM 唯一路径（不再有正则降级）
- 在设置模态框查看和手动重建 RAG 向量索引
- Agent 可主动调用 `RagSearch` 召回人物、地点、情节、时间线与世界观要素
- 将项目运行日志写入 `.novel/logs/agent.log.jsonl`
- 删除文件会先移入 `.novel/trash` 回收站，而不是永久删除
- 记住最后打开的项目，并在刷新后恢复
- 在内容面板编辑模式下直接修改章节、提示词、要素文件（Ctrl/Cmd+S 保存）
- 在内容面板选中文字后携带引用与 AI 对话（独立 `quote` 字段注入模型）
- 在运行中停止 Agent（LLM 流式请求中止 + Loop 停止信号检查，UI 发送按钮切换为停止）
- 内容面板宽度可拖拽调整（240~720px）并持久化到 localStorage
- 首页项目卡片展示章节数与要素数（「N 章 · M 个要素」）
- 在对话输入框输入 `@` 切换激活场景（筛选 + 键盘导航 + 场景 chip 双向联动）
- 在对话输入框输入 `/` 弹出斜杠命令菜单，`/提取要素` 支持章节多选、候选预览、确认写入流程

## 当前未完成重点

- 写工具执行前还没有权限确认和 diff 预览。
- 用户即时工具约束还不稳定，例如明确要求“不读文件”时仍可能触发读取工具。
- 同一会话内修改 `prompts/system.md` 后，旧 Agent 消息上下文不会自动刷新。
- RAG 召回仍是 IndexedDB 记录 + 手写 cosineSimilarity 的过渡实现，正式 Orama 召回待补齐。
- 要素提取缺少用户确认、去重合并和覆盖策略（已具备 LLM 结构化提取能力，但流程未闭环）。
- Agent 执行后的文件变更仍由 service 层推导，后续应改为工具层结构化输出。
- UI 重构 R4（`@场景` 输入框指令）、R6（`/提取要素` 斜杠指令）进行中。
