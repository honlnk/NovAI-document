# NovAI 项目总览

## 项目定位

NovAI 是一个面向长篇小说创作的 AI 工作台。

它的核心目标不是做一个普通聊天工具,而是让 AI 围绕本地文件系统、章节文件、故事要素和 RAG 检索来协助作者持续创作长篇小说。

## 当前阶段

当前处于:

`Agent Loop 与队列/插话闭环已通,创作质量与 RAG 验证阶段`

现状特点:

- 产品规划、需求说明、UI 设计、技术架构文档已经成型
- MVP 闭环(项目创建 → 配置 → 自然语言驱动 → 文件读写 → 要素提取 → RAG 检索)已打通
- 主工作台 UI(Activity Bar + 分类面板 + 对话面板 + 可拖拽内容面板 + 设置模态框)已稳定
- Agent Loop 已从 Claude Code 参考系切换至 DeepSeek Harness 参考系,具备压缩、spill、范围权限、turn/step 循环、队列与插话
- 文件改动账本 changeLedger 落地,聊天区支持 dsh 风折叠 + 轮次级 diff 面板
- 写工具权限五档、`.novel/` 防护、ReadFile 三道闸、spill 可读化等安全与可用性机制就位
- 章节命名规范 `第NNN章-标题.txt` 在工具层强制,旧项目可一键整理
- 对话输入框 AI 补全(FIM ghost text)、设置页优化(协议选择 + 自动保存)已上线
- 当前重点是验证真实长篇创作任务下的要素提取质量、RAG 召回质量、上下文压缩连贯性

## MVP 目标

第一阶段重点验证以下闭环(已达成):

1. 创建并打开小说项目 ✓
2. 配置 LLM 与 Embedding ✓
3. 通过自然语言指令驱动 Agent 读写项目文件 ✓
4. 将生成或修改结果写入本地章节文件 ✓
5. 从章节中提取要素并建立向量索引 ✓
6. 下一次生成时能够检索并利用已有要素 ✓(已接入 RagSearch 工具)

## 当前判断

MVP 闭环已成立,当前项目最关键的不是补更多想法,而是尽快验证下面两件事:

1. **真实长篇创作下的质量**——Agent 在 >8 个 step 的长任务中是否稳定(队列与插话已解除轮次硬上限),要素提取与 RAG 召回是否支撑连贯创作
2. **「长篇上下文靠文件 + RAG + 压缩管理」是否真的比聊天式记忆更稳定**——8 段检查点压缩与 CJK token 估算已就位,但摘要质量与压缩后创作连贯性需要真实项目验证

如果这两点成立,NovAI 的产品方向就成立。

## 当前已落地能力

### 项目与文件系统
- 创建、打开与修复小说项目目录,初始化标准项目文件结构
- 读写 `novel.config.json`,测试 LLM / Embedding / Rerank 配置
- 项目文件扫描、分组展示、原文预览
- 记住最后打开的项目,刷新后恢复;最近项目列表最多 8 个,首页卡片展示「N 章 · M 个要素」
- 删除文件先移入 `.novel/trash` 回收站,不永久删除
- 项目运行日志写入 `.novel/logs/agent.log.jsonl`

### Agent Loop(DeepSeek Harness 参考系)
- turn/step 分层循环,`agentMaxTurns` 默认 0 不限(退化为安全阀)
- 双队列收件箱:next-turn 排队 / next-step 插话,随会话落盘,刷新后不自动消费
- 8 段检查点上下文压缩(`conversationTokenLimit` 阈值 + 溢出双触发、保留 `compressionKeepRecentTurns` 轮、tool 配对回退、摘要自合并、CJK 感知 token 估算)
- spill 超长工具结果落盘 `.novel/spill/`(ReadFile 三道闸:2000 行 / 2000 单行字符 / 50KB 字节),spill 文件可读回,7 天启动清理
- 工作区范围权限 + 写工具权限五档(仅审阅全问 / 章节 / 素材 / 章节+素材 / 完全访问),`.novel/` 与配置文件任何档位直接拒
- 模型驱动工具:`ReadFile / EditFile / CreateFile / RenameFile / DeleteFile / ListDirectory / FindFiles / RagSearch / GetFileChangeHistory`
- 写工具执行前用户确认,展示 diff/路径预览卡片,拒绝则回灌模型
- LLM 流式请求可中止,Loop 每层检查停止信号,停止后保留已生成内容
- system prompt 同会话刷新:`system.md` 或场景提示词变化在下一轮自动反映
- 项目级累积记忆 `prompts/NovAI.md`,每轮注入 system prompt,变化时经 hash 触发刷新
- 流式打字机渲染(stable streamingMessageId + 光标)

### 文件改动追踪与展示
- changeLedger append-only 账本(事件驱动累积、随会话 JSON 落盘、压缩免疫)
- 写工具 output 携带片段级 diff(EditFile/CreateFile 实际应用文本)
- 聊天区 dsh 风:去头像、工具行按 toolCallId 合一单行、任务组默认折叠成计数摘要行、纯问答轮无折叠、steering 气泡非组边界
- 轮次级 diff 面板 TurnChangesPanel(最新轮展开,历史轮折叠,点击行展开 jsdiff 行级 diff),右下角「本会话共修改 N 个文件」
- GetFileChangeHistory 只读工具按需取回历史(新→旧清单 + path/runId/limit 过滤)

### 队列与插话 UI
- 输入框运行中解禁,Enter=排队 / Ctrl+Enter=插话(空草稿 + 插话键 = 全部排队逐条插话)
- QueueDock 挂输入框正上方,多条折叠计数头、展开行编辑 / 删除 / 立即插话
- 排队消息携带消息级 activeFilePath 快照,每条 followup 用自己入队时的文件
- 发送按钮运行中切换为独立停止键 + 插话按钮
- 权限档位选择器(输入框工具行左侧 popover,与设置页共享同一份配置)

### 章节与要素
- 章节正文统一 `chapters/*.txt`,命名强制 `第NNN章-标题.txt`(编号至少 3 位补零,标题非空),同编号重号拒绝
- 旧 `.md` 章节兼容读取/预览/计数/迁移;`OrganizeChaptersModal` 支持批量整理(机械转换 + 缺标题正文兜底)
- 要素类型:`characters / locations / entities / plots / timeline / worldbuilding`,`entities/` 收纳武功/武器/坐骑/丹药/信物等具体实体
- 要素提取采用 LLM 唯一路径(无正则降级),`/提取要素` 斜杠命令支持章节多选、候选预览、确认写入、同名智能合并
- 要素写入后标记 RAG 索引 stale

### RAG 与上下文
- Orama 内存向量检索(每 projectId 一个常驻实例,维度不匹配降级空召回)
- 两阶段检索:粗召回(Orama) + Rerank 精排 + 最终上下文筛选
- 索引状态栏常驻主工作区底部,contentHash 增量重建,支持一键手动重建
- `RagSearch` 工具接入 Agent Loop,模型可主动召回要素上下文

### 输入与交互
- 对话输入框 AI 补全(DeepSeek FIM 流式 ghost text,防抖 + AbortController + Intl.Segmenter 中文分词逐段接受,独立可开关配置)
- `@场景` 指令切换激活场景(筛选 + 键盘导航 + 场景 chip 双向联动)
- `/` 斜杠命令菜单(命令注册表驱动,可扩展)
- 选中内容引用:预览模式选中文本生成 quote chip,独立字段透传给模型
- 内容面板预览 / 编辑 / 原始三态,编辑模式 Ctrl/Cmd+S 手动保存 + dirty 标记
- 内容面板宽度 240~720px 拖拽调整,持久化到 localStorage
- 设置模态框(三段式 + 左侧竖排导航 + 自动保存 600ms 防抖 + 四面板统一测试连接 + LLM 协议选择)

## 当前未完成重点

- **要素提取缺少用户确认、去重合并与覆盖策略**——LLM 提取能力已可用,但提取→确认→合并→覆盖的完整流程未闭环
- **要素模板与拆分规则未稳定**——`characters / plots / timeline / entities / locations` 五类要素的默认模板、剧情块按事件拆分、时间线按阶段拆分仍待补齐(见 [Element 要素体系优化计划](../plans/Element要素体系优化计划.md))
- **近期章节上下文 `recentChapters` 未接通**——类型已定义但当前恒为空数组,需决定接进 Loop 还是改为工具化读取策略
- **RAG 自动增量重建与错误降级未补**——状态栏 + contentHash 手动重建已落地,但后台自动重建与索引错误降级策略仍缺
- **生成结果结构化处理未落地**——章节写完后的计数刷新、自动打开变更文件、章节级元数据(字数 / 第几章 / 新建 vs 续写)
- **anthropic / gemini 生成链路适配**——设置页已支持协议配置,实际生成适配待另立计划
- **Git 自动提交策略未设计**——Phase 5 基座,章节整理/校对/版本管理配套依赖
- **「dsh 借鉴与映射设计」文档待补**——对位 0002,系统梳理 DeepSeek Harness 借鉴清单

## 阻塞与风险

- 纯前端文件系统方案依赖浏览器能力,兼容性有限
- 上下文压缩摘要质量仅用 mock 模型验证过结构,真实模型的摘要质量与压缩后创作连贯性需真实项目验证;`conversationTokenLimit` 设置低于保留区时会每轮触发压缩(预期尽力而为行为),默认 12000 不受影响
- `RagSearch` 主动调用率、两阶段检索中 Rerank 精排效果、FIM 补全 delta 字段兼容性(代理网关改写场景)与延迟体验,均需真实使用验证
- 要素提取已收敛 LLM 唯一路径,但用户确认 / 去重合并 / 覆盖策略缺位,流程未闭环
