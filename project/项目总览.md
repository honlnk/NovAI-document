# NovAI 项目总览

## 项目定位

NovAI 是面向长篇小说创作的智能体工作台。用户用自然语言表达创作意图，AI 通过受控工具读写本地项目文件，持续维护章节、要素、提示词和大纲。

聊天是协作界面，不是故事内容的主要存储位置。项目文件既服务创作智能体，也允许作者直接查看、编辑和迁移。

## 当前形态

项目已形成以下完整工作循环：

1. 用户创建或恢复小说项目，配置所需模型。
2. 在对话中提出创作、修改、整理或查资料的要求。
3. Agent 按需读取文件、加载要素、检索剧情或查询外部资料。
4. 需要写入时，权限系统决定是否请求确认，工具将结果写回项目。
5. 对话展示执行过程和文件差异，故事资产与会话分别持久化。

当前重点是验证这套机制在真实长篇创作中的质量与稳定性，而不是继续堆叠未形成工作闭环的功能入口。

## 核心结构

| 组成 | 作用 |
| :-- | :-- |
| 本地项目 | 保存章节、要素、提示词、大纲和配置，是创作资产的事实来源 |
| 主智能体 | 理解创作意图，使用完整工具集完成读写、检索和协作 |
| 要素管理员 | 以受限工具维护要素，可通过直聊或独立委派会话工作 |
| 上下文系统 | 组织项目记忆、大纲、稳定要素目录、检索结果和会话历史 |
| 服务与界面 | 将核心能力转换为项目、会话、确认、队列和变更等界面协作契约 |

## 故事记忆策略

不同信息采用不同获取方式：

- 人物、地点、实体和世界观先披露稳定目录，再按需加载完整定义。
- 情节和时间线使用向量检索与可选重排，处理模糊的剧情查询。
- 章节正文通过文件工具按需读取，不自动选取近期章节注入。
- 会话历史通过压缩与工具结果溢出机制控制体积。

这套分工让稳定设定尽量确定可见，让快速增长的剧情信息保持可检索，同时避免把整部小说长期放入提示词。

## 当前工程形态

代码采用 pnpm monorepo：核心包负责 Agent、工具、模型、文件和检索，应用包负责 Vue 界面与 Pinia 状态。界面通过服务层使用核心能力，不直接操作核心内部对象。

应用当前是纯浏览器 SPA，依赖本地目录访问能力，没有桌面壳和 Git 版本管理。模型协议、检索、联网、输入补全和角色权限均以项目配置为中心组织。
