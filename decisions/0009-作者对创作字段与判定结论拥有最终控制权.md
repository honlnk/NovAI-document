# 0009 - 作者对创作字段与判定结论拥有最终控制权

## 状态

- 日期：2026-11-22
- 状态：已落地（伏笔与节奏卡作者字段控制权升级计划阶段 1–6 完工；门禁与真机验证结论见[施工计划文末施工日志](../plans/伏笔与节奏卡作者字段控制权升级计划.md)）
- 关联计划：`docs/plans/伏笔与节奏卡作者字段控制权升级计划.md`

## 背景

伏笔与节奏卡此前存在一类系统性问题：**结构化字段的写权默认在自动链路（AI 工具、自动判定、阈值重算）手里**。具体表现：

- 节奏卡的偏差结论由系统按比较值与阈值自动判定，作者不同意时没有明确的「我说了算」出口；
- AI 工具更新卡片时可能顺手改写判定相关字段，作者结论与系统结论混在同一份字段里无法区分；
- 伏笔的高级字段（回收窗口、关联信息、实际回收章节）虽可编辑，但缺少「AI 改动必须先过作者」的关卡；
- 阈值或规则变化时，存在后台批量重算改写旧卡的风险。

## 决策

**作者对创作字段与判定结论拥有最终控制权。** 自动链路（AI 工具、自动判定、阈值重算）可以计算、可以提案，但结论的采纳与解除只能是作者的明确操作。落地为以下长期遵循的原则：

1. **判定来源分立**：判定字段（status / deviation_flag / judgment_source）带来源标记（auto / author）。作者校正与恢复自动是仅限作者在卡片详情中操作的显式动作，AI 工具层拒收这两类参数（`RhythmUpdate` 遇 `authorJudgment` / `restoreAutoJudgment` 直接报错）。
2. **AI 改判定必须披露并经确认**：AI 提交实际比较值会按新值重算并回到自动判定——这是允许的，但提案必须向作者明示「当前作者结论 → 按提案重算的自动结论」，由作者确认后才执行；`RhythmSync` 的 guidance 同时要求模型尊重既有作者结论、不顺手推翻。
3. **作者说明与系统说明分立**：`author_deviation_note` 与系统 `deviation_note` 是两个独立字段，作者校正永不触碰系统说明，恢复自动时作者说明保留为历史。
4. **看板位置只由作者改变**：同列拖动即时重排；跨列拖动不直接移动，进入作者校正操作态，应用校正时判定与落点一次保存原子生效。
5. **零批量改写**：旧项目打开不补写、不重算任何卡片；阈值变化只提示待复核，不后台改写；人工结论在一切自动重算中保留。
6. **伏笔真相的可见性边界**：`ReadForeshadowing` 永不含作者真相（装配层权限，模型无法越权），规划路径 `ReadForeshadowingForPlanning` 才含真相；作者界面直接可见真相。
7. **正文两节分离**：伏笔正文的读者视角与作者真相是两节，写正文链路只拿读者视角；AI 更新真相需 contentHash 防覆盖，只改状态/元数据时真相节原样保留。

## 后果

- 作者与系统的结论可以共存、可追溯（来源标记 + 双说明字段），「谁判的」永远可回答。
- AI 的账本维护能力不受损：登记、回写实际值、推进状态、追加暗示历史都保留，只是判定结论的变更被收进披露-确认关卡。
- 工具层与领域层各守一段：工具层拒收越权参数，领域层保证判定语义（互斥、校验表、落点原子性），UI 层保证操作必须是显式点击。
- 代价：AI 同步链路多一步作者确认；普通文件工具仍可直写卡片文件（与专用工具同一份文件）——这是保留的逃生通道，依赖模型遵循 guidance 而非硬封锁，属于已知取舍。
